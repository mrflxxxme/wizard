# Записи настоящих ответов моделей (V4-03, D79 (10))

- `probe/<этап>.jsonl` — ответы живой пробы этапа (`node tools/fixtures/probe.mjs --stage=<этап>`, воркфлоу `stage-probe`).
- `e2e-v3/<этап>.jsonl` — записанный прогон e2e v3 по этапам (стенд `packages/e2e/stand`, V4-19), его проигрывает CI.
  PR с правками разных этапов не конфликтуют в git.
- `prompts.json` — исходники промпта каждого callType. Версия промпта — хеш этих файлов плюс хеш схем инструментов;
  ключ записи — `<callType>@<версия>/<модель>`. Правка промпта — новая версия: старые записи больше не отвечают.

Вызов без записи в CI падает с ошибкой «нет записи для <callType>@<версия>» — этап не уходит молча в запасной путь.
Отказ модели при записи тоже записывается и проигрывается тем же отказом. Вызов сверх записанного прогона (живой этап
остановился по своему бюджету времени, а проигрывание его не тратит) отвечает «модели недоступны» и помечается
«запись прогона закончилась» — это не промах. Тест `tools/fixtures/test/e2e-v3-records.test.ts` уже на PR сверяет записи e2e каждого этапа с текущими исходниками
промптов и маршрутами моделей: устарел этап, если промпт изменился или записавшей модели больше нет в маршруте.
Как перезаписать: запушить ветку `claude/**` или `task/**` с правкой промпта (проба этапа и, если промпт входит в e2e,
запись e2e v3 запускаются сами и коммитят записи в ветку)
— запись e2e v3 идёт в режиме `record-stale`: вживую только устаревшие этапы и все этапы после них по конвейеру
(brief → направления и арт-директор → фото → страницы → критик → техревью), остальные проигрываются; полный прогон —
флаг `e2e_full` или запустить `stage-probe` вручную (этапы, входы, модель). После коммита записей подтяните ветку и запушьте
следующий коммит — пуш токеном воркфлоу CI не запускает.

Секреты и сильные идентификаторы (почта, телефон, карта, СНИЛС, паспорт) вычищаются при записи; вложения хранятся
только хешем.
