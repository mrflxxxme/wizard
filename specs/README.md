# Wizard: машиночитаемые спецификации

Это источник истины для ИИ-агентов, которые строят Wizard. Документы в `docs/` объясняют, *почему* принято решение. Файлы в `specs/` фиксируют, *что именно* строить и как проверить результат.

## Порядок чтения для агента-исполнителя

1. `../AGENTS.md` — правила работы в репозитории. Обязательно.
2. `product.yaml` — цели, границы, принятые решения. Эти решения нельзя пересматривать без эскалации.
3. `architecture.yaml` — компоненты, стек с зафиксированными версиями, интерфейсы между пакетами.
4. `milestones.yaml` — вехи M0–M4 и критерии их готовности.
5. `backlog.yaml` — граф задач: id, зависимости, критерии приёмки, группа параллельности.
6. Спецификация своей задачи (в поле `specs:`):
   - `appspec/` — ядро: схема AppSpec, операции, diff и миграции;
   - `runtime/` — runtime созданных систем и SDK для сгенерированного кода;
   - `platform/` — API платформы, её БД, воркфлоу DBOS;
   - `agents/` — оркестратор, строитель, QA: инструменты, промпты, бюджеты;
   - `quality/` — гейты G0–G2 и eval-стенд;
   - `security/` — граница данных (ПДн), изоляция кода, антифрод, пакет 152-ФЗ;
   - `connectors/` — ЮKassa, Telegram, email, QR;
   - `ui/` — библиотека компонентов ядра, дизайн-токены, экраны платформы.
7. `escalation.yaml` — что требует решения основателя. Всё остальное агент решает сам.

## Правила спецификаций

- Нормативный язык: MUST, MUST NOT, SHOULD. Всё, что не помечено MUST, агент может сделать лучше, если не нарушает MUST.
- У каждой задачи в `backlog.yaml` есть проверяемые критерии `acceptance`. Задача не закрыта, пока они не проходят в CI.
- Противоречие между файлами — это баг спеки. Приоритет такой: `product.yaml` > `architecture.yaml` > частная спека. Агент фиксирует противоречие в `specs/CHANGELOG.md` и следует файлу с более высоким приоритетом.
- `node tools/specs/validate.mjs` проверяет структуру спек: ссылки, граф задач, схемы. Запуск обязателен перед каждым PR.
