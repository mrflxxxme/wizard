# Замер v3 на сервере пилота: проба маршрутов и чекпоинт 1

Задача V3-18 (`specs/backlog.yaml`), решение D77_v3 (8)–(11), (16), (18б), план `docs/plans/2026-10-08-v3.md` §4–5.
Чекпоинт 1 волны A — 4 брифа классов 1–3 на сервере пилота через настоящий путь v3, как его проходит владелец.
По каждому брифу замеряется сборка, сценарии, техревью, время и ₽, делаются снимки 390 и 1280 px.

Порядок — по лестнице бережливого харнесса (`specs/agents/builder-v3.md` §4). Следующая ступень запускается, только когда предыдущая зелёная:

| Ступень | Что | Цена |
|---|---|---|
| 0 | CI: драйвер v3 сквозной на локальной платформе на записанных ответах, проба на подменённых ответах | 0 ₽ |
| 2 | `v3-probe`: по одному минимальному живому вызову на голову каждого маршрута v3 | ≤ 30 ₽ |
| 4 | `eval-pilot`, порог `v3`: 4 брифа чекпоинта 1 | ≈ 1 100 ₽, потолок 1 300 ₽ |

Каждый платный прогон начинается только с записью в журнале трат (`docs/progress/v3-spend.json`, V3-01): цель, гипотеза, ожидаемые ₽, потолок, волна.
На потолке прогон останавливается. Больше 1 000 ₽ за раз или выход за план волны — только с «да» основателя (`founder_ok=yes`).

## Ступень 0 — бесплатно, в CI

Эти проверки идут в каждом PR (`pnpm test`):

- `tools/eval/test/v3-driver.test.ts` — драйвер проходит бриф `v3-02` на локальной платформе с настройками пилота. Клиенты на modules, организации замеров на v3. Путь: грилл-интервью (вариант по основе из брифа, «Решите за меня», свой текст) → направления и «Решите за меня» → «Собрать» → сборка харнессом v3 по снимкам хода → G0–G2 → первая публикация до ревью основателя → collect с v3-строками → отчёт чекпоинта. Ответы моделей записаны. Сеть и деньги не нужны, нужен psql.
- `tools/eval/test/v3-pieces.test.mjs` — ответы интервью, покрытие ожиданий, ход сборки, готовность и цифры отчёта. Ещё два случая: организация не на v3 (замер останавливается сразу) и отказ ТЗ или направлений (сборка всё равно идёт).
- `tools/eval/test/v3-probe.test.ts` — головы маршрутов и цены совпадают с реестром `@wizard/llm`, проба проходит через настоящий роутер на подменённых ответах, на потолке останавливается.
- `tools/deploy/test/pilot.test.mjs` (V3-18) — `pilot.mjs eval --threshold v3` и `pilot.mjs v3-probe`. Скрипт пробы запускается так же, как в поде: `node --import tsx --input-type=module -` в папке воркера.
- `apps/platform-api/test/v3-org-pipeline.test.ts` — переключатель v3 по организациям.

Посмотреть отчёт сухого прогона: `WIZARD_V3_DRY_OUT=/tmp/v3dry pnpm exec vitest run tools/eval/test/v3-driver.test.ts`. Отчёт появится в `/tmp/v3dry/v3-a-checkpoint1-<дата>.md`.

## Подготовка сервера: v3 только для организаций замера

Клиенты пилота остаются на `WIZARD_BUILD_PIPELINE` (modules), пока чекпоинт не принят. На v3 начинают новые системы организаций из `WIZARD_BUILD_PIPELINE_ORGS` (`specs/platform/deploy.yaml`).

1. Выкатите релиз: **deploy-pilot** (`sha` — текущий main, `confirm` — PROD), в поле `pipeline_orgs` укажите:
   - `eval` — организации замеров и проб;
   - `eval,staff` — то же плюс организации основателя (для V3-19);
   - вместо вида можно указать uuid конкретной организации.

   Пустое поле берёт переменную репозитория `WIZARD_BUILD_PIPELINE_ORGS` (Settings → Secrets and variables → Actions → Variables). Опечатку выкат отклоняет. Значение действует до следующего выката: выкат без поля и без переменной возвращает всех на `WIZARD_BUILD_PIPELINE`.
2. `eval-pilot` с порогом `v3` проверяет переменную сам, до траты. Если в окружении воркера нет `eval`, замер останавливается с ошибкой «организации замера не на v3» и ничего не тратит.

Система остаётся на конвейере, с которого начала. Если убрать вид из переменной, уже начатые системы не переедут.

Режим показа (B2-02) проигрывает записанные сценарии конвейера модулей. Если основатель им пользуется, вместо вида `staff` укажите uuid его рабочей организации.

## Ступень 2 — проба маршрутов v3 (≤ 30 ₽)

Workflow **v3-probe** (Actions → v3-probe → Run workflow):

| Поле | Значение |
|---|---|
| `sha` | пусто (последний main) |
| `wave` | `A` |
| `purpose` | `Головы маршрутов v3 отвечают на сервере пилота` |
| `hypothesis` | `8 из 8 типов вызовов отвечают головой маршрута или резервом; ≈ 3 ₽` |
| `expect_rub` | `5` |
| `cap_rub` | `30` (больше 30 форма не примет) |
| `confirm` | `PROD` |

Что делает проба (`tools/deploy/pilot.mjs v3-probe`, `tools/eval/server/probe.mjs`):

1. Создаёт служебную организацию «Замер V3 · <runid>» вида eval. Её сессия сразу отзывается.
2. В поде воркера через stdin запускает скрипт `kubectl exec -i deploy/wizard-worker -- node --import tsx --input-type=module -`. Файлы релиза для этого не нужны.
3. Скрипт создаёт роутер `@wizard/llm` с ключами, реестром и политикой сервера. Вызовы идут в режиме live, расход пишется в `platform.llm_calls` этой организации и входит в бюджет v3.
4. На каждый тип вызова уходит по одному вызову: «Ответь одним словом». У `critic_visual` к вызову приложена картинка 8×8. `research` вызывается, только если на сервере `WIZARD_RESEARCH_MODE=live`.
5. Когда расход дошёл до потолка, следующие вызовы не начинаются.

По каждому вызову отчёт показывает:

- статус;
- голову маршрута по реестру и модель, которая на самом деле ответила;
- уровень (T0/T1) и причину маршрута;
- маскирование ПДн (scrub);
- задержку и ₽;
- попытки цепочки.

Точный расход читается из базы.

Ожидаемый расход по ценам голов (300 токенов на вход и 150 на выход; у моделей Z.ai — 1 000 на выход с размышлением):

| Тип вызова | Голова | ≈ ₽ |
|---|---|---|
| interview_v3, art_direction, page_compose, signature_section | glm-5.3 (T1) | 0,56 каждый |
| brief_extract | gigachat-3.5 (T0) | 0,07 |
| critic_visual (с картинкой → T0) | kimi-k2.6 | 0,16 |
| techreview | deepseek-v4-pro (T0) | 0,16 |
| research | gpt-oss-120b (T0) | 0,01 |
| **Всего** | | **≈ 2,6 ₽** (потолок 30) |

Если на сервере `WIZARD_BUILD_DEFAULT_TIER=T0`, вызовы сборки уйдут на головы T0. Отчёт это покажет в разделе «Ответила не голова маршрута».

## Ступень 4 — чекпоинт 1 (4 брифа)

Workflow **eval-pilot** (Actions → eval-pilot → Run workflow):

| Поле | Значение |
|---|---|
| `sha` | пусто |
| `briefs` | `all` (4 брифа `v3-*`) или id через запятую |
| `threshold` | `v3` |
| `wave` | `checkpoint` |
| `purpose` | `Чекпоинт 1 волны A: 4 брифа классов 1–3 через путь v3 на сервере` |
| `hypothesis` | `Все 4 системы собираются с превью ≤ 5 мин, сборкой ≤ 30 мин и ≤ 500 ₽, обязательные сценарии проходят, техревью без блокеров` |
| `expect_rub` | `1100` |
| `cap_rub` | `1300` |
| `founder_ok` | `yes` (потолок больше 1 000 ₽ за раз) |
| `confirm` | `PROD` |

Откуда цифры. Цель сборки D77 (11) — ≤ 300 ₽, потолок харнесса — 500 ₽ на сборку. К этому добавляются интервью (≈ 10–20 ₽) и направления (≤ 40 ₽). Итого на бриф ≈ 270–360 ₽, на четыре ≈ 1 100–1 400 ₽.

Приёмка V3-18 — расход ≤ 2 000 ₽ вместе с V3-19 (план «Чекпоинты основателя» — 2 000 ₽). Потолок 1 300 ₽ оставляет ≥ 700 ₽ основателю на 2–3 системы.

Есть вариант без «да» основателя: `cap_rub` = `1000`. Тогда при расходе ≈ 300 ₽ на бриф четвёртый бриф остановит потолок. Его можно догнать отдельным прогоном: `briefs` = `v3-04`, волна `checkpoint`.

Что делает замер (`tools/eval/server/v3.mjs`, параллельно 2 брифа):

1. Проверяет, что организации замера на v3 (см. выше), и создаёт учётку «Замер V3 · <runid>» с ревью основателя.
2. По каждому брифу `POST /systems` создаёт систему и проводит грилл-интервью. Ответы берутся из `answers` брифа:
   - `тема: основа варианта` — первый вариант, где есть эта основа;
   - `delegate` — «Решите за меня»;
   - `{text}` — свой ответ;
   - иначе — рекомендованный вариант.
   После `rest_after` ответов отправляется «Дальше решай сам». Если у брифа есть `tz`, после первого хода прикладывается файл ТЗ.
3. Направления: три первых экрана, выбор `direction` брифа (1–3 или `delegate`). Если направления не получились, сборка всё равно идёт.
4. «Собрать» по последней версии брифа. Сборка отслеживается по снимкам `progress` событий `build_stage`/`step_*`:
   - этапы и их время;
   - живое превью;
   - сценарии;
   - ₽ из потолка.
   Ход по брифам выводится в issue «Замер D67: ход на сервере».
5. G0–G2, затем первая публикация. Она останавливается на ревью основателя, в prod ничего не уходит.
6. Снимки превью на 390 и 1280 px.
7. Из базы читаются:
   - точный ₽ по системам;
   - вызовы моделей по типам и моделям;
   - чекпоинты критика, гейта шаблонности и техревью;
   - сходство с сайтами ниши;
   - события этапов;
   - «Запросы на развитие»;
   - вызовы T1 с запрещёнными для ПДн типами.

Бриф «готов», если сборка завершилась, G0–G2 без блокеров, техревью без блокеров и прошли все обязательные сценарии брифа. Цели D77 (10)–(11) отчёт сверяет отдельно:

- превью ≤ 5 мин;
- медиана ≤ 20 мин, максимум ≤ 30 мин;
- средний расход ≤ 300 ₽, максимум ≤ 500 ₽.

Время замера — около 40–70 минут.

## Отчёт и журнал трат

Артефакт задания `v3-eval-prod-<run>` (у пробы — `v3-probe-eval-prod-<run>`) содержит:

- `v3-a-checkpoint1-<дата>.md` и `.json` — отчёт чекпоинта на русском и данные по брифам. Скопируйте оба в `docs/progress/` (дата — по Москве);
- `shots/*.png` — снимки остаются только в артефакте, в git не попадают;
- `spend-entry.json` — запись для журнала: `node tools/deploy/spend.mjs register --entry spend-entry.json`.

Строка «потрачено X ₽ из плана Y ₽ волны …» есть в отчёте, в сводке задания и в аннотации.

Повтор — только упавших брифов: тот же workflow, `briefs` через запятую (например `v3-03`), волна `retry`. Системы замера не удаляются, первая публикация ждёт ревью основателя в /admin.

## Вручную, без GitHub

```bash
node tools/eval/server/cli.mjs seed --session-file s.json --threshold v3 --max-cost-rub 1300 > seed.sql   # → psql < seed.sql > seed.out
node tools/eval/server/cli.mjs run --base https://borntobuild.ru --session-file s.json --seed-output seed.out \
  --threshold v3 --briefs all --max-cost-rub 1300 --screenshots shots --out v3.json
node tools/eval/server/cli.mjs collect --seed-output seed.out --threshold v3 > collect.sql                    # → psql < collect.sql > collect.out
node tools/eval/server/cli.mjs report --results v3.json --collect collect.out --out v3-a-checkpoint1-<дата>.md
```

Ручной прогон тоже платный, и запись в журнале трат делается заранее: `node tools/deploy/spend.mjs register …`.
