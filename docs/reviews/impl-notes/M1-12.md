# M1-12 — platform-web: S-import (сопоставление колонок при импорте таблицы): решения

- 2026-10-01 · M1-12 · Вход в импорт — кнопка «Загрузить таблицу» в подвале чата (chat-upload, скрытый input chat-upload-file). Она активна у редактора и владельца, когда у системы есть previewRevision и не идёт прогон. createImport отвечает 409 PREVIEW_NOT_READY без превью, поэтому до первой сборки кнопка disabled с подсказкой «Таблицу можно загрузить после первой сборки» (S1 по-прежнему показывает «после первого сообщения»). У наблюдателя — «Загружает таблицы редактор или владелец».
- 2026-10-01 · M1-12 · В multipart уходит имя `table.<ext>`, а не исходное имя файла: в нём могут быть ПДн («Клиенты Иванова.xlsx»), а сервер всё равно берёт только расширение. До отправки клиент отклоняет не .xlsx/.csv («Поддерживаются только файлы .xlsx и .csv») и файлы > 20 МБ. 413 → «Файл слишком большой: можно загрузить до 20 МБ», 415 → то же, что не-xlsx, остальное — message_ru.
- 2026-10-01 · M1-12 · Экран /s/:systemId/import/:importId опрашивает GET import раз в 0,8 с, пока статус profiling/mapping/importing или awaiting_confirm без inputId. SSE прогона не нужен: шаги совпадают со статусами импорта. Ошибка прогона берётся из GET /runs/:id (failure.message_ru, cancelled → «Импорт отменён»).
- 2026-10-01 · M1-12 · Рендерятся только поля профиля column, typeGuess, piiKindGuess, nullShare, distinct («Заполнено: 75% · 9 значений»). Любые другие поля ответа (значения, синтетические строки) игнорируются, это проверяет DOM-тест с «протекающим» ответом.
- 2026-10-01 · M1-12 · «Куда»: select со значениями skip | map:<entity>.<field> | new:<entity>. Поля берутся из спеки previewRevision (в неё грузятся строки) и только загружаемых типов (как IMPORTABLE в platform-api). Для new_field есть необязательное имя латиницей, пустое не отправляется: имя выбирает сервер. ПДн — select нет/ПДн, начальное значение — из mapping сервера (basic при piiKindGuess) с подсказкой «похоже на: телефон». Снять отметку можно только явным выбором.
- 2026-10-01 · M1-12 · В API нет числа строк, поэтому вместо «Загрузить N строк» кнопка говорит «Загрузить N колонок» (сколько колонок не пропущено). Число строк показывается в итоге «Импортировано строк: N» (rowsImported). Подтверждение: PUT mapping (полный, по всем колонкам профиля), затем POST /runs/:id/input {inputId, choice: confirm}. 422 OPS_INVALID → details.problems у строк (aria-invalid), input не отправляется. «Отмена» → choice: cancel (до needs_input — POST cancel), возврат в систему.
- 2026-10-01 · M1-12 · В рабочем пространстве прогон import_table показывается RunNotice «Импорт таблицы» («Ждёт подтверждения сопоставления колонок» на needs_input). Ссылки на экран импорта там нет: Run не несёт importId.
- 2026-10-01 · M1-12 · Стенд M1 (packages/e2e/stand/m1.ts): import_mapping идёт через настоящий router (live) в OpenAI-совместимые моки T1/T0. Каждый запрос пишется в .data/e2e-m1/llm-requests.jsonl (M1_LLM_LOG), маппер предлагает поля форума по заголовку. Фикстура в WIZARD_LLM_MODE=fixture не подошла: её ключ зависит от модели, payload и спеки. Остальные прогоны стенда LLM не вызывают.
- 2026-10-01 · M1-12 · @wizard/e2e получил devDependencies @wizard/pii (writeXlsx для канареечного xlsx в спеке) и @wizard/llm (createRouter для стенда). Это workspace-пакеты, лицензия не меняется.
- 2026-10-01 · M1-12 · e2e import.spec: xlsx на 12 канареечных строк (поток, вместимость, описание, куратор-ФИО, телефон) → import-pii-Телефон = basic, на экране и в запросах к моделям нет ни одной канарейки. «Описание» перенаправляется в stream.description → confirm → run succeeded, rowsImported = 12, строки видны в GET /api/data/stream на draft-хосте превью. Ширина 390 px — без горизонтального скролла. Наблюдатель: chat-upload disabled, прямой POST → 403, экран импорта — «Импорт таблиц доступен редактору и владельцу».
