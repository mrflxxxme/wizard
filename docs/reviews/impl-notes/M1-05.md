# M1-05 — вход конечных пользователей: решения реализации

- 2026-09-30 · M1-05 · Код в apps/runtime/src/auth/{keys,limits,deps,login,otp,telegram-oidc,consent,client-ip}.ts и routes/login.ts; в app.ts — только подключение маршрутов и опция `auth` (RuntimeAuthOptions: secretsKey, smsSender, orgOf, telegramOAuthBase, fetch, limiter). loginPage перенесён из routes/static.ts в routes/login.ts.
- 2026-09-30 · M1-05 · Ключи — HKDF(WIZARD_SECRETS_KEY) с отдельными подключами: pepper OTP, HMAC адреса, HMAC IP, userIdHash (runtime.yaml#logging), ключ запечатывания. Без ключа — случайный на процесс; при NODE_ENV=production ключ короче 32 символов → отказ старта (как platform-api, M1-02).
- 2026-09-30 · M1-05 · challengeId = `<id строки _w_otp>.<AES-256-GCM(адрес, канал, роль)>`, AAD — система, env и id. Контакт не хранится в БД до создания пользователя; _w_otp держит только HMAC адреса и code_hash = HMAC(pepper, id ␀ адрес ␀ код). Новый код для того же адреса заменяет старый.
- 2026-09-30 · M1-05 · Глобальные счётчики OTP (по всем системам) — таблица wz_runtime.otp_sends (только HMAC адреса и IP, org_key, billable). Схему создаёт runtime при первом использовании (CREATE IF NOT EXISTS под advisory xact lock) своим соединением; в облаке её должна создать миграция (M2-06) с DML-правами роли runtime. Строки старше 2 суток чистятся при вставке.
- 2026-09-30 · M1-05 · Лимиты: повтор через 60 с — на адрес в системе; 5/ч и 10/сут — на адрес глобально (заменяет «5/ч на адрес» в системе); 20/ч — на сеть клиента в системе (IPv4, IPv6 по /64). IP берётся из сокета node-server (server.ts запоминает его в WeakMap по Request); во внутрипроцессных fetch IP неизвестен — лимит по IP пропускается. За прокси — M2 (WIZARD_TRUSTED_PROXIES). 429 всегда с Retry-After.
- 2026-09-30 · M1-05 · Капча после 3 запросов с IP и алерт «SMS > 3× медианы» не сделаны: нет выбранного провайдера капчи и метрик (M2). Уведомление владельцу о превышении SMS-бюджета — пока только лог `sms_budget_exceeded`.
- 2026-09-30 · M1-05 · SMS-бюджет org в сутки (UTC): org и тариф — из platform.systems ⋈ platform.orgs (читается локально; 42P01/42501 → нет данных), иначе ключ — система, тариф по features.phoneOtp (start). Нужны org_id и plan в platform.deployments. Бюджет тратят только SMS prod (draft пишет в тестовый ящик).
- 2026-09-30 · M1-05 · Доставка: draft — всегда dev-sender (runtime outbox() + <outboxDir>/<systemId>/sms.jsonl), и для Free, и для платных; prod — `auth.smsSender` (провайдер — E-ACCESS), в локальном режиме — dev-sender, иначе 503 SMS_UNAVAILABLE. Email — почтовый аккаунт платформы (sendPlatformEmail); в локальном режиме без WIZARD_SMTP_HOST и для prod — outbox.
- 2026-09-30 · M1-05 · Коды вне runtime.yaml#data_api.error_codes: OTP_INVALID (422, неверный/просроченный/исчерпанный код, без раскрытия существования пользователя), SMS_UNAVAILABLE (503), OTP_DELIVERY_FAILED (502).
- 2026-09-30 · M1-05 · Роль нового пользователя: ?role= (только selfSignup и с этим методом), без роли — единственная selfSignup-роль с этим методом, иначе 403 FORBIDDEN. Проверка — после верного кода, поэтому start не раскрывает, есть ли пользователь. Существующий (приглашённый) входит своей ролью; метод обязан быть в loginMethods роли и разрешён тарифом.
- 2026-09-30 · M1-05 · Согласие при входе (в спеке M2, сделано сейчас по L3-33): «первый вход» = нет строки _w_consents(entity='users', row_id = user.id), поэтому приглашённые тоже дают согласие. Требуется, только если у системы есть consentText (иначе согласие дать нельзя — вход без него; наличие текста проверяют гейты). Без _consent → 422 CONSENT_REQUIRED, код не гасится. consent_text_hash хранится как bytea из hex, ip_hmac — HMAC сети.
- 2026-09-30 · M1-05 · Telegram OIDC: client_id — числовой префикс токена бота; token endpoint с Basic client_id:client_secret (core.telegram.org/bots/telegram-login), поэтому нужен новый секрет интеграции `telegram_client_secret` — дописать в connectors/telegram.yaml#secrets. Подпись id_token — RS256/ES256/EdDSA по JWKS (кэш 1 ч, перечитка при неизвестном kid); iss = база OAuth. База настраивается WIZARD_TELEGRAM_OAUTH_BASE (заглушки) — дописать в deploy.yaml.
- 2026-09-30 · M1-05 · redirect_uri = `<WIZARD_PUBLIC_SCHEME>://<host>/api/auth/telegram/callback` (локально http). Scope `openid telegram:bot_access`, плюс `phone`, если у запрошенной роли (или любой login-роли без ?role=) есть phone_otp (L1-36 истолкован так). telegram_chat_id = id пользователя (bot_access); приглашённый по телефону узнаётся по phone_number.
- 2026-09-30 · M1-05 · Cookie состояния wz_oidc / __Host-wz_oidc: запечатанные state, nonce, verifier PKCE, роль, next и согласие; SameSite=Lax (callback — навигация верхнего уровня), 10 мин, очищается на callback. Ошибки callback — 302 на /login?error=<CODE>&method=telegram&next=&role= (не JSON 422: это навигация браузера); AppShell.Login показывает текст и при CONSENT_REQUIRED — чекбокс и «Продолжить через Telegram».
- 2026-09-30 · M1-05 · Отзыв согласия выполняется сразу, а не «до 30 дней»: сессии удаляются, users — контакты, telegram, display_name, attrs → NULL/{} и blocked_at; pii-поля строк, где пользователь — ownerField, → NULL, а NOT NULL — заглушки «Удалено» / deleted@anonymized.invalid / +70000000000 (форматы CHECK appspec). Сущность, которую не удалось обезличить (savepoint), — в _w_audit op=consent_revoked_pending. platform.deletion_log и событие владельцу runtime не пишет — лог `consent_revoked` (userIdHash).
