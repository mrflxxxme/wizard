- 2026-10-01 · M2-05 · consentText в runtime: свой текст владельца → иначе шаблон consentTemplateId (неизвестный id → default), если пакет применяется (pii-поле или роль с входом). - 2026-10-01 · M2-05 · policyVersion = первые 16 hex sha256 отрендеренного текста политики без версии и даты (compliance.yaml#policy_page.versioning); меняется при смене шаблона, оператора, полей, ролей, retention, интеграций. Дата редакции — entry.publishedAt (у закреплённых систем — текущая дата), в хэш не входит. compliance.policyPage по умолчанию /privacy, если пакет применяется и страница спеки не занимает маршрут; RoleSpec.compliance.policyPage отдаёт эффективное значение.
- 2026-10-01 · M2-05 · Получатели в политике (subprocessors_of_system): Wizard (обработчик), Cloud.ru (хостинг), ЮKassa при коннекторе yookassa, почтовый провайдер при email_otp или коннекторе email, SMS-провайдер при phone_otp, Telegram при входе или коннекторе telegram. Факты (категории, действия по permissions, сроки) генерируются из спеки; «Права субъекта» — заглушка до юриста.
- 2026-10-01 · M2-05 · Журнал согласий: data API create/update с pii ролью без isAdmin пишет _w_consents в той же транзакции (entity, row_id, policy_version, consent_text_hash, ip_hmac). ip_hmac — HMAC сети клиента (auth keys) через WriteOptions.ipHmac (поле добавлено в DataAccess, задаёт только сервер). POST /api/fn с collectsPii — entity `fn:<name>`, row_id = вызывающий пользователь или случайный uuid для public (row_id NOT NULL), запись после успешного вызова. Записи ctx.db согласия не проверяют и не журналируют (согласие — на уровне функции).
- 2026-10-01 · M2-05 · appspec SYSTEM_TABLES: добавлены users.last_login_at (runtime.yaml#system_tables его перечисляет; нужен для retention users) и таблица _w_deletion_log {id, at, entity, mode ∈ delete|anonymize|retention|consent_revoked|subject_request, cutoff, rows_affected, fields} — журнал удаления системы, только счётчики. В runtime.yaml#postgres.system_tables её нет — дописать; платформа переносит её в platform.deletion_log вместо разбора _w_audit (счётчик _w_audit op=retention сохранён). Схемы, созданные до M2-05, этих колонки/таблицы не имеют (create_schema = CREATE TABLE IF NOT EXISTS): last_login_at пишется в savepoint и пропускается, retention users и журнал на таких схемах падают с отчётом retention_failed — нужна миграция системных таблиц (M2-06).
