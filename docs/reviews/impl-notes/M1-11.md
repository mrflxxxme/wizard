# M1-11 — platform-web: S10, публикация S6, M1-части S1/S3/S4/S7, S-auth, S-invite: решения

- 2026-10-01 · M1-11 · Сессия: PlatformProvider читает GET /me. 401 означает «не вошёл»: все маршруты, кроме /login, /invite/:token и /legal/:doc, уводят на /login?next=<путь>. next проверяется по ^/(?![/\\]). Если GET /me не отвечает (мок M0, тестовые двойники), платформа работает на M0-организации, права «только владелец» выключены, а сервер решает сам. Любой 401 UNAUTHORIZED от API (истёкшая сессия) тоже переводит на вход (ClientOptions.onUnauthorized).
- 2026-10-01 · M1-11 · Текущая организация: выбор в S1 (start-org, «Название · роль») хранится в localStorage `wz.orgId`, по умолчанию M0-организация или первое членство. orgId передаётся в GET /systems и POST /systems, только если у пользователя несколько организаций. Причина: api.yaml требует его именно тогда, а z.uuid() в platform-api не принимает сидовый id 00000000-…-0001 (не RFC 4122). Иначе M0-стенд в dev-режиме не мог создать систему. Для пользователя нескольких организаций, у которого текущая — M0-организация, это остаётся проблемой platform-api.
- 2026-10-01 · M1-11 · S-auth: согласия показываются после первого 422 CONSENT_REQUIRED: новый пользователь узнаётся только на verify, запрос кода ответ всегда 204. Чекбоксы раздельные и неотмеченные, ошибка выводится у каждого, код при этом остаётся действительным (M1-02). Клиент не отправляет verify, пока не отмечены все запрошенные согласия. Ссылки ведут на /legal/offer и /legal/pd-consent — заглушки «текст готовит юрист» (PENDING E-LEGAL, тексты от имени компании не публикуются).
- 2026-10-01 · M1-11 · S-invite: в API нет чтения приглашения по токену, поэтому карточка не называет организацию и роль до принятия: они есть в письме. После «Принять» новая организация (отличие GET /me до и после) становится текущей, и S1 показывает её системы и роль в start-org. 410 → «Приглашение устарело, попросите новое», 403 (чужой email) → message_ru сервера.
- 2026-10-01 · M1-11 · S10 — отдельная страница /s/:id/settings (rail со ссылкой ⚙). Блоки: команда (роль — select у владельца, «Убрать», «Сборки идут по одной…» + «Снять блокировку», форма приглашения, активные приглашения с «Отозвать»), модели («Только российский контур» — оптимистичный переключатель, откат при отказе; при t1Restricted — только текст), данные и вход (loginMethods ролей черновика; телефон помечен «только тарифы Старт и Бизнес», ссылки на S-billing нет до M2-11; сроки удаления из entity.retention без журнала удалений — M2), «Код — чтение», ревизии. Owner-only элементы у editor/viewer disabled с подсказкой «Доступно владельцу организации».
- 2026-10-01 · M1-11 · В S10 добавлен минимальный блок «Персональные данные»: оператор (название, почта, адрес, ИНН) → PUT /systems/:id/compliance. Полный блок с текстом согласия и журналом — M2-11. Без него владелец не может снять блокер OPERATOR_* на S6 из UI, а publish M1-04 требует оператора. Ссылка «Указать в настройках» на S6 ведёт к блоку (#pd). Форма заблокирована, пока не загружена спека, иначе загрузка перезаписывала бы введённое.
- 2026-10-01 · M1-11 · Ревизии S10: «Откатить» показывается у ревизий, которые были live (публикация live или superseded), кроме текущей prod. Подтверждение — модальный диалог «Вернуть prod к ревизии N? Данные сохранятся» (фокус на «Вернуть», Esc закрывает). Прогон rollback показывается на той же странице (RunNotice по SSE), по завершении перечитываются пилюля «prod · ревизия N» и история.
- 2026-10-01 · M1-11 · S6: «Опубликовать» публикует ту же ревизию, что и publishBlockers (M1-08: последняя, если её G0 не провален, иначе preview), с confirmDiff: true. Кнопка disabled при непустом publishBlockers, без ревизии, если prod уже на ней, и во время прогона. Если показана карточка diff S7, публикует она, а кнопка S6 скрыта. 403/422 выводятся как message_ru (publish-error). publish-card-status до M2 — «Сейчас публикация доступна без привязки карты». Прогоны publish и rollback видны в ленте (RunNotice: шаг, итог, ссылка prodUrl).
- 2026-10-01 · M1-11 · S1: «только РФ» доступен владельцу (PATCH settings, оптимистично), при t1Restricted отмечен и заблокирован. Карточки систем показывают «Команда: N человек · пригласить» (GET members; «пригласить» → S10, только владельцу). Добавлена кнопка «Выйти» (POST /auth/logout). Кредиты (start-credits, оценка и баланс) — заглушка без чисел до M1-03.
- 2026-10-01 · M1-11 · S3: «Строить» у наблюдателя disabled с подсказкой «Сборку запускает редактор или владелец». Ввод в чат и «Стиль» у наблюдателя тоже disabled. S4: пилюля «<Имя> собирает» из GET /systems/:id/lock, пока идёт сборка. Строка «Часть шагов выполнена на моделях в РФ» (build-model-notice) уже была в M0-16, её проверяет screens.browser.test.
- 2026-10-01 · M1-11 · CSP и L3-17: e2e проверяет заголовок CSP стенда M1 (default-src 'self', script-src 'self', frame-src только http://*.localhost:4110, object-src 'none'). Vitest-тест проверяет, что в src нет dangerouslySetInnerHTML, innerHTML, outerHTML и insertAdjacentHTML.
