Статус: всё, что не требует облака, сделано и проверено локально. В `backlog.yaml` статус M2-06 — `todo`, его не меняли (правило impl.md). Доступов к облаку, домена и прав администратора GitHub не было. Ни один облачный API не вызывался, ничего не развёртывалось. Runbook — `docs/ops/deploy.md`.

## Решения основателя, учтённые по ходу (сообщения координатора)

- 2026-10-01 · M2-06 · Код нейтрален к провайдеру. Helm не предполагает managed control plane и работает на k3s на обычных ВМ. gVisor включается через RuntimeClass на наших узлах. Всё, что зависит от провайдера, вынесено в тонкий слой: `infra/tofu/<провайдер>/`, `infra/helm/providers/<провайдер>.yaml` и бэкенд DNS-01.
- 2026-10-01 · M2-06 · Бета: бюджет до 30 000 ₽/мес, **без managed Kubernetes** (свои ВМ с k3s), managed PostgreSQL и S3. Staging поднимается по требованию одной командой и удаляется так же. Допустимый простой 1–2 ч. Первый провайдер — **Timeweb Cloud**: провайдер `timeweb-cloud/timeweb-cloud` 1.8.2 есть в реестре OpenTofu. Cloud.ru остаётся только провайдером LLM. ## Что сделано

### Приложение (тесты зелёные локально)
- **L3-11, превью-вход.** `apps/runtime/src/auth/preview-token.ts`.
  - Токен `p1.<claims>.<HMAC-SHA256>`. Claims строго `{systemId, env: draft, role, revision, platformUserId, exp, nonce}`. Секрет — не меньше 256 бит, подпись разделена по домену, сравнение за постоянное время. Токен отклоняется, если `exp ≤ now` или `exp > now + 15 мин`.
  - `GET /_wizard/preview-login?t=&next=` работает только на draft-хосте при заданном `WIZARD_PREVIEW_SECRET`. Nonce одноразовый: новая системная таблица `_w_preview_nonces` в `packages/appspec` SYSTEM_TABLES (для старых схем её создаёт `upgradeSystemTables`). Любая ошибка даёт 404. Ответ — `Referrer-Policy: no-referrer`, `next` проходит через `safeNext`.
  - Пользователь тот же, что у dev-login (`dev-<role>`): на него ссылаются seed черновика. Для публичной роли тоже создаётся сессия, чтобы пройти «ворота» черновика; `resolveSubject` превращает её в публичного субъекта.
  - Ворота черновика (`abuse.yaml#identification.draft`): вне локальных режимов, при заданном секрете или схеме https, draft-хост без живой сессии отвечает 404 на всё, кроме preview-login, health и хуков (`draftPreviewOnly` в env.ts).
  - platform-api `getPreviewUrl`: при `WIZARD_PREVIEW_SECRET` выдаёт `https://<slug>--draft.<WIZARD_SYSTEMS_DOMAIN>/_wizard/preview-login?t=…`. `exp` берётся на минуту меньше 15 мин, чтобы расхождение часов подов не отклоняло токен. Без секрета поведение M0 не меняется.
- **L3-15, cookie превью.** Правило уже было (M0-24, `preview-cookie.test.ts`). Добавлены облачные проверки: на draft — `__Host-wz_prev` с Secure; SameSite=None; Partitioned и без Domain; на prod нет ни одного SameSite=None, preview-login там 404.
- **L3-19, внутренний порт.**
  - `createRuntimeApp().internalFetch`. `startRuntime({internalPort})` поднимает второй listener; `main.ts` берёт `WIZARD_RUNTIME_INTERNAL_PORT`, по умолчанию PORT+1 = 4101, `off` отключает.
  - На внутреннем порту:
    - health с `{status, version, db, systemsLoaded}`, а на хосте системы ещё и `{system, env, revision}`;
    - `POST /_wizard/internal/reload {systemId, env}` с `X-Wizard-Internal-Token`, проверка за постоянное время; без настроенного токена — 403. Реализация — `SystemCache.evict`;
    - `POST /_wizard/internal/egress-authorize` — авторизация egress-прокси, см. ниже;
    - `/rpc/*` — `SandboxRpc`, если он передан.
  - На публичном порту `/_wizard/internal/*` по-прежнему 404, на https health отдаёт только `{status}`. Локально (http) детали health на публичном порту оставлены для инструментов M0–M1 (smoke, превью).
  - Smoke публикации (`httpSmoke`) при `WIZARD_RUNTIME_INTERNAL_URL` читает ревизию с внутреннего порта, подставляя Host системы. `prodUrl` и `systemOrigin` учитывают `WIZARD_SYSTEMS_DOMAIN` и `publicScheme`.
  - Попутно исправлен баг: в `listSystems` `page.map(toSystem)` передавал индекс как runtimePort.
- **L3-27, IP клиента.** Логика уже была (`effectiveClientIp`, ключи `/64`). Добавлен тест на композицию `clientNetwork(effectiveClientIp(...))`: XFF от недоверенного не меняет ключ; от ingress берётся последний недоверенный хоп; IPv6 считается по /64. В кластере `WIZARD_TRUSTED_PROXIES` = pod CIDR. NetworkPolicy пускает на публичные порты только namespace ingress. Traefik не доверяет XFF клиентов (`forwardedHeaders.insecure: false`).
- **L3-21, PgBouncer.** `apps/runtime/test/pgbouncer.test.ts`.
  - Тест сам запускает PgBouncer (`WIZARD_PGBOUNCER_BIN`) как обычный процесс с `default_pool_size=1` и `max_prepared_statements=100`. Под root он переходит на `-u nobody`.
  - Проверяется: два клиента получают один `pg_backend_pid`; `set_config('role'|'wizard.*', …, true)` системы A не видны следующей транзакции системы B; контрольный опыт с сессионным `SET` протекает (показывает, зачем запрет); data API двух систем, 20 параллельных запросов через одно серверное соединение, считает свои строки; после этого на соединении нет ни роли, ни GUC.
  - **Локально прогнан на настоящем PgBouncer 1.22**: пакеты Ubuntu распакованы в scratchpad через `dpkg -x`, без установки в систему. 4/4 зелёные. Без бинарника тест пропускается. В CI — job `pgbouncer` (apt-пакет).
- **L3-24, egress-прокси.** Вход `apps/runtime/src/egress-main.ts`. `remoteCapabilityAuthorizer` проверяет токен-возможность через внутренний порт runtime (`SandboxRpc.openCapability`: подпись, срок и **открытый** вызов). HMAC-ключ не покидает runtime: так требует M2-01 notes. Политика — `egressPolicyFor(spec)`, кэш до `exp` (не больше 30 с). Запреты: частные сети, metadata, CGNAT и CIDR кластера (`WIZARD_EGRESS_DENIED_CIDRS`).
- `sandboxNetworkPolicy({rpcPort})`: RPC идёт на внутренний порт 4101. Значение по умолчанию 443 сохранено, тесты M2-01 не тронуты.

### Kubernetes (Helm, `infra/helm/wizard`)
- **Почему Helm, а не Kustomize.** `deploy.yaml#ci_cd.cd` прямо называет `helm upgrade`. Значения окружений накладываются слоями: values, провайдер, профиль, окружение и `--set` из выходов OpenTofu. `--atomic` откатывает неудачный выкат. Helm — Apache-2.0.
- Проверено локально: `helm lint --strict`, `helm template` для вариантов {timeweb+k3s, cloudru} × {staging, prod}, kubeconform по встроенным kind. Все pod:
  - runAsNonRoot, seccomp RuntimeDefault, корневая ФС только для чтения, drop ALL, resources;
  - SA-токен смонтирован только у DNS-01-решателя.
- NetworkPolicy — default-deny в platform и sandbox. Разрешённые потоки:
  - web и api — только из ingress;
  - runtime: 4100 — из ingress; 4101 — из api, worker, egress-proxy и пода песочницы;
  - egress runtime — только PgBouncer, egress-proxy, поды песочницы и S3-CIDR;
  - egress-proxy и временный прямой выход коннекторов prod — интернет без частных сетей, metadata и API-сервера;
  - политика песочницы сгенерирована из `sandboxNetworkPolicy()`, тест следит за расхождением.
- Внутренний Service `wizard-runtime-internal` — только ClusterIP. Тест проверяет, что ни одно Ingress на него не указывает.
- PgBouncer в кластере: transaction mode, `max_prepared_statements=200`, `server_tls_sslmode=verify-full`.
- HSTS через Middleware Traefik: на prod — 2 года, includeSubDomains, preload; на staging — preload выключен.
- **Ingress — Traefik (MIT), а не ingress-nginx:** ingress-nginx снят с поддержки (best-effort до марта 2026).
- Профиль `profiles/k3s.yaml`: local-path RWO, по одной реплике, RuntimeClass `gvisor`, сети k3s.
- Аддоны (`addons.json`, версии сверены через `helm search` 01.10.2026, все отрендерены и прошли kubeconform):
  - cert-manager v1.21.2;
  - Traefik 41.6.1;
  - реестр образов twuni/docker-registry 3.0.0 — только для k3s: managed-реестра нет, а реестр в кластере от провайдера не зависит;
  - VictoriaMetrics single 0.48.0 — метрики 90 дней;
  - VictoriaLogs single 0.13.9 с vector — логи 30 дней.

### TLS wildcard (DNS-01)
- `infra/acme-dns01` — workspace-пакет `@wizard/acme-dns01`: webhook-решатель cert-manager с бэкендами DNS.
  - **Протокол:**
    - discovery и `ChallengePayload` Present/CleanUp;
    - запрос считается, только если пришёл через kube-apiserver: клиентский сертификат front-proxy и CA из `extension-apiserver-authentication`. Это проверено mTLS-тестом на сертификатах, сделанных openssl;
    - действовать можно только от SA cert-manager (`X-Remote-User`);
    - только имена `_acme-challenge.*` в разрешённых зонах;
    - сбой DNS API даёт `success=false`, а не HTTP-ошибку.
  - **Бэкенд timeweb** (`api.timeweb.cloud/api/v1/domains/{zone}/dns-records`, Bearer): одна TXT-запись на значение, повторный Present ничего не делает, CleanUp удаляет по значению.
  - **Бэкенд cloudru** (Evolution DNS + IAM): rrset со слиянием значений, асинхронные операции, обновление токена при 401.
  - Оба бэкенда проверены на fake-серверах. С настоящими API не проверялись.
- Chart (`acme-webhook.yaml`): APIService, RBAC, серверный сертификат через cainjector, NetworkPolicy. ClusterIssuer берёт решатель из `tls.solver`/`tls.webhook.dnsProvider` (из файла провайдера) либо произвольный список `tls.solvers`.

## Смена провайдера: какие файлы меняются

Новый провайдер `X` (Yandex Cloud, Selectel, VK Cloud и т. п.):

1. `infra/tofu/X/provider.json`:
   - имя;
   - `requiredEnv` (переменные учётных данных → `TF_VAR_*` или null, если провайдер читает env сам);
   - `profile` (`k3s` для ВМ, null для managed K8s);
   - `destroyable`;
   - `helmValues`.
2. `infra/tofu/X/modules/env/*.tf` и `infra/tofu/X/envs/{staging,prod}/main.tf` с тем же **контрактом выходов**:
   - `env` — `{registry_url, registry_push?, domains, network{pods_cidr, services_cidr, nodes_cidr}, postgres_cidr, s3_endpoint?, ingress_ip?}`;
   - `postgres` — `{main|platform: {connection_string}}`;
   - `kubeconfig` **или** `k3s_server{private_ip, public_ip}`;
   - корни принимают `-var=ingress_ip`.

   Для ВМ модуль берёт cloud-init из `infra/k3s/*.tftpl` без изменений. Если нужен свой CLI-конфиг (зеркало), он лежит в `infra/tofu/X/tofurc`. Если PITR описывается в IaC — `infra/tofu/X/drills/pitr/main.tf`.
3. `infra/helm/providers/X.yaml`:
   - `config.s3Endpoint`/`s3Region`;
   - `tls.solver` + `tls.webhook.dnsProvider` (или `tls.solver: none` + `tls.solvers`, например acmeDNS);
   - `data.storageClass`/`accessMode`;
   - `runtime.s3Cidrs`.
4. Если DNS у X, а бэкенда ещё нет — `infra/acme-dns01/src/backends/X.ts` и регистрация в `backends/index.ts` с тестом на fake-сервере.
5. GitHub: `vars.WIZARD_PROVIDER=X`, секреты из `requiredEnv`. Состояние OpenTofu — в S3 X: эндпоинт задаётся в `backend "s3"` корней X.

**Не меняются:**
- `infra/helm/wizard/**`, `infra/helm/addons/**`, `infra/helm/profiles/**`, `infra/k3s/**`, `infra/k8s/**`, `infra/docker/**`;
- `tools/deploy/*.mjs`, все workflows;
- код приложений.

Тест «provider neutrality» не пускает имена провайдеров в чарт.

## Отклонения от спеки и предлагаемые правки текста

1. `deploy.yaml#cloud` целиком описывает Cloud.ru и managed K8s (D16). Решение основателя — Timeweb и k3s на ВМ. Нужно переписать раздел: провайдер; k3s на ВМ, без HA control plane; managed PG и S3; staging по требованию. Также поправить `architecture.yaml#environments.cloud` и `infra_and_libs.k8s_addons`.
2. **PITR.** Провайдер Timeweb в OpenTofu даёт только ежедневные копии (`twc_database_backup_schedule`), PITR в IaC нет. Пока Timeweb не подтвердит PITR в DBaaS, критерий «restore из PITR проверен» выполняется восстановлением копии: RPO до 24 ч. Это расхождение с `deploy.yaml#postgres.pooling/backup` и `restore_drill`. Нужно решение основателя: принять RPO 24 ч для беты или требовать PITR (свой PG с WAL-G на ВМ — не managed). Runbook `restore_drill` в спеке указывает `docs/runbooks/pitr.md`, фактически это раздел в `docs/ops/deploy.md`.
3. **Наблюдаемость:** VictoriaMetrics и VictoriaLogs (Apache-2.0) вместо Prometheus + Grafana + Loki. Совместимо с PromQL и LogsQL, два маленьких бинарника, UI встроен. Правка: `deploy.yaml#observability.stack`.
4. **Реестр образов** для k3s — в кластере (CNCF distribution), а не Artifact Registry. Правка: `deploy.yaml#ci_cd.cd`.
5. `deploy.yaml#local.env_vars` — добавить `WIZARD_RUNTIME_INTERNAL_PORT`, `WIZARD_RUNTIME_INTERNAL_HOST`, `WIZARD_RUNTIME_INTERNAL_URL`, `WIZARD_VERSION`, `WIZARD_EGRESS_ALLOW`, `WIZARD_EGRESS_DENIED_CIDRS` (в `.env.example` уже добавлены).
6. `runtime.yaml#service_endpoints.health`: на публичном порту при `WIZARD_PUBLIC_SCHEME=http` (только локально) остаются детали `{system, env, revision}` — их используют инструменты M0–M1. Предлагаю дописать это в спеку.
7. `deploy.yaml#ci_cd.ci` говорит, что SBOM и license-check — в `ci.yml`: так и сделано (job `supply-chain`). SBOM образов — в `images.yml`.
8. `deploy.yaml` описывает buckets {artifacts, imports, eval, backups}, `runtime.yaml#files` — `system-files`. Сделаны пять бакетов, `files` — бакет полей file. Lifecycle (imports 7 дней) на Timeweb в провайдере недоступен — остаток.

## Остатки: что нужно, когда появятся доступы

- **Блокер prod:** у platform-api нет SMTP-почтальона. `main.ts` создаёт API без `mailer`, а при `NODE_ENV=production` `createPlatformApi` падает («почтовый провайдер платформы не подключён»). Нужен SMTP-Mailer по `WIZARD_SMTP_*` (M1-06/E-ACCESS). Вне рамок M2-06.
- **Артефакты не в S3.** `.data/artifacts` platform-api, worker и runtime делят том `wizard-data`. На k3s это RWO local-path, и все такие поды должны быть на сервере k3s. На managed K8s нужен RWX. После пересоздания сервера артефакты пропадают: нужна пересборка или повторная публикация. Задача: хранилище артефактов на S3 (`deploy.yaml#object_storage.buckets.artifacts`).
- **Песочница не оркестрируется.** Поды workerd по пулам не создаются. В кластере есть только RuntimeClass, namespace, квоты и NetworkPolicy. Кто размещает системы по подам и доставляет config.capnp — открытый вопрос из M2-01; runtime сейчас не создаёт `SandboxRpc` в `main.ts`.
- **Коннекторы runtime через egress-прокси** (остаток M2-01). До этого в prod включён временный прямой egress 443/465/587 у runtime (`runtime.directConnectorEgress`) — без частных сетей, metadata и API.
- **DBOS** (worker и platform-api) может требовать сессионное соединение. Если DBOS использует LISTEN, его системная БД должна ходить мимо PgBouncer: NetworkPolicy это позволяет при заданном `postgresCidrs`. Проверить на первом выкате.
- **Роли БД.** Миграции создают `wizard_owner`, `wizard_runtime`, `sys_*` (M2-01: нужен CREATEROLE). Неизвестно, есть ли CREATEROLE у администратора managed PG Timeweb. Вопрос недели 0 к Timeweb. Если нет, роли создаёт поддержка или нужен свой PG.
- **TLS к PG из PgBouncer:** `server-ca.crt` Timeweb DBaaS нужно скачать в панели и положить в Secret `wizard-pgbouncer`.
- **Пул paid песочницы.** В prod одна ВМ-агент пула `free`, платные системы туда не попадут, пока не появится второй агент `paid` или пул не будет общим в конфиге SandboxPool. Это решение основателя по бюджету.
- **Не настроено:** алерты (`deploy.yaml#observability.alerts`), OpenBao в кластере (секреты пока из файлов раннера), lifecycle бакетов, CAA-записи (`twc_dns_rr` не поддерживает CAA), DKIM платформы.
- **Не проверялось (нет docker и облака):** реальная сборка образов (базовый `node:22.22-bookworm-slim` и nginx-unprivileged 1.29 тянутся из Docker Hub — для РФ лучше зеркалировать), cloud-init на ВМ Timeweb, ServiceLB k3s с плавающим IP, `externalTrafficPolicy: Local` (сохраняется ли IP клиента), эндпоинт S3 Timeweb `s3.twcstorage.ru` и регион `ru-1` (сверить), формат строки подключения DBaaS, настоящие DNS API Timeweb и Cloud.ru, OIDC-роль OpenBao.
- **Сохраняется ли IP клиента:** если балансировщик или DNAT провайдера делает SNAT, включить PROXY protocol в Traefik (`ports.websecure.proxyProtocol.trustedIPs`).
- **После первого выката prod** — заявка в PSL и HSTS preload по runbook. Номер PR записать сюда.

## Пилот

Решение основателя от 01.10.2026: пилот на паре живых клиентов. Расходы — 5–10 тыс. ₽/мес, функциональность полная, Timeweb Cloud, только Москва, без managed K8s и managed PG. Простой — 1–2 ч, потеря данных — не больше ≈ 1 мин. Runbook — `docs/ops/deploy.md`, раздел «Пилот», спека — `specs/platform/deploy.yaml#pilot`. Ни один облачный API не вызывался, ничего не развёртывалось.

### Решения

- **Профиль `pilot`** — `infra/helm/profiles/pilot.yaml` поверх `k3s.yaml`.
  - В `tools/deploy/infra.mjs` появились `PROFILES` и `profileChain`.
  - Слои значений: values → провайдер → k3s → pilot → values-<env> → `pilot-<env>.yaml`. Последний слой нужен, потому что `values-prod.yaml` масштабирует бету до 2–3 реплик.
  - Профиль приходит из выхода OpenTofu `env.cluster_profile`, поэтому команда та же: `pnpm infra:apply --env prod`.
- **Размер ВМ — по замеру.** Сэмплер `tools/deploy/rss-sample.mjs` снимал память стенда разработки в покое и во время `forum.spec.ts` (сборка, G0/G1, превью; прогон под `flock`, зелёный). workerd снят отдельно, в `workerd.sandbox.test.ts`.
  - Замер: platform-api — 300/356 МиБ, worker — 312/565 МиБ и до 2,7 ядра при сборке, runtime — 132/185 МиБ, workerd — 100 МиБ на два пода.
  - k3s и аддоны оценены: запускать k3s здесь нельзя (правило 7).
  - Пик стека ≈ 4,5 ГиБ из 7,7. Выбран **Cloud MSK 80 (4/8)**, запас ≈ 40 %. Вариант 2/4 не вмещает пик, 8/16 — первая ступень роста.
  - Тест чарта проверяет, что сумма запросов помещается в узел.
- **PostgreSQL 16 — StatefulSet** на local-path, а не сервис хоста.
  - Один механизм выката (Helm), проверки kubeconform и NetworkPolicy, тот же образ для CronJob.
  - Образ `wizard-postgres` = postgres:16.13-bookworm + WAL-G v3.0.9 + rclone v1.75.1 + node. Загрузки закреплены sha256.
- **WAL-G.**
  - `archive_timeout 60`, libsodium, zstd, `WALG_PREVENT_WAL_OVERWRITE`.
  - Базовая копия — CronJob каждый день. Хранение 14 дней: `delete before FIND_FULL`, так что любая точка последних 14 дней восстановима.
- **Сценарии** — `infra/postgres/pg-ops.mjs`, без зависимостей.
  - `monitor` (сайдкар): отставание = возраст старейшего файла `.ready` в `pg_wal/archive_status`. Это точнее, чем `last_archived_time`: на простаивающей БД время последнего архива старое, хотя очереди нет.
  - `basebackup`.
  - `restore-drill`: SHARE-блокировки, точные счётчики, `pg_create_restore_point` в той же транзакции, `recovery_target_name`. Сверка — точное равенство по каждой таблице схемы platform. Без блокировок сравнение было бы приблизительным.
  - `bootstrap` (init-контейнер): пустой том → восстановление из архива, пустой архив → initdb, недоступный архив → под не стартует.
  - `data-sync` и `data-restore`.
- **Алерты.** Путь — события `level: error` в логе в формате логгера платформы, они уходят в VictoriaLogs. Необязательный вебхук `WIZARD_OPS_ALERT_URL` (Bot API Telegram) — не чаще раза в час на вид. Метрики — `/metrics`. В `wizard_ops.ops_runs` пишется журнал копий и учений, сайдкар следит за их давностью.
- **Том `.data`** — исходники ревизий и `secrets.enc` — копируется rclone crypt в бакет `backups` раз в минуту.
  - Удалённо ничего не удаляется.
  - Без этого RPO ≈ 1 мин касался бы только БД: артефакты пока не в S3 (остаток M2-06).
  - Под работает от uid 1000: файл секретов имеет права 0600.
- **Образы — GHCR вместо реестра в кластере.**
  - Сборка в `images.yml` на GitHub-hosted раннерах (`vars.WIZARD_IMAGES_GHCR=enabled`, `GITHUB_TOKEN` с `packages: write`).
  - ВМ тянет образы с токеном `read:packages`. Pull-секрет передаётся через stdin как dockerconfigjson.
  - Релиз ждёт тег в GHCR через API distribution (`waitForImages`).
  - Docker Hub — через зеркало `dockerhub.timeweb.cloud` в `registries.yaml`; шаблон k3s получил переменную `docker_mirror`.
  - Запасной путь, если GHCR закроют из РФ: `image_registry = "registry.wizard.local"`, тогда возвращается профиль k3s с реестром и `--build-images`.
- **Наблюдаемость.**
  - VictoriaMetrics (90 дней, 5 ГБ) оставлена: она нужна для триггеров роста.
  - VictoriaLogs (30 дней, 5 ГБ) оставлена ради ретенции по времени. Ротация kubelet по размеру хранит логи «тихих» контейнеров дольше 30 дней.
  - Vector заменён на vlagent (чарт `victoria-logs-collector` 0.3.8, Apache-2.0).
  - Оверлеи аддонов: поля `overlays` и `exceptProfiles` в `addons.json`.
- **OpenTofu Timeweb.** Один модуль на две формы.
  - `settings.postgres = null` — пилот: нет DBaaS, бакеты `files` (10 ГБ) и `backups` (100 ГБ), `postgres_mode = in-cluster`.
  - ВМ берётся из пресета `twc_presets` с `price_filter.to = max_price`: план, которому нужен пресет дороже, падает. Это потолок самостоятельного роста.
  - Локация закреплена на `ru-3` валидацией, обе формы — только Москва.
  - Порт 30500 открывается только при реестре в кластере.
  - Образцы tfvars: пилот — `terraform.tfvars.example`, бета — `terraform.tfvars.beta.example`.
  - `tofu test` (`modules/env/tests/shapes.tftest.hcl`) проверяет пилот, staging, бету и запрет не-Москвы. `mock_provider` в OpenTofu 1.10 не применяется, если локальное имя провайдера (`twc`) не совпадает с типом (`timeweb-cloud`) — проверено на минимальном примере. Поэтому вместо него все data и resource переопределены, а `base_url` провайдера указывает на закрытый локальный порт: обращений к API нет.

### Отклонения и правки спек

1. **S3 только в Санкт-Петербурге.** У Timeweb S3 есть только в ru-1, это проверено на странице услуги 01.10.2026. ВМ — в Москве, бакеты — в Петербурге, всё в РФ. Это единственное отступление от «только Москва»; записано в `deploy.yaml#pilot.provider`.
2. **Ручное ежемесячное учение `#cloud.postgres.restore_drill`** заменено для пилота еженедельным автоматическим. `docs/runbooks/pitr.md` по-прежнему не существует: runbook — `docs/ops/deploy.md`.
3. **PgBouncer → PostgreSQL в пилоте без TLS.** Трафик pod → pod внутри одной ВМ, под NetworkPolicy. Значение `pgbouncer.serverTlsSslmode` по умолчанию осталось `verify-full`.
4. **Наблюдаемость.** vlagent вместо Vector — дописать в `deploy.yaml#cloud.observability.stack` вместе с пунктом 3 исходных заметок.
5. **CD.** Образы пилота строятся на GitHub-hosted раннерах и лежат в GHCR, а не в Artifact Registry. Нужна правка `deploy.yaml#cloud.ci_cd.cd`, частично отражено в `#pilot.images`.
6. **`deploy.yaml#cloud.secrets.tenant`:** OpenBao в пилоте не разворачивается, как и раньше (остаток). Ключи WAL-G и копии `.data` нужно хранить вне ВМ, иначе архив не расшифровать после потери ВМ.

### Остатки

- **Пул paid на одном узле.** `sandboxPod()` выбирает узел по `wizard.ru/pool=<pool>`, а у одного узла только одно значение метки. На ВМ пилота стоит `free`, поды платных систем туда не попадут. Нужна правка apps/runtime: отдельные ключи меток на пул или общий пул в конфиге SandboxPool. Это продолжение остатка «Песочница не оркестрируется», который полной функциональности песочницы в кластере пока не даёт.
- **DBOS и прямое соединение.** NetworkPolicy пропускает platform-api и worker прямо к `wizard-postgres:5432`. Нужен ли DBOS отдельный URL мимо PgBouncer, проверить на первом выкате (как и раньше).
- **Не проверялось:** сборка образа `wizard-postgres` (docker не использовался); entrypoint официального образа при `readOnlyRootFilesystem` и uid 999; реальный S3 Timeweb для WAL-G и rclone (эндпоинт `s3.twcstorage.ru`, path-style); `twc_presets` с `price_filter` против API; зеркало `dockerhub.timeweb.cloud` в containerd k3s; ghcr.io с ВМ в Москве.
- **Цены «[не проверено]»:** плавающий IPv4 (≈ 150 ₽, анонс 2023 г.), домены, ВМ раннера. Сверить с калькулятором при первом заказе.
- **Секреты платформы:** OpenBao в кластере пилота нет (остаток M2-06).
