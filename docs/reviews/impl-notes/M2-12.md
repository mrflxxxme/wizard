- 2026-10-01 · M2-12 · `tools/eval/partner-brief.mjs upload|fetch|check`. upload берёт файл только вне репозитория (realpath, симлинки раскрываются) и требует, чтобы пересказ уже существовал. Для текстовых оригиналов он отказывает, если пересказ совпадает с оригиналом, содержит дословный фрагмент из 12 слов или больше 30 % общих шестисловий. Затем PUT в `<bucket>/eval/partners/…` с метаданными sha256, brief, partner, а в бриф записывается только блок `partner`. fetch пишет файл только вне репозитория (по умолчанию `mkdtemp` в tmpdir ОС, права 0600) и сверяет sha256. check хеширует отслеживаемые git файлы того же размера и падает, если какой-то совпадает с записанным оригиналом. Та же проверка идёт в `pnpm test` (`test/partner-brief.test.ts`), то есть в CI.

## Что требует live-ключей и действий основателя

- Live-прогон 30 брифов (`eval:full`) и запись p80 по реальным моделям. Сейчас p80 проверен только на fixture-прогонах. Нужны `CLOUDRU_API_KEY` (и `ZAI_API_KEY`, пока T1 по умолчанию). Новых брифов в CI-fixture нет (`skipped` — «нет фикстуры»), их фикстуры `tools/fixtures/eval/<id>.jsonl` появятся только из `--llm-mode=record`.
- Брифы дизайн-партнёров (E-PARTNERS): по 3 от каждого, пересказ плюс `partner-brief.mjs upload`. Нужны бакет и ключи `EVAL_S3_*` в Timeweb (секреты — не в чат).
- Реальная загрузка в S3 Timeweb не проверялась. Path-style адресация `s3.twcstorage.ru/<bucket>/<key>` и SigV4 с регионом `ru-1` предполагаются по S3-совместимости Timeweb [не проверено], проверены только на моке. Если Timeweb потребует virtual-hosted адресацию, нужна правка `objectUrl` в `lib/s3.mjs`.

## Правки спеки (предлагаю)

- `eval.yaml#briefs.format`: добавить `partner: "опционально {ref: P01…, original: {key: eval/partners/<ref>/<id>.<ext>, sha256, bytes}} — бриф-пересказ дизайн-партнёра; оригинал только в S3 eval в РФ (tools/eval/partner-brief.mjs)"`.

Скрипт партнёров по умолчанию берёт `ru-1`, workflow — переменную `EVAL_S3_REGION`. Её нужно задать при настройке бакета, иначе отчёты live уйдут с неверным регионом (`docs/founder/access-checklist.md` ещё описывает Cloud.ru S3).
