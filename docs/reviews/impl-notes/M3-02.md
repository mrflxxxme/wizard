# M3-02 — ИИ-действия extract/generate на T0: решения, отклонения, остатки

Задача сделана по просьбе основателя «собрать всё, что не требует его участия», хотя её зависимость M2-09 формально ждёт развёртывания (код M2-09 смержен). Статусы backlog и CHANGELOG не менялись.

## Что сделано

- 2026-10-01 · M3-02 · Форма aiAction. Схема оставляет `input` и `output` открытыми объектами. Смысл зафиксирован в `packages/appspec/src/ai-actions.ts` (`resolveAiAction`, `aiTargetFields`), описания полей в `appspec.schema.json` дополнены:
  - `input`: `{entity, fields?: string[], instruction?: string ≤ 1000}`. По умолчанию источниками считаются все поля string, text и enum, кроме приёмников. Поля file уходят в модель как изображение или PDF.
  - `output` для extract: `{fields: string[]}`, допустимые типы приёмников: string, text, enum, int, decimal, money, bool, date, email, phone, url. Для generate: `{field}`, одно поле string или text.
  - Нарушения формы ловит семантическая проверка спеки: неизвестное поле даёт UNKNOWN_FIELD, неверный тип или форма — SCHEMA_INVALID. Прежние тесты с `input: {entity}` проходят, потому что `fields` необязательно.
- 2026-10-01 · M3-02 · `@wizard/llm`. Новый модуль `runtime-ai.ts` (`routeRuntimeAi`, `runtimeAiMessages`, `fillFieldsTool`, `normalizeAiValue`, `toPlainText`) построен по образцу `import-mapping.ts`.
  - extract использует инструмент `fill_fields` с toolChoice=required; ответ сверяется с типами полей.
  - Ответ generate приводится к простому тексту: управляющие символы удаляются, внешний code fence и кавычки снимаются, длина обрезается. Разметка сохраняется как символы и не интерпретируется.
  - Вызов идёт с `containsPiiHint=true`, потому что это реальные записи.
- 2026-10-01 · M3-02 · Запрет T1 стоит в нескольких местах:
  1. `decideTier` уже отправлял callType из `pii_forbidden_for_T1.always` в T0.
  2. Новый guard роутера `assertTierAllowed` проверяет tier перед каждой попыткой, в том числе в fixture-режиме. Для runtime_ai_*, support и любых мультимодальных вызовов цепочка T1 не строится, даже если реестр маршрутов говорит обратное.
  3. `routeRuntimeAi` бросает T1_FORBIDDEN, если ответ пришёл не от T0.
  4. Клиент шлюза в runtime (`httpAiGateway`) не принимает ответ с tier ≠ T0, и runtime ничего не пишет.

  Тест подменяет реестр так, что runtime_ai_* маршрутизируются в T1, и проверяет, что к zai ушло 0 запросов.
- 2026-10-01 · M3-02 · Мультимодальность. В сообщение пользователя добавлено поле `LlmMessage.attachments` (`{mime, data base64}`); провайдер получает его как file part AI SDK, то есть image_url или file для PDF. Любое вложение переводит вызов в T0 с reason `pii_hint` для любого callType.
  - Ключ фикстуры и строка фикстуры хранят хеш вложения `sha256:…`, а не байты (`withoutAttachmentBytes`). Ключи прежних фикстур не изменились.
  - Имена файлов в модель не передаются, потому что в них могут быть ПДн.
  - ОТКЛОНЕНИЕ от models.yaml#credits.runtime_ai («мультимодальные вызовы — отдельный callType с T0 only»): отдельного callType нет. Мультимодальный вызов идёт под runtime_ai_* (они и так только T0), а общий guard запрещает T1 любому вызову с вложениями. Так не пришлось менять список call_types и матрицу роутера. Если нужен отдельный callType для учёта, его можно добавить позже.
- 2026-10-01 · M3-02 · Шлюз платформы `POST /internal/v1/ai/run` (`apps/platform-api/src/ai/gateway.ts`, `routes/internal.ts`).
  - Аутентификация по `X-Wizard-Internal-Token` (WIZARD_INTERNAL_TOKEN). Без токена в конфиге маршрут отвечает 404. Он подключён до originGuard; ingress в облаке маршрутизирует только `/api`, поэтому снаружи `/internal/*` недоступен.
  - Проверки идут в таком порядке, и при отказе модель не вызывается:
    1. Лимит платформы M2-15: 503 AI_UNAVAILABLE, алерт основателю отправляет `LlmMonthlyCap`.
    2. `aiAction.monthlyLimit`: 429 AI_LIMIT_REACHED. Считаются строки `platform.ai_action_calls` со статусом pending или ok по паре (system, action) за календарный месяц по Москве.
    3. Кредиты org ≤ 0: 402 AI_CREDITS_EXHAUSTED, владельцу раз в месяц уходит письмо (`claimOpsAlert` с ключом `ai_credits:<systemId>:<yyyy-mm>`).
  - Лимит и запись журнала делаются в одной транзакции под `pg_advisory_xact_lock` системы, чтобы параллельные вызовы не превысили лимит.
  - Вызовы ИИ пишутся в `llm_calls` через DbUsageSink, поэтому в live-режиме они входят в месячный лимит платформы (тест).
  - Режим роутера: live при WIZARD_LLM_MODE=live, иначе fixture с фикстурой `WIZARD_AI_FIXTURE` (по умолчанию `unit/runtime-ai`). record для ИИ-действий не используется: записывать фикстуры можно только из брифов репозитория, а не из живых записей.
- 2026-10-01 · M3-02 · Списание, `Billing.chargeAi`.
  - ОТКЛОНЕНИЕ от billing.yaml («charge агрегируется по (system, час) с ключом `ai:<systemId>:<yyyy-mm-ddThh>`»): журнал только дописывается, а задача требует идемпотентности на каждый вызов. Поэтому на каждый вызов пишется отдельная строка charge с ключом `ai:<systemId>:<yyyy-mm-ddThh>:<callId>`. Час берётся из `created_at` строки журнала, так что повтор не перейдёт в другой час. Агрегат по часу получается по префиксу ключа.
  - Как и для хода интервью, списание не превышает доступный остаток, разницу несёт платформа. Повтор с тем же callId не списывает повторно и не считается в лимите второй раз; модель при повторе вызывается снова, потому что результат прошлого вызова не хранится.

## Остатки

- Helm и сеть облака: runtime нужен WIZARD_PLATFORM_INTERNAL_URL (ClusterIP-сервис platform-api) и NetworkPolicy runtime → platform-api; платформе — WIZARD_INTERNAL_TOKEN из platformEnv. Без этого в облаке кнопки ИИ отвечают 503, а backfill останавливается с RUNTIME_UNREACHABLE. В `scripts/dev.mjs` не задан WIZARD_RUNTIME_INTERNAL_URL, поэтому локальный backfill без `.env` тоже даёт RUNTIME_UNREACHABLE.
- Лимит public-роли хранится в памяти процесса: при нескольких репликах runtime он действует на реплику. Если нужен общий счётчик, понадобится таблица в wz_runtime, как otp_sends.
- Ограничение public-роли действует только на кнопку. Воркфлоу, которые запускаются от записей public-роли (on_create с ai-шагом), ограничены только monthlyLimit и кредитами.
- `_aiFilled` читается сверткой `_w_audit` без индекса (entity, record_id). Если записей станет много, нужен индекс в SYSTEM_TABLES — это миграция схем app_*.
- Повтор вызова с тем же callId снова вызывает модель (платформа несёт расход), потому что результат не хранится, чтобы не держать данные записей в БД платформы.
- UI платформы (S-card) не показывает флаг aiBackfill отдельной строкой; карточка выводит summary.
- Помощь агентов (builder/orchestrator) в M3-02 не входила.
