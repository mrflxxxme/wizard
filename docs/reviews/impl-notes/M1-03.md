# M1-03 — кредиты: ledger, hold/charge по факту, гранты Free, лимиты тарифа: решения

- 2026-09-30 · M1-03 · Распределение по корзинам хранится в самих строках ledger, а не в note. Одна логическая операция с ключом K даёт по строке на корзину, ключи K, K#2, K#3… (уникальны в org). У каждой строки заполнен bucket, поэтому view platform.credit_buckets — простая сумма по (org_id, bucket, bucket_expires_at). note_ru остаётся текстом для людей. Миграция 0003_m1_credits добавляет CHECK знака суммы по kind и триггер, который запрещает UPDATE, DELETE и TRUNCATE.
- 2026-09-30 · M1-03 · hold(−cap) пишется в транзакции approveCard/startFixBuild (insertRun с billing), а не при переходе прогона в running. Так 402 INSUFFICIENT_CREDITS {available, required} приходит синхронно и без гонки. Ключ — hold:<runId>. Отмена прогона в очереди проходит через finalize → release.
- 2026-09-30 · M1-03 · Факт used = Σ llm_calls.credits_milli (billable) по run_id, как в billing.yaml#credit.test. runs.credits_used_milli по-прежнему служит только для проверки бюджета перед вызовом. Расчёт идёт одной транзакцией в finalize: release(+hold по корзинам), затем charge(−min(used, Σhold)) из корзин своего hold, затем expire. Остаток корзины, которая истекла во время прогона, сгорает сразу после расчёта.
- 2026-09-30 · M1-03 · Ход интервью идёт без hold: charge = min(used, 2 кр., available), остаток перерасхода несёт платформа. 402 при available ≤ 0 проверяется на POST messages/answers, а также на createSystem: это первый ход интервью.
- 2026-09-30 · M1-03 · Refund пишется отдельными строками после charge (ключ refund:<runId>). Он полагается прогону любого вида, если прогон завершился с кодом INTERNAL, WORKER_RESTARTED, LLM_UNAVAILABLE или MIGRATION_FAILED. Для build — ещё и когда у прогона нет прошедшего G0 в gate_reports, в том числе при cancelled/stop до G0. Остановка по потолку после G0 списывается полностью (= cap).
- 2026-09-30 · M1-03 · Free считается периодами по 30 дней от orgs.created_at. Приветственные 100 кредитов действуют до created+30д. Месячные 25 — это период k≥1 [created+30k д, created+30(k+1) д): корзина сгорает в момент следующего гранта. Ключ — grant:free_monthly:<org>:<yyyy-mm-dd начала>. Пропущенные периоды задним числом не начисляются, поэтому кредиты не копятся.
- 2026-09-30 · M1-03 · Гранты и expire материализуются лениво: settleOrg под pg_advisory_xact_lock(hashtext(org_id::text)) вызывается перед каждой операцией с балансом и в GET credits/ledger. Дополнительно в platform-api работает ежечасный таймер Billing.sweep (credits_cron; DBOS ещё нет, опция creditsCronMs, 0 — выключен). createOrg и личная org M1-02 отдельно грант не пишут: он появляется при первом обращении.
- 2026-09-30 · M1-03 · Уведомление владельцу при available < 10% месячного гранта не реализовано: в платформе нет канала уведомлений (письма только OTP и приглашения). Переносится к задаче уведомлений.
- 2026-09-30 · M1-03 · До платежей M2 платный тариф и докупка начисляются только staff-командой с прямым доступом к БД: `pnpm --filter @wizard/platform-api credits balance|topup|plan|adjust|sweep` (src/billing/cli.ts). plan start|business ставит orgs.plan и начисляет plan_monthly на период (по умолчанию 30 дней), корзина сгорает в конце периода. topup начисляет 60 кредитов на пакет на 365 дней, ключ topup:staff:<reference>. HTTP /admin/* не добавлялся: он требует MFA (M2).
- 2026-09-30 · M1-03 · Локальный стенд: Config.billingExemptOrgs, по умолчанию [локальная org] при WIZARD_AUTH_MODE=dev, иначе пусто. Новых env-переменных нет. Для этих org лимиты тарифа не действуют, а нехватку кредитов покрывает запись adjustment «Локальный стенд: пополнение без оплаты» (ключ dev:*), так что инварианты ledger соблюдаются. Иначе e2e и `pnpm dev` на общей .data/pg упирались бы в 3 черновика и 100 кредитов. Непустой список при NODE_ENV=production → отказ старта. Тесты M1-03 передают billingExemptOrgs: [].
- 2026-09-30 · M1-03 · draft_systems — все неудалённые системы org (deleted_at is null). Проверка идёт в транзакции createSystem под advisory lock org, поэтому параллельные создания не превышают лимит. Для publish (M1-04): `await deps.billing.lock(trx, orgId); await deps.billing.assertLimit(trx, orgId, "prod_systems", current)` → 402 PLAN_LIMIT {limit, current, plan}. MEMBER_LIMITS M1-02 сверяется тестом с PLANS и billing.yaml.
- 2026-09-30 · M1-03 · raise_cap_N: если available < N, в needs_input остаётся только вариант «Остановить» («вариант недоступен»). Выбор raise пишет дополнительный hold с ключом hold:<runId>:cap:<новый cap> и в той же транзакции поднимает runs.credits_cap_milli. Если кредитов не хватило из-за гонки, прогон становится cancelled.
- 2026-09-30 · M1-03 · CreditBalance: available = Σ amount_milli, held = −Σ(hold + release), balance = available + held. В buckets попадают только живые корзины с остатком > 0. listLedger: строки по корзинам отдаются отдельными записями, source = bucket, cursor = id последней записи страницы.
- 2026-09-30 · M1-03 · Порядок блокировок: строка runs → строка systems → advisory lock org. createSystem берёт advisory lock до вставок. FOR UPDATE по orgs в этих путях не используется, чтобы не получить взаимную блокировку с FK KEY SHARE.
