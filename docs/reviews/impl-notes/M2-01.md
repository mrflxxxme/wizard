## L3-20 — системный доступ через роль БД, а не через GUC
- 2026-10-01 · M2-01 · packages/appspec: `DdlOptions.systemRole`. toRLS создаёт `"wz__system" … TO <systemRole> USING (true) WITH CHECK (true)` и выдаёт этой роли USAGE и DML. Условие `current_setting('wizard.role') = '__system'` из политик удалено полностью. Если systemRole не передан, системной политики нет вообще (fail-closed). Новые экспорты: `systemRoleName(schema)` (app_<key>_<env> → sys_<key>_<env>_system, длинные имена хешируются), `toSystemRoleDDL(schema, {members})` (идемпотентно: роль NOLOGIN NOINHERIT NOBYPASSRLS, `GRANT … WITH INHERIT FALSE, SET TRUE`, то есть членство даёт право только на SET ROLE), `dropSystemRoleDDL(schema)`.
- 2026-10-01 · M2-01 · Роль создаёт подключение с CREATEROLE: локально владелец `wizard`, в облаке — провизионер платформы (M2-06). Мигратор её не создаёт. В Postgres право SET ROLE проверяется по session_user, поэтому `ensureSystemRole` (apps/runtime) выдаёт SET роли runtime и session_user подключения, которое выполняет сиды, экспорт и удаление.
- 2026-10-01 · M2-01 · runtime DataAccess (data/pg.ts): системный контекст (ctx.systemDb, SYSTEM_SUBJECT, воркфлоу, планировщик) — это `set_config('role', sys_…_system, true)`, контекст субъекта возвращает роль runtime. GUC wizard.role по-прежнему выставляется (логическое имя для аудита и $user.role), но прав не даёт. Telegram-хук clearEverywhere переключается на системную роль каждой схемы; схемы без роли (созданные до M2) пропускаются.
- 2026-10-01 · M2-01 · Переведены с GUC на SET LOCAL ROLE <systemRole>: platform-api draft (migrateDraft/seedDraft), prod (applyProdMigration), exports, imports/load, publish/snapshot (чтение prod — роль prod, запись draft — роль draft, TRUNCATE и COMMENT — владелец), privacy/deletion-log (moveJournal теряет параметр migratorRole), privacy/delete-system (подсчёт строк — системной ролью, DROP SCHEMA — владельцем, затем удаление системных ролей). Гейты G1/G2 (packages/gates/src/g1/env.ts): эфемерная схема получает свою роль, reset делает TRUNCATE до переключения роли, drop удаляет роль.
- 2026-10-01 · M2-01 · Тесты: appspec (имена, DDL, отсутствие GUC в политиках; на живом PG: GUC '__system' под ролью runtime видит 0 строк, у роли runtime нет USAGE, но есть SET; системная роль получает 42501 на чужой схеме и platform.*; атрибуты роли). runtime data-api: DataAccess в системном контексте имеет current_user = sys_…_system, в контексте субъекта — роль runtime; системная роль A не читает схему B. Тестовые хелперы удаляют системные роли (роли общие для кластера).
- Переход локальной БД: старые схемы app_* без системной роли перестанут давать системный доступ, пока draft не пересоберётся (migrateDraft создаёт роль). Миграции платформы не нужны (0012 не занят).
- Не сделано по db_access: роли sys_<key>_<env> для пользовательского контекста (сейчас wizard_runtime на все системы) и интеграционный тест через PgBouncer. В acceptance M2-01 их нет — это следующий шаг.

## L3-23 — RPC по токену-возможности, пул ≤ 10 систем, SharedArrayBuffer
- apps/runtime/src/sandbox/capability.ts: `v1.<payload>.<HMAC-SHA256>`, payload ровно {systemId, env, requestId, exp}, ключ ≥ 256 бит только у runtime. Подпись сравнивается за постоянное время, exp ≤ now — истёк.
- sandbox/rpc.ts `SandboxRpc`: open() регистрирует вызов (exp = now + лимит вызова) и выпускает токен, close() его отзывает. `POST /rpc/<systemId>/<env>`: 403, если токена нет, он подделан, подписан чужим ключом, истёк, выпущен для другой системы или env, его requestId не открыт или вызов уже завершился (украденный токен непригоден и до exp). Диспетчеризация переиспользует `dispatch` из exec/executor.ts (теперь экспортирован вместе с `isFatalHostError`).
- sandbox/workerd-executor.ts `WorkerdExecutor` (тот же интерфейс, что FunctionExecutor → `GuestExecutor`): вызов уходит на сокет Worker'а системы. Wall-лимит → 504 TIMEOUT и `onTimeout`, токен отзывается в finally. Эндпоинт вычисляется лениво: поды перезапускаются с новыми адресами. `createRuntimeApp({sandbox})` включает функции без WIZARD_UNSAFE_LOCAL_EXEC.
- sandbox/guest.mjs: гостевой рантайм вынесен из child.mjs и общий для M0–M1 (vm, `--allow-fs-read` добавлен ровно на этот файл) и workerd (sandbox/worker-host.mjs). Гость удаляет SharedArrayBuffer, Atomics, WebAssembly и console; worker-host дополнительно удаляет fetch, WebSocket, EventSource, caches и connect.
- sandbox/workerd-config.ts: config.capnp пода — по Worker'у (изоляту) на систему, ≤ 10, globalOutbound = сервис `deny-all` (`network (allow = [])`), без compatibility flags (нет nodejs_compat и precise_timers), биндинги — только RUNTIME_RPC (external) и текстовые. v8Flags `--max-old-space-size=128`. Отдельный health-Worker для liveness.
- sandbox/pool.ts `SandboxPool`: Free и платные — разные пулы, ≤ 10 систем на под (конфиг > 10 отклоняется). Business — под на организацию. Если места нет, `SandboxPoolFullError`, переуплотнения нет.
- sandbox/pod.ts: манифест пода (runtimeClassName gvisor, runAsNonRoot, readOnlyRootFilesystem, drop ALL, seccomp RuntimeDefault, без токена SA, hostNetwork/hostPath, dnsPolicy None, taint/nodeSelector пула) и NetworkPolicy (egress только runtime:443 и egress-proxy:3128, ingress только от runtime). Применение — M2-06.
- Тесты: test/sandbox/rpc.test.ts (токены и все варианты 403), pool.test.ts (пул, конфиг workerd, манифесты), executor.test.ts — сквозной путь /api/fn → WorkerdExecutor → worker-host.mjs → RPC → DataAccess. В нём worker-host запускается в обычном процессе Node (test/sandbox/emulated-worker.mjs), это **не песочница**: тест проверяет протокол, отзыв токенов, отсутствие SAB/Atomics/WebAssembly/fetch у кода системы и 504 по wall-лимиту.
- Отклонение от спеки: в workerd нет compatibility flag, который выключает SharedArrayBuffer. workerd сам запрещает Atomics.wait и не даёт потоков. SAB и Atomics убирает наш модуль до загрузки кода системы. Правка спеки: isolation.yaml#M2.runtime — «выключены compatibility flags» → «удалены модулем-хостом Worker'а; workerd запрещает Atomics.wait».
- Отклонение: в open-source workerd нет лимитов CPU и памяти на изолят. CPU-лимит — wall-таймаут runtime (504) плюс liveness пода (зациклившийся изолят блокирует health → перезапуск). Память — `--max-old-space-size`; OOM роняет процесс, и вызов получает 500 INTERNAL, а не 422 LIMIT_EXCEEDED. Требование «латентность соседа < 2×» при зацикливании соседа в одном процессе workerd не выполнимо — нужен процесс на систему или лимиты, которых в workerd нет. Вынести на ревью изоляции.
- Отклонение: пункт escape_tests.M2 «fork/exec … отклоняется gVisor» — gVisor исполняет fork/exec. Запрет обеспечивает workerd (нет API), gVisor и seccomp — без capabilities (mount, raw socket, ptrace). Предлагаю переформулировать.

## L3-24 — egress-прокси
- sandbox/egress.ts `createEgressProxy`: только CONNECT (любой обычный запрос → 403). Авторизация `Proxy-Authorization: Bearer <токен-возможность>` → политика системы (иначе 407). :443 — хост из policy.https, :465/:587 — только из policy.smtp. Хост — DNS-имя (IP-литерал, wildcard, скобки → 403). Все адреса после резолва публичные и вне deniedCidrs (isPrivateAddress/ipInCidrs из @wizard/connectors), соединение открывается на проверенный IP без повторного резолва (DNS rebinding). Первый TLS-рекорд буферизуется: SNI ≠ CONNECT-хост, нет SNI, не TLS → разрыв, апстрим не получает ни байта. На :587 до STARTTLS разрешены только EHLO/HELO/STARTTLS/NOOP/RSET/QUIT (AUTH в открытом виде → разрыв), затем та же проверка SNI. Лимиты байт и длительности. В логах только host, port, status, reason/outcome, размеры и метка системы.
- `egressPolicyFor(spec, {globalAllow, platformSmtpHost})`: https = хосты коннекторов ∪ (function.egress ∩ глобальный allowlist); smtp = хост email-интеграции с provider=smtp, иначе SMTP платформы.
- sandbox/sni.ts — разбор ClientHello. ClientHello, разбитый на несколько рекордов, отклоняется.
- Тест test/sandbox/egress.test.ts: настоящий ClientHello из node:tls, внедрённые DNS и dial (трафик не покидает машину). Проверены 403/407, rebinding, metadata, cluster CIDR, SNI match/mismatch, не-TLS, 465, 587 и чистота логов.
- Не сделано: ctx.http.fetch из Worker'а через прокси (в M2 возвращает EGRESS_DISABLED, как в M0–M1). Подключение транспорта коннекторов runtime к прокси и деплой прокси — M2-06.
