# M1-04 — draft/prod: решения исполнителя

- 2026-09-30 · M1-04 · prod в M1 — локальный/стендовый хост `<slug>.localhost:<runtimePort>` (публичный prod — после привязки карты, M2-07). runtime менять не пришлось: DbRegistry читает prod-строки platform.deployments (view дополнен UNION по publications live/suspended), SystemCache подхватывает смену ревизии на следующем запросе; POST /_wizard/internal/reload в M1 не шлётся.
- 2026-09-30 · M1-04 · Артефакт prod = артефакт ревизии из draft-сборки (`<systemId>/<revision>`, bundle_key ревизии): раскладка runtime.yaml#artifact_layout не различает env, отдельная prod-сборка (минификация, без bridge.js и wz-map) потребует `<systemId>/<env>/<revision>` в packages/build и runtime — вне зоны задачи. Бандл prod пока содержит `<script src="/_wizard/bridge.js">`, на prod-хосте он отдаёт 404 (безвредно).
- 2026-09-30 · M1-04 · schema_hwm_revision двигается в той же транзакции, что и DDL apply_migration (а не в switch): db.yaml определяет hwm как «ревизия, чья схема фактически применена». Падение между apply_migration и switch оставляет схему-надмножество и согласованный hwm, повторная публикация — без повторного DDL (тест). switch дополнительно ставит max(hwm, revision), как в workflows.yaml.
- 2026-09-30 · M1-04 · Предусловие «g0_passed = true» расширено: последнюю ревизию без бандла (правка «Стиль» или PUT /compliance владельца) можно публиковать — publish сначала гоняет draft G0 (migrate_draft, bundle, preview), затем G0 prod. Иначе публикация после ввода данных оператора ПДн невозможна без пересборки.
- 2026-09-30 · M1-04 · PUT /systems/:id/compliance (setCompliance, M1) реализован здесь: данные оператора — предусловие публикации (OPERATOR_NAME_REQUIRED/OPERATOR_CONTACT_REQUIRED). Ревизия kind=compliance, author=user, без кредитов.
- 2026-09-30 · M1-04 · gate_G0_prod: при destructive-шагах плана G0 не запускается, сразу run_failed DESTRUCTIVE_IN_PROD (публикация failed, prod не тронут); иначе executors.gates('G0', env=prod, prevSpec = spec(hwm)), отчёт пишется в gate_reports обычным образом.
- 2026-09-30 · M1-04 · smoke по умолчанию — HTTP к 127.0.0.1:runtimePort с Host `<slug>.localhost` (GET / → 200 и /_wizard/health.revision = ревизии). Провал → публикация failed, предыдущая снова live, prod_revision возвращается, run_failed SMOKE_FAILED. `PlatformApiOptions.publish` принимает свой smoke, роли мигратора/runtime и паузы повторов lock_timeout (по умолчанию 5/15/45 с).
- 2026-09-30 · M1-04 · migration_plan в publications хранится без `next` (полной спеки): {env, additiveOnly, steps: [{kind, destructive, text}], destructive, errors}; Publication.migrationSteps = число шагов (включая set_rls). Откат prod — publication с {steps: [], additiveOnly: true}, schema_revision = текущий hwm; RLS-политики остаются от hwm (без DDL по спеке).
- 2026-09-30 · M1-04 · Откат draft — прогон rollback: ревизия kind=revert (spec и files_manifest_sha целевой), событие ops_applied (0 ops), затем draft G0 → preview. Разрешён editor; для prod нужен owner (NOT_OWNER).
- 2026-09-30 · M1-04 · draft_snapshot: признак «уже снят с этой prod-ревизии» — COMMENT ON SCHEMA app_<key>_draft = `wz_snapshot:<id live-публикации>` (колонки в db.yaml нет; пересоздание схемы draft сбрасывает признак, копия повторится). Таблицы сущностей draft очищаются (TRUNCATE), пользователи draft (seed, dev-<role>) остаются, пользователи prod копируются с синтетическими display_name/email/phone, telegram_* и attrs не копируются.
- 2026-09-30 · M1-04 · draft_snapshot маскирует поля с pii ≠ none (file без pii — как basic, как в seed G1) и дополнительно все поля типов email/phone. Синтетика — в форматах seed G1 (словарь SYNTHETIC_NAMES, user<N>@example.test, +7999000XXXX, «ул. Тестовая», «Тестовый текст»), N детерминирован sha256(id, поле); уникальность сохраняется перебором. faker-ru не подключён: словаря seed достаточно и isSyntheticValue G1 его распознаёт. qr_token в копии заменяется случайным; ссылки на нескопированные строки → NULL или строка пропускается (NOT NULL); копируются только колонки, описанные какой-либо из спек (prod, hwm, preview), и системные.
- 2026-09-30 · M1-04 · diffSpecs(prev, next) в @wizard/appspec — diff спек, а не батча ops (у humanDiff агентов вход — ops). kind из api.yaml: изменение app — kind=theme; acceptance в diff не показывается; значения compliance в тексте не выводятся. Файлы — строки kind=file по манифестам ревизий (в platform-api). from по умолчанию — parent_version.
- 2026-09-30 · M1-04 · e2e (packages/e2e/test/publish.test.ts, vitest) поднимает platform-api и runtime в процессе теста (реальные гейты G0, migrate_draft/seed_draft/bundle, prod-миграции, HTTP-сервер runtime с DbRegistry), строитель — скрипт (forum.json как ops + specs/runtime/examples): записанной LLM-фикстуры правки нет, а Playwright-сценарий «только HTTP» не может добавить поле без LLM. Поэтому у @wizard/e2e появились devDependencies @wizard/platform-api, @wizard/runtime, postgres (workspace/стек) — расхождение с architecture.yaml#monorepo (e2e depends_on: []).
- 2026-09-30 · M1-04 · Миграция 0003_m1_publications (после 0002_m1_accounts из M1-02): publications + пересоздание view deployments с prod-строками. Тест миграций сверяет с db.yaml и мигрированные M1-таблицы.
- 2026-09-30 · M1-04 · GET /systems/:id publishBlockers считается для ревизии, которую владелец опубликовал бы сейчас (последняя публикуемая draft-ревизия, иначе preview): NOT_OWNER, SYSTEM_SUSPENDED, GATES_FAILED, OPERATOR_NAME_REQUIRED/OPERATOR_CONTACT_REQUIRED, PHONE_LOGIN_PLAN_REQUIRED.
