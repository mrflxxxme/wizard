# M0-23 — решения исполнителя

- 2026-09-30 · M0-23 · Исполнитель — дочерний процесс Node 22 (`--permission --allow-fs-read=<каталог артефакта>`, без `--allow-child-process`/`--allow-worker`, `--max-old-space-size=128`, env {}, без argv), а не worker_threads: isolation.yaml#M0_M1.mechanism и acceptance M0-23 (L3-12) приоритетнее устаревшей строки runtime.yaml#functions.isolation.M0_M1.
- 2026-09-30 · M0-23 · В процессе — node:vm с `vm.constants.DONT_CONTEXTIFY` (глобал без перехватчиков, иначе `this.constructor` вёл бы в объект хоста), `codeGeneration {strings:false, wasm:false}`, `microtaskMode: 'afterEvaluate'`. SDK функций (`v`, `query/mutation/action`, `WizardError`) создаётся внутри контекста; хост держит ссылки на функции гостя и обменивается с ними только JSON-строками. Удалены console, WebAssembly, SharedArrayBuffer, Atomics; fetch/process/require/Buffer/setTimeout в контексте отсутствуют.
- 2026-09-30 · M0-23 · `server/functions.mjs` грузится как `vm.SourceTextModule` (в дочернем процессе флаг `--experimental-vm-modules`); импорт чего-либо кроме `@wizard/sdk` и зависание верхнего уровня (>5 с) → ошибка загрузки → 503 FUNCTIONS_DISABLED «Функции системы не загружены» + лог `functions_load_failed`. Нет каталога артефакта или файла — тот же ответ.
- 2026-09-30 · M0-23 · Валидаторы аргументов гость сериализует при загрузке, runtime пересоздаёт их через `v` из @wizard/sdk и проверяет в createFunctionHost до запуска handler (RegExp — как {source, flags}).
- 2026-09-30 · M0-23 · Пул: до 4 процессов на загруженную ревизию системы, один вызов верхнего уровня на процесс; вложенные runQuery/runMutation из action идут в тот же процесс (AsyncLocalStorage). Простаивающие процессы останавливаются через 60 с; `closeExecutors()` экспортирован для остановки.
- 2026-09-30 · M0-23 · Сроки: query/mutation 1 с, action 30 с, но не больше потолка 5 с; по сроку процесс получает SIGKILL → 504 TIMEOUT. Гонка таймаута в createFunctionHost выставлена на +500 мс и служит только страховкой.
- 2026-09-30 · M0-23 · Ошибки ctx.* с кодом LIMIT_EXCEEDED/TIMEOUT, ошибки сериализации (40001/40P01) и прочие не-WizardError фатальны для вызова, даже если функция их перехватила: иначе лимит чтений и повтор SERIALIZABLE обходились бы try/catch.
- 2026-09-30 · M0-23 · Падение процесса по памяти (SIGABRT/код 134) → 422 LIMIT_EXCEEDED {limit: "memory"}; иное падение → 500 INTERNAL. `--stack-size` не задаётся: в runtime.yaml значения нет, остаётся умолчание V8.
- 2026-09-30 · M0-23 · Модель прав Node 22 не ограничивает сеть; в vm-контексте сетевых API нет, ctx.http.fetch → EGRESS_DISABLED внутри гостя. Сетевую изоляцию закрывает M2 (L4).
- 2026-09-30 · M0-23 · `_consent` в /api/fn проверяется по содержимому (consentMatches); несовпадающий считается отсутствующим → CONSENT_REQUIRED только для функций с collectsPii у ролей без isAdmin.
- 2026-09-30 · M0-23 · ctx.user.attrs = строка users без id, role, phone, email, telegram*, created_at/updated_at/created_by (sdk.md §2.5).
- 2026-09-30 · M0-23 · Коннекторы в action (connectors: 'outbox'): вызов пишется в outbox runtime, ответ как в тестовом режиме (telegram {delivered:false, reason:"test_mode"}, email {messageId}, yookassa refund {status:"pending"}/getPaymentStatus "none", qr revoke). Живые коннекторы через @wizard/connectors — отдельной задачей.
- 2026-09-30 · M0-23 · /api/events: ≤ 3 потока на токен сессии (анонимные не ограничены), 4-й → 429 RATE_LIMITED; Origin проверяется, если есть; первый комментарий `: ok`, heartbeat `: ping` каждые 25 с.
- 2026-09-30 · M0-23 · В RuntimeServices добавлен `log` (одна строка в app.ts), чтобы ctx.log.* функций попадал в лог runtime с system/env. В apps/runtime добавлена dev-зависимость @wizard/build (workspace) — сборка фикстур в тестах. Из guards.test.ts убраны строки-заглушки 501 для /api/fn и /api/events.
