# M0-24 — решения реализации

- 2026-09-30 · M0-24 · SSE /api/events и критерий «invalidate организатору с id, участнику без id» переданы M0-23 (routes/events.ts в его зоне по распределению работ); M0-24 даёт статику, мост, QR, qr_token и оплату-заглушку.
- 2026-09-30 · M0-24 · Мост /_wizard/bridge.js генерирует runtime: platformOrigin берётся из WIZARD_PLATFORM_ORIGIN процесса runtime (тот же источник, что frame-ancestors), revision — из registry. Meta wz-platform-origin из draft-сборки мостом не читается: DOM доступен коду системы.
- 2026-09-30 · M0-24 · set-role: мост принимает только URL того же origin, подставляет next = текущий путь + query и делает location.replace; id запроса хранится в sessionStorage и возвращается в ready после перезагрузки. navigate — pushState + popstate (как navigate в SDK), ответа нет; route-changed шлётся из перехвата pushState/replaceState и popstate. select-mode и highlight (M3) игнорируются как неизвестные типы. ready.role берётся из GET /_wizard/spec.
- 2026-09-30 · M0-24 · БЛОКЕР для превью в iframe (M0-16): cookie сессии SameSite=Lax (runtime.yaml#auth.session_cookie) не уходит из iframe localhost:5173 → *--draft.localhost (разные сайты), поэтому set-role в iframe в M0 не меняет роль (проверено в Chromium). Проверено: `SameSite=None; Secure; Partitioned` на http://*.localhost работает. Предлагаемое решение: dev-login на *--draft ставит cookie с этими атрибутами (прообраз __Host-wz_prev из M2); не сделано — меняет M0-09 и спеку session_cookie.
- 2026-09-30 · M0-24 · Полный CSP (security_headers.csp, в спеке since M1) уже в M0 ставится на HTML-документы системы (index.html, /login, страница политики, pay-mock) вместе с Referrer-Policy и Permissions-Policy; frame-ancestors по-прежнему дописывает guards.ts. Бандл форума под этим CSP рендерится и мост работает (ручная проверка Chromium).
- 2026-09-30 · M0-24 · Кэш: index.html — no-cache; assets с хешем в имени (index-<sha256[:12]>.*) — max-age=31536000, immutable; прочие файлы assets/ (logo.png) — no-cache. /sw.js и /manifest.webmanifest до M1 → 404. Путь в /assets/ — одно имя [A-Za-z0-9_.-], иначе 404.
- 2026-09-30 · M0-24 · /login и compliance.policyPage — минимальные серверные шаблоны runtime до AppShell.Login (M0-25/M1-05): в draft с WIZARD_DEV_LOGIN=1 /login показывает ссылки dev-login по login-ролям (фильтр ?role=, next через safeNext), иначе текст «Вход пока недоступен». Страница политики — реквизиты оператора и текст согласия.
- 2026-09-30 · M0-24 · qr_token: pg.ts принимает асинхронный генератор qrToken; SystemCache получает его от ConnectorHost: для поля, совпадающего с qr-интеграцией (entity + tokenField), — signQrToken активным ключом (как issueQrToken), без интеграции — прежний случайный токен.
- 2026-09-30 · M0-24 · Секреты коннекторов: RuntimeAppOptions.secrets (фабрика SecretReader), по умолчанию .env WIZARD_SECRET_<SYSTEMID>_<NAME>. Для draft в локальном режиме без qr_signing_key runtime генерирует связку ключей и хранит её в .data/secrets/<systemId>.json (0600), чтобы билеты переживали перезапуск.
- 2026-09-30 · M0-24 · ConnectorCtx на стороне runtime (src/preview/connectors.ts): SystemDb — отдельная транзакция READ COMMITTED от __system на каждый вызов через DataAccess (CONFLICT → UniqueViolation); store — строки _w_connector_calls с ключом kv:<integration>:<key>, action='kv', значение и срок в result; outbox — в RuntimeApp.outbox(); fetch → EGRESS_DISABLED. M0-23 может заменить SystemDb своим ctx.systemDb.
- 2026-09-30 · M0-24 · QR check: интеграция по ?integration= или единственная; нет qr-интеграции → 404; тело {payload ≤ 200, deviceId ≤ 100, checkpoint? ≤ 100}, иначе 422. /_wizard/qr/manifest и /sync — 501 до M2.
- 2026-09-30 · M0-24 · Оплата M0: POST /api/pay/:integration читает запись правами вызывающего (скрытая/чужая → 404) и вызывает startPayment; ошибки NOT_PAYABLE/NOTHING_TO_PAY → 409 с message_ru. /_wizard/pay-mock (только draft) — страница с суммой и кнопкой; подтверждение — POST /_wizard/pay-mock {binding, id} скриптом /_wizard/pay-mock.js (форма без JS не может передать X-Wizard-Request), тоже только для записи, видимой вызывающему; интеграция ищется по id привязки.
- 2026-09-30 · M0-24 · Dev-вход: `pnpm --filter @wizard/runtime dev` слушает $PORT/$HOST (запасные WIZARD_RUNTIME_PORT/HOST, затем 4100/127.0.0.1), корень репозитория по умолчанию вычисляется от файла (dev.mjs запускает скрипт из apps/runtime), .env корня загружается, если есть.
- 2026-09-30 · M0-24 · Зависимости runtime: @wizard/connectors (workspace) и devDependency @wizard/build (workspace; тесты собирают бандл форума с заглушкой ui-kit в apps/runtime/.generated, в .gitignore).
