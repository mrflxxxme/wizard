# M0-12 — оркестратор (packages/agents): решения

- 2026-09-30 · M0-12 · Пакет экспортирует `@wizard/agents/core` (tool-loop `callTool`/`runToolLoop`, `defineTool` zod → JSON Schema через `z.toJSONSchema(io: "input")`, события) и `@wizard/agents/orchestrator`. Общий `src/index.ts` не тронут: M0-13/M0-14 добавляют свои sub-path. Зависимости: zod 4 (стек), @wizard/llm, @wizard/pii, @wizard/appspec.
- 2026-09-30 · M0-12 · Оркестратор между ходами не хранит состояние. `OrchSession` (JSON) и выходы `OrchOutput` с `id` сохраняет хост (interview_turn.persist_output). `chat_output {kind, messageId, cardVersion?}` и `run_failed` отправляются через `deps.emit`. Мини-карточка правки уходит как `change_proposal`, текстовые подсказки — как `answer`.
- 2026-09-30 · M0-12 · applies_when проверяется кодом по сигналам Analysis: goals, constraints, имена, метки и keyFields сущностей, роли (регулярки в `taxonomy.ts`). Цитаты evidence не используются.
- 2026-09-30 · M0-12 · Правило default_if_unasked: confidence=high, если модель не отметила развилку в `unknowns`. Поэтому развилки с impact < 3 задаются, только если они есть в `unknowns`. Остальные решаются по рекомендации кода и попадают в карточку как «Решено по умолчанию».
- 2026-09-30 · M0-12 · Зависимые развилки: F-VISIBILITY зависит от F-STAFF, F-GD-PREPAY — от F-PAYMENT (≠ none). Их задают, только если зависимость закрыта брифом. Иначе они решаются по рекомендации после ответов, потому что все вопросы формулируются одним вызовом.
- 2026-09-30 · M0-12 · F-APPROVAL при segment=events не применяется: подтверждение там покрывают F-EV-TICKETS (оплата и квоты) и F-EV-SPEAKERS (модерация). С этими правилами форум детерминированно даёт ровно 5 развилок, как в golden: F-EV-CHECKIN, F-LOGIN, F-RETENTION (score 4), F-PAYMENT, F-STAFF (score 3).
- 2026-09-30 · M0-12 · ask_questions должен покрыть все выбранные развилки ровно по одному разу, варианты — из таксономии после plan_rule (на free нет phone*). Любое нарушение возвращается модели как ошибка инструмента, допускается ≤ 2 повторов, затем ORCH_INVALID_OUTPUT.
- 2026-09-30 · M0-12 · Analysis после валидации проходит через `scrubJson`. Если в карточке находятся ПДн (`detect` по всем строкам), это ошибка валидации `PII_IN_OUTPUT` с повтором. `forkAnswers` карточки берётся из ответов сессии, копия модели игнорируется. В `acceptance.check` допускается `milestone`, как в appspec acceptance (golden AC5/AC6).
- 2026-09-30 · M0-12 · Оценка: доля «qa 0.1» делится поровну между qa_generate и qa_explain (по 0.05). Tier сборки T0 при ruOnly, при t1Restricted ≠ false (fail-safe, как в route()) или при buildDefaultTier=T0, иначе T1. Форум: 578 000 токенов, T1 → 27 кредитов (cap 41), T0 → 35.
- 2026-09-30 · M0-12 · Мини-карточка small_edit считается по той же формуле (с базой 110k) по имеющимся полям, cap = max(3, ceil(1.5·expected)). Калибровка — через estimate.coefficients.json.
- 2026-09-30 · M0-12 · Правки: style_only определяет классификатор кода (регулярки стиля без структурных слов), без LLM и без смены состояния. small_edit/big_change определяет вызов interview с инструментом `submit_change` ({kind, summary, questions ≤ 2}). Мини-карточка приходит через `submit_change_card`. В spec.schemas.tools этих двух инструментов нет, это дополнение.
- 2026-09-30 · M0-12 · После 5 версий карточки CARD_EDIT не выполняется: выдаётся текст «начать заново» (hint=restart), состояние не меняется. При нехватке баланса APPROVE тоже не выполняется: текст с «Докупить» и insufficientCredits=true.
- 2026-09-30 · M0-12 · Ошибки LLM: BUDGET_EXCEEDED роутера → run_failed BUDGET_STOPPED, остальные LlmError (включая FIXTURE_MISS) → LLM_UNAVAILABLE. Код ошибки сохраняется в `failure.cause`, содержимое промптов — нет.
- 2026-09-30 · M0-12 · Тест зеркала таксономии читает orchestrator.yaml через python3 + PyYAML (как validate.mjs). YAML 1.1 читает вариант `no` у F-INVENTORY как false, тест это нормализует. Спеку стоит поправить на `"no"`.
- 2026-09-30 · M0-12 · F-INVENTORY: сигнал «остатки/склад» ловил «остаток» из оплаты («Предоплата 50%, остаток — при готовности») и добавлял лишний вопрос про учёт остатков в брифы с предоплатой (golden bakery, gd-01). Теперь регулярка берёт только множественное «остатки/остатков/…», «склад» и «запас». Единственное «остаток/остатка» в брифах с оплатой означает недоплаченную сумму, а склад со «складом» и так ловится. Тест — taxonomy.test.ts.
