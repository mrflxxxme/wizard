# M0-13 — строитель (packages/agents/src/builder): решения

- 2026-09-30 · M0-13 · Строитель экспортируется через `@wizard/agents/builder`, общий `src/index.ts` не менялся (L2-19). Новые зависимости: `@wizard/gates` (workspace: runGates и checkFile для write_file) и `postgres` (стек; тип `db` в memory-host).
- 2026-09-30 · M0-13 · `BuildHost` структурно совместим с хостом platform-api (`apps/platform-api/src/runs/types.ts`). `route` принимает `{…RouteInput без ctx/orgPolicy/signal, step, upperBoundCredits}`, `runGates(level, {checks?})`, `needsInput(req)`. В store есть `commitFiles`, `qa: {generate, explain}`. В M0-26 останется адаптер для QaAgent и отображение `BuildOutcome.failed` в RunFailure. Строитель не бросает ошибку, а возвращает `{status: failed, code}`. RunCancelled хоста пробрасывается как есть.
- 2026-09-30 · M0-13 · Кто эмитит события. Хост: `gate_started`/`gate_result` в runGates (как platform-api), `needs_input`/`input_received`, `run_started`/`run_finished`/`run_failed` (для memory-host это делает `executeBuild`). Строитель: `step_started`/`step_finished` (plan, ops, code, verify, fix), `plan_ready`, `ops_applied` (summary_ru = humanDiff), `file_written` (после commitFiles, с revision), `agent_message` (итоговый текст фазы), `budget_update`/`budget_exceeded`.
- 2026-09-30 · M0-13 · Бюджет: upper_bound = (символы/3.2) × input + max_tokens × output по самой дорогой включённой модели цепочки callType, потому что tier выбирает роутер уже после проверки. Флаг `host.managesBudget=true` (для platform-api, где бюджет проверяется в #route по upperBoundCredits) отключает проверку, budget_* и needs_input(budget) в строителе. Без флага проверку делает строитель; «stop» → `{status: cancelled, reason: budget_stop}`.
- 2026-09-30 · M0-13 · Объяснение эскалации (≤ 400 символов) собирает код из упавших проверок или последней ошибки инструмента, отдельного вызова модели с toolChoice=none нет. Так выполняется критерий backlog «6-го LLM-вызова нет», а в RouteInput значения toolChoice=none всё равно нет.
- 2026-09-30 · M0-13 · Подсчёт ошибок подряд. +1 за каждый гейт с passed=false (run_gate или verify). Сброс, если гейт прошёл или блокирующих провалов стало меньше, чем в прошлом прогоне того же уровня. Ещё +1 за ход, где есть ошибка инструмента с тем же (code, path первой issue), что в прошлом ходе, или 3 одинаковых вызова подряд. Любой ответ, кроме rollback, сбрасывает счётчик и итерации гейтов. Повторный порог после любого ответа → failed CONSECUTIVE_ERRORS, или GATES_FAILED с последними отчётами, если исчерпаны итерации гейта. После эскалации по итерациям текущий раунд считается первым.
- 2026-09-30 · M0-13 · Исчерпание max_steps (64, в point_edit 12) → эскалация: retry даёт +8 шагов. Превышение 45 минут → failed BUDGET_STOPPED. LlmError BUDGET_EXCEEDED → BUDGET_STOPPED, прочие LlmError (включая FIXTURE_MISS) → LLM_UNAVAILABLE retryable.
- 2026-09-30 · M0-13 · PERMISSION_WIDENING (mode=create). `card.roles[].can` — свободный текст, поэтому проверки механические: set_permission для роли, которой нет в карточке, и выдача op, запрещённого AC `{type: permission, expect: deny}` той же роли и сущности, без rowFilter на этот op. ACCEPTANCE_LOCKED (create|change): каждый AC карточки должен остаться с тем же id и теми же полями check (type/role/entity/op/expect/milestone), текст менять можно. Запрет снимается только после кнопки «Упростить».
- 2026-09-30 · M0-13 · apply_ops: zod проверяет только форму (`ops[1..50]` с `op` ∈ OP_NAMES, объект loose), полную проверку делает applyOps. Ошибки уходят модели как `{ok: false, error: {code: первый OpsError.code, message, issues: [{path, code, message_ru + allowed/hint}]}, data: {errors: OpsError[]}}`. Ошибки zod → INVALID_ARGS с issues. idempotencyKey = `runId:шаг:i`, ключ модели — `runId:<ключ>`.
- 2026-09-30 · M0-13 · write_file: коды PATH_FORBIDDEN, EMPTY_FILE, FILE_TOO_LARGE (> 48 КБ), STATIC_CHECK_FAILED (checkFile из @wizard/gates, issues.path = `file:line`, code = id проверки), TARGET_ONLY (point_edit). Файл больше 400 строк даёт warning. Файлы коммитятся (commitFiles = ревизия kind=files) в конце каждого LLM-шага и перед каждым гейтом. В memory-host у ops и files общий счётчик ревизий, как draft_revision в platform-api.
- 2026-09-30 · M0-13 · Если ревизия после G0 не менялась, повторный G0 переиспользует последний отчёт. В golden run_gate G0 в последнем шаге кода и verify дают один прогон G0. run_gate G1 без G0 passed на текущей ревизии → GATE_PRECONDITION. QA.generate вызывается один раз за прогон, при провале G1 без explanations вызывается QA.explain.
- 2026-09-30 · M0-13 · mode=fix начинается с verify (G0, затем G1) без плана, ops и кода: в интерфейсе BuildHost нет чтения последних gate_reports, а новый прогон гейта даёт то же самое. mode=change идёт по фазам create (plan → ops → code → verify), но с текстом правки и без PERMISSION_WIDENING. point_edit (M3) сделан минимально: без apply_ops, write_file только в target.file, 12 шагов.
- 2026-09-30 · M0-13 · Контекст: system static (роль, фазы, ops, семантика, конвенции, оглавление ui-kit, ≈ 4k токенов, лимит 12k) + system session (сжатая карточка, дайджест спеки, дерево файлов, план). Session пересобирается только в начале фазы, поэтому префикс 1–2 внутри фазы не меняется: тест на golden-прогоне и юнит на 40 ходов (≤ 3 сдвигов). Свёрнутая история идёт одним user-сообщением с однострочниками. План живёт в session, а последний отчёт гейта и последнее сообщение пользователя дописываются в свёртку полностью. Код Chef не заимствован, только описание приёма из builder.yaml, поэтому запись в THIRD_PARTY_NOTICES не нужна.
- 2026-09-30 · M0-13 · Документация get_ui_kit_docs/get_sdk_docs и фрагменты промпта генерирует `packages/agents/scripts/gen-builder-assets.mjs` из specs (ui-kit.yaml components ≤ M0, разделы sdk.md, code_conventions, ops, forbidden_api) в `assets/builder.json`. Свежесть проверяет тест, сравнение идёт по данным: biome переформатирует JSON.
