# M1-10 — eval в CI (fixture) и ночной live в пределах бюджета F6: решения

- 2026-09-30 · M1-10 · Журнал бюджета хранится в артефакте GitHub `eval-budget-ledger` (90 дней). Каждый live-прогон скачивает последний неистёкший артефакт через `gh api` и загружает обновлённый. Закоммиченный JSON отвергнут: запись из CI потребовала бы прямого push в main, а он запрещён AGENTS.md. Кэш Actions отвергнут: его вытесняют через 7 дней без обращений и по LRU, и тогда расход месяца молча обнулился бы. Если API недоступен, шаг падает и прогон не стартует (fail-closed). Гонок нет: `concurrency: eval-live-budget` пускает прогоны по одному.
- 2026-09-30 · M1-10 · Расход месяца (UTC) = журнал ∪ live-отчёты в `tools/eval/results/` (как в `live_cadence.budget`), дубли убираются по `started_at`. Если прогон не оставил отчёта, в журнал записывается его прогноз.
- 2026-09-30 · M1-10 · Прогноз пары (бриф, модель): 150 ₽, пока в журнале меньше трёх реальных прогонов, затем 1,25 × среднее по последним десяти. Оценка по golden-фикстурам — 8–16 ₽ за пару, но usage в них — оценка символы/3.2 без системных промптов и истории, поэтому стартовое значение взято с запасом.
- 2026-09-30 · M1-10 · Acceptance «прогон не стартует сверх 30 000 ₽»: nightly стартует, если расход + прогноз ≤ 30 000 ₽. full стартует, если расход + прогноз + резерв на оставшиеся ночи месяца (5 пар × цена пары × ночи) ≤ 30 000 ₽. Иначе full красный с текстом для E-MONEY, а nightly продолжается (`live_cadence.budget`). Прогон дополнительно ограничен `--max-cost-rub`: когда расход достигает остатка, новые брифы не стартуют.
- 2026-09-30 · M1-10 · Live в CI идёт с `--gates=G0`: G1 заменяется заглушкой, которая проходит без проверок, а `g0g1_pass` не измеряется (`g1_skipped`, в отчёте «—»). Причина: G1 исполняет сгенерированные функции, а AGENTS.md и `architecture.yaml` (M0_M1) разрешают это только локально с `WIZARD_UNSAFE_LOCAL_EXEC=1`. На раннере CI в том же процессе лежат ключи провайдеров, и побег из `node:vm` дал бы к ним доступ. Регрессия ночного прогона проверяется по `g0_pass`. `--gates=G0` убирается после песочницы M2-01.
- 2026-09-30 · M1-10 · Live-отчёты не загружаются в артефакты GitHub, вопреки формулировке задачи. Причина — `eval.yaml#fixtures.rules`: «CI-артефакты… отчёты — только fixture-прогонов; артефакты live — в S3 eval в РФ». JSON и md загружаются в S3 (`EVAL_S3_*`), если он настроен, таблица — в step summary. В артефакт GitHub попадает только журнал бюджета: даты, ₽ и число пар, без вывода моделей.
- 2026-09-30 · M1-10 · Ротация ночного поднабора (`lib/rotation.mjs`) детерминирована по дню UTC. Сначала берётся бриф с канарейками, затем по одному на недостающий сегмент, остальное добирается сдвигом. Весь набор из 14 брифов проходится за 14 ночей (тест).
- 2026-09-30 · M1-10 · Baseline: `tools/eval/baseline.json` = `{v, entries: [{mode, modelId, briefSetHash, metrics, per_brief, commit, date}]}`, где mode — `harness-fixture`, `harness-live` и т. д. Хеш набора считается по содержимому брифов, так что правка брифа снимает сравнение. `per_brief` добавлен сверх спеки: иначе ночное подмножество из 5 брифов никогда не совпало бы по `briefSetHash` с baseline полного прогона. Если baseline нет, в отчёте появляется пометка, но прогон не падает. Первая запись (fixture, демо forum и bakery, 100%) сделана из fixture-прогона, live-baseline появится с первым live-отчётом.
- 2026-09-30 · M1-10 · full: модели — `vars.EVAL_FULL_MODELS` или `glm-5.3,glm-5.1` (по умолчанию T1 плюс лучшая T0 до отчёта недели 0). Метка `eval:full` срабатывает на событие `labeled` (не на каждый push), только для PR из этого репозитория: у форков нет секретов. Проверка «промпты или `models.yaml` изменены без `eval:full`» пока выдаёт предупреждение, а не ошибку: без ключей (E-ACCESS) такой PR нельзя было бы закрыть.
- 2026-09-30 · M1-10 · Статус задачи в backlog не менялся: spec-файлы вне зоны задачи (impl.md). Live-часть acceptance («ночью — 5 брифов…») заработает, когда основатель добавит секреты (docs/ops/eval.md).
