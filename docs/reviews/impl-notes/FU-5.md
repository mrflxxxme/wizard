# FU-5 — плавающий SC-AC1 = error в G1 на CI — решения

- 2026-09-30 · FU-5 · Причина не во времени и не в исполнителе функций. Ключ сида G1 случайный: sha256(systemKey + specVersion), systemKey = uniqueKey(). Примерно в 0,3% ключей UUID в `provider_payment_id` (realistic.ts) содержал цепочку цифр, которую `detect()` читает как телефон, ИНН или счёт. Сид не проходил собственный DLP: G1SetupError SEED_PII → failAll → все проверки error. В CI прогон упал на подготовке за 315 мс, а обычный прогон длится около 1,5 с. В логе Postgres в это окно ошибок нет. Serialization failures (23:24:01, 23:25:51) и `platform.deployments does not exist` (23:28:36) приходятся на другие файлы. Воспроизведено детерминированно на ключе, который даёт SEED_PII.
- 2026-09-30 · FU-5 · Исправление: (1) id платежа генерируется повторно, пока `detect()` пуст. Попытка 0 даёт прежнее значение, поэтому существующие сиды не меняются. (2) Общий инвариант в ValueGen.value: правдоподобное значение, которое сработало бы в DLP сида (`nonSyntheticPii`, общий с seedDlp), заменяется синтетическим. Генератор больше не срабатывает на собственном DLP. Классификация SEED_PII как error не менялась: она верна для настоящих ПДн в сиде.
