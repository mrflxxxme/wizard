# M2-10 — выгрузка данных системы: решения

- 2026-10-01 · M2-10 · Тело createExport — `{env, includePii?}`. Поле includePii (по умолчанию false) — явное согласие владельца на выгрузку ПДн. Без него колонки ПДн в CSV не попадают. В api.yaml тело строгое `{env}`, а поручение требует явного подтверждения ПДн, поэтому поле добавлено и его нужно внести в api.yaml. S10 (M2-11) отправляет `includePii: true` только после диалога подтверждения. Запрос `{env: prod}` из platform-screens работает, но выгружает данные без ПДн.
- 2026-10-01 · M2-10 · ПДн определяются как в draft_snapshot (M1-04): поле с pii ≠ none (file без pii считается basic), а также все поля типов email и phone. В users.csv к ПДн отнесены display_name, email, phone и telegram_id. Поля telegram_chat_id и email_bounced_at не выгружаются никогда. qr_token не выгружается никогда (connectors/qr.yaml). Не выгружается и поле, скрытое (hiddenFields) у всех ролей с read на сущность.
- 2026-10-01 · M2-10 · Журнал выгрузок — сама platform.exports: created_by, created_at, env, downloads. Признак ПДн хранится в runs.input.includePii, колонки для него в db.yaml нет. В ответ Export добавлено поле includePii (схема Export не закрыта). В deletion_log запись не пишется: у mode нет значения для выгрузки, и это журнал удалений. Аудит дополнительно дают события прогона kind=export (run_started, step dump/store, run_finished с summary_ru «…с персональными данными»).
- 2026-10-01 · M2-10 · Формат CSV: UTF-8 с BOM, разделитель «;», строки через CRLF. Ячейка берётся в кавычки, если содержит ; , " CR LF или начинается либо заканчивается пробелом; кавычки удваиваются. Заголовок — имена полей (подписи есть в spec.json). Значения берутся как `to_jsonb(col) #>> '{}'` при TimeZone=UTC: время в ISO 8601 с +00:00, bool — true/false, money/decimal — в точном виде numeric (1500.00).
- 2026-10-01 · M2-10 · Защита от формул (L3-37): апостроф ставится перед любой ячейкой, которая начинается с = + - @ TAB или CR. Это касается и телефонов E.164: «'+79161234567» — иначе Excel вычислит ячейку как формулу. Единственное исключение — значение колонки int/decimal/money вида `-?\d+(\.\d+)?`: отрицательное число не может быть формулой, а с апострофом превратилось бы в текст.
- 2026-10-01 · M2-10 · Чтение идёт в одной транзакции REPEATABLE READ READ ONLY. Первым запросом читаются prod_revision или preview_revision системы, поэтому spec.json и строки согласованы. Дальше SET LOCAL ROLE мигратора (как у draft_snapshot), wizard.role=__system, курсор по 500 строк, порядок created_at, id. Колонки, описанные спекой, но ещё отсутствующие в схеме, пропускаются. Для сущности без таблицы выгружается CSV только с заголовком. Для draft берётся preview_revision (ревизия, схема которой есть в draft), для prod — prod_revision.
- 2026-10-01 · M2-10 · Архив хранится в «хранилище артефактов» — `<artifactsDir>/exports/<id>.enc`, storage_key = `exports/<id>.enc`. Шифрование AES-256-GCM, подключ HKDF от WIZARD_SECRETS_KEY (метка exports/aes-256-gcm), AAD = exportId. Формат потоковый: MAGIC «WZE1» | iv | шифротекст | tag. ZIP (fflate, потоковый ZipDeflate) шифруется по мере записи, в памяти держится не больше одной пачки курсора. При скачивании расшифровка тоже потоковая: тег GCM проверяется в конце потока, и подмена файла обрывает ответ.
- 2026-10-01 · M2-10 · Зависимость fflate 0.8 (MIT) добавлена в platform-api: она уже в репозитории (@wizard/pii, M1-07) и умеет потоковую запись ZIP.
- 2026-10-01 · M2-10 · Ссылка на скачивание: `GET /api/v1/systems/:id/exports/:exportId/download?token=…`. Этой операции нет в api.yaml: это и есть downloadUrl из getExport, абсолютный URL от WIZARD_PLATFORM_ORIGIN. Токен — 32 байта base64url, в БД хранится sha256, срок 15 минут. Каждый getExport со status=ready выдаёт новый токен, прежняя неиспользованная ссылка перестаёт работать. Скачивание атомарно гасит токен (UPDATE … RETURNING) и увеличивает downloads. Повтор, истёкший токен или удалённый архив → 410 EXPORT_LINK_USED. Помимо токена нужна сессия владельца: чужая org → 404, editor → 403.
- 2026-10-01 · M2-10 · getExport отвечает 200 и для истёкшей выгрузки ({status: expired, downloadUrl: null}), а 410 возвращает скачивание. Статус для клиента вычисляется так: running при терминальном прогоне → failed, ready после expires_at → expired. Очистка по TTL идёт вместе с уборкой импортов (при старте и раз в час): файл удаляется, running/ready → expired, storage_key и токен обнуляются.
- 2026-10-01 · M2-10 · Ограничение: не больше 20 выгрузок на систему за 24 ч (429 RATE_LIMITED) — защита диска и БД. Неопубликованная система при env=prod и несобранная при env=draft → 409 PREVIEW_NOT_READY. Выгрузка бесплатна: прогон вставляется без резерва кредитов и не берёт блокировку системы.
- 2026-10-01 · M2-10 · Движок прогонов: в RunEngine добавлена только диспетчеризация kind=export (`#export` → runExport из src/exports/workflow.ts) и "export" в NewRun.kind. При переносе на DBOS шаги dump и store переносятся как есть: ExportHost требует только step, signal и log. Ошибка шага → run_failed EXPORT_FAILED (retryable), архив удаляется, выгрузка → failed.
- 2026-10-01 · M2-10 · Миграция названа `0006_m2_exports`. Если параллельная M2-задача тоже займёт номер 0006, одну из миграций нужно переименовать при слиянии: Kysely сортирует миграции по имени.
