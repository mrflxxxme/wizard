# M0-26 — интеграция platform-api с агентами, гейтами, сборкой и runtime: решения

- 2026-09-30 · M0-26 · Канонический контракт хоста экспортирует `@wizard/agents/host` (новый sub-path): типы BuildHost/BuildStore/HostRouteInput/InputRequest… из builder/types.ts, `hostRouteFn` (RouteFn агента → host.route без ctx/orgPolicy/signal, с upperBoundCredits и step) и `createHostQa` (QA через host.route). Поэтому кредиты QA входят в бюджет прогона, а в llm_calls qa_generate пишется с run_id сборки. platform-api (`src/runs/types.ts`) расширяет BuildHost агентов: runGates для G0–G2, store.deleteFile, run {orgId…}, `managesBudget: true`. Бюджет проверяет #route платформы.
- 2026-09-30 · M0-26 · Исполнители по умолчанию — `createAgentExecutors` (`src/agents/executors.ts`); stubExecutors остаются в экспорте. `PlatformApiOptions.executors` принимает и фабрику `({pg, config}) => RunExecutors`. У RunExecutors появился `close()`, его вызывает PlatformApi.close().
- 2026-09-30 · M0-26 · OrchSession между ходами хранится в `platform.runs.input.executorState` того хода, который её создал: в db.yaml нет колонки, а payload сообщений отдаётся UI. load_context берёт состояние последнего успешного interview_turn системы. В InterviewContext добавлены `org {id, plan, policy}` и `state`, в InterviewOutput — `state`. Триггеры: create → submitBrief; answers → answer по явным ответам, затем restByRecommendation; message → editCard (карточка), requestChange (система собрана, стадия ≠ card), подсказка без LLM (идут вопросы), иначе submitBrief. AgentError превращается в текстовый ответ, TurnFailure — в RunFailure с тем же кодом.
- 2026-09-30 · M0-26 · Исход сборки: failed → RunFailure(code, message_ru, retryable); cancelled (budget_stop/rollback) → run_finished cancelled; aborted → RunCancelled. Откат ревизии на последнюю G0-passed при rollback в M0 не делается: preview_revision и так указывает на неё.
- 2026-09-30 · M0-26 · G1 идёт против runtime внутри процесса platform-api (createRuntimeApp: MemoryRegistry, dbRole wizard_runtime, connectors outbox, `testModeSecrets()` с qr_signing_key в памяти, функции только при WIZARD_UNSAFE_LOCAL_EXEC=1). Runtime создаётся лениво, при первом G1. Хэндл запоминает loadSystem и после гейта вызывает новый `RuntimeApp.unloadSystem({slug, env})` (apps/runtime, SystemCache.unpin).
- 2026-09-30 · M0-26 · consentText (OWNER_ONLY) платформа подставляет из шаблона по `compliance.consentTemplateId` (реестр `CONSENT_TEMPLATES`: default, event_registration, orders; неизвестный id → default; тексты DRAFT до юриста, E-LEGAL). Текст собирается из operatorName/operatorContact (если их задал владелец, иначе «владелец системы»), названия системы и label полей с pii≠none. Подстановка идёт только в спеку для G1 и в spec.json артефакта превью, в ревизии она не пишется. Свой consentText владельца не трогается.
- 2026-09-30 · M0-26 · onG0Passed = migrate_draft → seed_draft → bundle_and_reload. Миграция идёт в транзакции с `SET LOCAL ROLE wizard_owner` (не суперпользователь, не владелец platform; тест проверяет has_schema_privilege и владельца app_<key>_draft). Схема пересоздаётся (DROP … CASCADE + план с нуля), если её нет, если нет preview_revision, если в плане есть ошибки или DDL упал. Seed (generateSeed(spec, sha256(schema_key)) и dev-<role>@dev.localhost для каждой login-роли, как в devUser runtime) пишется только при создании схемы, от wizard_owner с wizard.role=__system.
- 2026-09-30 · M0-26 · spec_hash: представление deployments считает sha256(revisions.spec::text), а packages/build — sha256 канонического JSON. Колонку добавить нельзя (миграции сверяются с db.yaml), поэтому manifest.specHash артефакта превью = spec_hash ревизии из представления. Иначе runtime отвергает артефакт (manifest mismatch → 503). Пока спека не хранит хеш явно, это единственный источник хеша для draft.
- 2026-09-30 · M0-26 · Реестр runtime: `DbRegistry(sql, fallback?)` в apps/runtime читает platform.deployments на каждом resolve. Новая preview_revision подхватывается следующим запросом (runtime.yaml допускает опрос реестра), POST /_wizard/internal/reload в M0 не нужен. `pnpm dev` runtime использует DbRegistry с запасным FileRegistry(registry.json). Если схемы platform нет, берётся запасной реестр.
- 2026-09-30 · M0-26 · GET /_wizard/health на хосте системы отдаёт {status, system (slug), env, revision} (runtime.yaml#service_endpoints.health). На голом хосте ответ по-прежнему {status: ok}.
- 2026-09-30 · M0-26 · Локальная org из seed получает region_code '77' (Москва). Иначе policy t1Restricted = (region_code is null) отправляет все вызовы на T0, а метка S1/S3 — «модели в РФ» (M0-30). Существующие БД не меняются (seed делает ON CONFLICT DO NOTHING). Регион можно сбросить в NULL, тогда вернётся fail-safe T0.
- 2026-09-30 · M0-26 · РАСХОЖДЕНИЕ ФИКСТУРЫ (не исправлено, чужая зона M0-22/M0-12): интервью demo/bakery.jsonl записано для развилок F-LOGIN, F-STAFF, F-VISIBILITY, F-STATUSES, а текущий selectForks оркестратора выбирает F-STAFF, F-LOGIN, F-STATUSES, F-APPROVAL, F-INVENTORY. ask_questions из записи не проходит проверку, повтор даёт FIXTURE_MISS, интервью падает с LLM_UNAVAILABLE. Поэтому в тесте кондитерской интервью воспроизводится из записи: вопросы golden/bakery.yaml, карточка = submit_card из фикстуры + estimateCard. Сборка идёт настоящими агентами по фикстуре: G0 и G1 passed, run succeeded. Нужно перезаписать интервью фикстуры или выровнять таксономию.
- 2026-09-30 · M0-26 · Тестовые БД (createTestDb {migrator: true}) создают роли wizard_owner/wizard_runtime, если их нет (как scripts/db.mjs), и дают wizard_owner CREATE на БД. Новых внешних зависимостей нет: у platform-api добавились только workspace-пакеты @wizard/agents, gates, build, runtime (architecture.yaml#monorepo.apps.platform-api.depends_on).
- 2026-09-30 · M0-26 · В режиме fixture без WIZARD_FIXTURE router бросает ошибку конфигурации, и прогон `pnpm dev` падает с INTERNAL. Для локального демо нужен WIZARD_FIXTURE=demo/forum (роутер создаётся на прогон, поэтому порядковые номера demo-строк начинаются заново в каждом прогоне).
