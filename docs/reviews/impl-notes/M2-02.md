# M2-02 — решения реализации

- 2026-10-01 · M2-02 · Транспорт ЮKassa: реальные вызовы API только при WIZARD_CONNECTORS=live (`PlatformConnectorConfig.yookassa.live`, в runtime — из `RuntimeAppOptions.connectors`). Draft без ключей магазина (SECRET_MISSING) и любой draft при outbox остаётся на mock-оплате M0; prod без live → EGRESS_DISABLED. `/_wizard/pay-mock` подтверждает только платежи `mock_*`: реальный платёж ЮKassa страницей-заглушкой не подтвердить.
- 2026-10-01 · M2-02 · Переменные окружения сверх deploy.yaml: WIZARD_YOOKASSA_API_BASE (заглушки, по умолчанию https://api.yookassa.ru/v3) и WIZARD_YOOKASSA_IP_ALLOWLIST (CIDR через запятую, по умолчанию список из yookassa.yaml). WIZARD_TRUSTED_PROXIES (deploy.yaml M2) реализован в runtime: `RuntimeEnv.trustedProxies`, server.ts берёт правый недоверенный хоп X-Forwarded-For только от доверенного пира (`effectiveClientIp`) — это действует и на лимиты по IP.
- 2026-10-01 · M2-02 · Idempotence-Key = sha256(ключ) в форме UUID v4. create_payment: `pay:<system>:<env>:<integration>:<binding>:<recordId>:<attempt>:<копейки>`, attempt = число платежей привязки по записи — двойной клик даёт тот же платёж ЮKassa, вторая вставка в журнал (UniqueViolation) возвращает ту же ссылку. Возврат — `refund:<system>:<idempotencyKey действия>`, закрывающий чек — `receipt:<system>:<id финального платежа>`, отмена — `cancel:<system>:<id>`. Ответ 500/сеть повторяется с тем же ключом (3 попытки) в /api/pay и вебхуке; в действиях — через invokeAction.
- 2026-10-01 · M2-02 · Вебхук: IP источника вне allowlist или неизвестен → 401 (до чтения тела) → неверный hookToken → 404 → тело > 256 КиБ → 413 → GET объекта. Решение — по статусу из ответа API, а не по имени события; pending → 200 без отметки об обработке (повторная доставка применится). Ключ идемпотентности `hook:<event>:<object.id>` в ctx.store на 7 дней; объект не найден у магазина или metadata чужой системы → 200 и игнор; сбой API → 500. При WIZARD_CONNECTORS≠live вебхук → 404.
- 2026-10-01 · M2-02 · hookToken = HMAC(yookassa_secret_key, "yookassa-hook:<integration>")[:32] без хранения: при смене ключа меняется URL. `yookassaWebhookUrl(ctx)` экспортирован; показ URL в настройках интеграции (platform-web/platform-api) не подключён.
- 2026-10-01 · M2-02 · /api/pay: доступ проверяется чтением записи правами вызывающего, а статус, сумма и контакты для чека берутся из системной копии записи (ctx.db) — скрытое для роли поле суммы не ломает оплату. return_url — абсолютный (`<схема>://<Host>` + returnRoute).
- 2026-10-01 · M2-02 · needs_review: «событие владельцу» — сообщение outbox `owner_event` {event: payment_needs_review, message_ru: «Оплата требует проверки»}; механизма доставки событий владельцу в платформе пока нет — нужен отдельно.
- 2026-10-01 · M2-02 · Возвраты: окно refundWindowDays от captured_at платежа (нет — от времени обработки уведомления); остаток = оплачено − возвраты этого платежа в статусах pending/succeeded; строка журнала {kind: refund} с id возврата ЮKassa; полный возврат → refundedStatus. Mock-возврат в draft теперь сразу succeeded (журнал + outbox + refundedStatus) вместо pending в outbox.
- 2026-10-01 · M2-02 · getPaymentStatus: needs_review отдаётся как "pending" (в enum SDK нет needs_review); для pending-платежа в live статус берётся GET-запросом (может быть waiting_for_capture). waiting_for_capture в вебхуке → POST /payments/{id}/cancel.
- 2026-10-01 · M2-02 · Чек 54-ФЗ: телефон — только цифры, quantity "1"; нет ни email, ни телефона в записи → INVALID_REQUEST (422). Закрывающий чек: payment_id предоплаты, позиция с описанием/НДС/предметом привязки предоплаты, payment_mode full_payment, settlements prepayment на сумму предоплаты; один раз на финальный платёж (флаг в ctx.store), создаётся и при повторной доставке, если первый раз упал.
- 2026-10-01 · M2-02 · Ключи: в test-режиме (draft или prod с testMode) ключ обязан начинаться с test_ (CONFIG_INVALID «Для черновика нужен тестовый магазин»), в live тестовый ключ отклоняется. Баннер «Тестовые платежи» в системе не сделан (UI).
