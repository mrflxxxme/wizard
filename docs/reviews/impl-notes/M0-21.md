# M0-21 — золотые фикстуры demo/forum: решения и контракт формата

## Решения

- 2026-09-30 · M0-21 · specToOps и генератор — чистый JS без зависимостей (`tools/fixtures/lib/*.mjs`), чтобы `node tools/fixtures/gen-golden.mjs` работал на голом Node 22; YAML читается через python3 + PyYAML, как в `tools/specs/validate.mjs`. Эквивалентность с `applyOps` проверяют тесты vitest.
- 2026-09-30 · M0-21 · В `vitest.config.ts` добавлен include `tools/*/test/**/*.test.ts`. biome `files.includes` не трогал: tools/ линтом не покрыт, файлы отформатированы тем же конфигом с расширенным include.
- 2026-09-30 · M0-21 · Порядок ops в specToOps: set_app → set_theme → роли → сущности → права → воркфлоу → интеграции → функции → страницы → aiActions → set_acceptance → set_compliance. Это порядок builder.yaml. Сущности отсортированы так, чтобы цель ref шла раньше, поэтому любой разрез на батчи ≤ 50 валиден. Батчи режутся жадно, каждый проверен через applyOps.
- 2026-09-30 · M0-21 · `app.template` и `app.locale` операциями не задаются (set_app = {name, description, timezone}). Эквивалентность «specToOps + applyOps на emptySpec» проверяется от `emptySpec(name)` с `app.template` из исходной спеки: шаблон ставит платформа при создании системы.
- 2026-09-30 · M0-21 · Golden-сборка стартует с `emptySpec(app.name)` версии 0, `expectedVersion` батча i = i. Если M0-13 создаёт стартовую спеку «app + роль admin» (builder.yaml#inputs.spec), фикстуру придётся перегенерировать с другим стартом.
- 2026-09-30 · M0-21 · Спека, которую собирает строитель в golden, — это forum.json с тремя отличиями. (1) Поля владельца в compliance отброшены (OWNER_ONLY_FIELD). (2) Почта переведена на `provider: platform`: адрес и SMTP строитель знать не может. (3) acceptance взят из карточки 1:1, без steps/actors: их генерирует QA. Патч лежит в `golden/forum.yaml#build.spec_patch`.
- 2026-09-30 · M0-21 · В карточку добавлен AC8 (модератор может менять заявку спикера, type=permission). Без него forum.json не проходит правило S5_card «≥ 1 AC на каждую роль с входом»: у moderator нет ни одного AC. Роль AC определяется полем `check.role`, для scenario/constraint тоже.
- 2026-09-30 · M0-21 · Правило «pii.detect = 0» выполнено для всего, кроме синтетических email `user<N>@example.test`: без email сценарии QA невозможны, потому что `registerTicket.holderEmail` и `speaker_application.email` обязательны. Эти адреса вынесены в `tools/eval/pii-allowlist.txt` (security/compliance.yaml#tests). Имена «Анна Тестова» и т. п. заменены на «Участник N»: их детектор не находит.
- 2026-09-30 · M0-21 · QA генерирует сценарии только для AC type=scenario|constraint с milestone ≤ M0: в forum это AC1–AC4. AC5 (M2) и AC6 (M1) получат skip, AC7 и AC8 (permission) обрабатываются без LLM. Шаги берутся из forum.json, значения синтезируются правилами `golden/forum.yaml#qa.replace`.
- 2026-09-30 · M0-21 · Фаза строителя (ops, code) завершается ответом модели без tool calls (`finishReason: stop`), поэтому последняя строка каждой фазы текстовая. В последнем шаге с записью файлов есть `run_gate {level: G0}` (builder.yaml: SHOULD после ≤ 6 файлов). Промежуточных run_gate нет, чтобы G0 не падал на незаписанных экранах.

## Контракт файла фикстуры (для M0-06 packages/llm и M0-13/M0-14)

Файл `tools/fixtures/<suite>/<name>.jsonl`, одна JSON-строка на вызов LLM, ключи в таком порядке (eval.yaml#fixtures.line):

```
{v: 1, key, callType, modelId,
 request: {messages: {role, content: string}[], tools: {name, schemaHash}[], params: {temperature, max_tokens}},
 response: {text?, toolCalls: {id, name, args: object}[], finishReason: "tool-calls" | "stop"},
 usage: {promptTokens, cachedPromptTokens, completionTokens}, latencyMs, recordedAt}
```

- `args` хранится объектом, не строкой JSON. `id` детерминирован: `call_<callType>_<n>_<i>`.
- `finishReason` принимает значение `tool-calls`, если есть toolCalls, иначе `stop` (как в AI SDK).
- suite=demo, поиск: по (callType, n), где n — порядковый номер строки этого callType в файле и номер вызова этого callType в прогоне (с 1). Из request сверяются только имена инструментов. Рекомендуемая проверка в M0-06: каждый `response.toolCalls[].name` ∈ имён инструментов, которые харнесс реально предложил; иначе FIXTURE_MISS. Точное равенство наборов не требуется.
- Наборы инструментов в golden (`tools/fixtures/lib/golden.mjs#TOOLSETS`):
  - interview №1 — `[submit_analysis]`;
  - interview №2 — `[ask_questions]`;
  - card — `[submit_card]`;
  - plan — `[submit_plan]`;
  - build_ops/build_code/fix — все 8 инструментов builder.yaml#tools в порядке файла;
  - qa_generate — `[submit_checks]`.
- В golden `schemaHash` равен `"golden"`: в demo он не сверяется. При record это sha256 JSON Schema инструмента (z.toJSONSchema).
- `modelId` берётся из `routes[callType].chain.T1[0]` (glm-5.3). В demo роутер выбирает модель как в live, `modelId` из фикстуры не сверяется.
- `usage` оценивается как символы/3.2: prompt считается по `JSON.stringify(request)`, completion — по `JSON.stringify(response)`, `cachedPromptTokens` = 0.
- `latencyMs` — детерминированная оценка (400 + completion×10). Провайдер не обязан ждать это время.
- `recordedAt` — фиксированная дата из golden yaml.
- `key` = sha256(hex) канонической строки. Реализация — `tools/fixtures/lib/format.mjs#canonicalRequest`, M0-06 должен дать байт-в-байт тот же результат:
  1. Объект `{callType, modelId, messages, tools: [{name, schemaHash}], temperature: params.temperature, max_tokens: params.max_tokens}`.
  2. Во всех строках messages срезаются пробелы и табы в конце строк (`/[ \t]+$/gm`). Точные вхождения `ctx.runId` и `ctx.systemId` заменяются на `<runId>` и `<systemId>`.
  3. Объект сериализуется в JSON: ключи отсортированы рекурсивно, массивы сохраняют порядок, `undefined` опускается.
  4. По сериализованной строке UUID (без учёта регистра) заменяются на `<uuid:N>` в порядке первого появления, затем ISO-даты и дата-время заменяются на `<date>`.

Golden-сценарий: `tools/fixtures/golden/<name>.yaml`. Структура из спеки выводится автоматически: сущности Analysis, роли, данные, экраны, интеграции, автоматизации и ПДн карточки, ops, код и сценарии QA. В yaml остаются смысловые тексты, `brief` и `answers`, по ним e2e кликает кнопки. Проверка актуальности: `node tools/fixtures/gen-golden.mjs forum --check`.
