- 2026-10-01 · M2-04 · Нормализация: нижний регистр, ё→е, удаление невидимых символов. Гомоглифы сводятся к одному алфавиту только внутри слов со смешанной письменностью (по большинству не-гомоглифов), иначе «отр» превращалось бы в «otp», и ложные находки шли бы между алфавитами. Бренды сравниваются по «скелету» (кириллические гомоглифы → латиница) со склейкой соседних токенов (Сбер-Банк = СберБанк). Для slug дополнительно используется транслитерация (gosuslugi = Госуслуги). В rx() `\b`, `\w`, `\W` заменены на Unicode-аналоги, и каждое совпадение начинается с начала слова (стемы abuse.yaml#word_boundary).

- 2026-10-01 · M2-04 · G2-PERM-01 — все PC-op из generatePermissionChecks (роль × сущность × op) через Prober G1. G2-PERM-02 — те же тройки в SQL: SET LOCAL ROLE <runtimeRole> + set_config(wizard.role/user_id/user_attrs, true), всегда ROLLBACK. Чтение — count по id. Вставка — 42501 = deny, другие 23xxx = allow (ограничение срабатывает после RLS). UPDATE/DELETE с WHERE id, если у роли есть read; иначе без WHERE, потому что Postgres для WHERE требует SELECT-политику. Затронуто > 0 строк или 23503 = allow. Мигратор должен иметь право SET ROLE на роль runtime. Если права нет, проверка даёт error.
- 2026-10-01 · M2-04 · G2-PERM-03/04 дополнительно вызывают публичные query (минимальные args по валидаторам, id сущности = проверяемая строка) от A для каждой роли из function.roles. Строка B под rowFilter: утечка — это её отличимое значение (строка ≥ 6, не ref/enum/дата), которого не было в ответе до вставки. Сравнение «до/после» защищает от совпадений словарных синтетических значений. Скрытые поля проверяются так же. ПДн seed, невидимые роли (с исключением значений, видимых ей в своих строках), не должны появляться в ответе. Это вторая линия проверки к стрипу в runtime. Публичные mutation/action не вызываются (побочные эффекты).
