# Грилл-5: срез MVP до выпуска (05.10.2026)

Основа: [грилл-4](grill-4.md), [план полнофункционального пилота](../plans/2026-10-04-full-pilot.md), [аудит готовности](2026-10-04-pilot-gap-audit.md), [ревизия ограничений](2026-10-04-restrictions-review.md), состояние сервера пилота на 05.10.2026 (выкат PR #47 и #48).

**Зачем понадобился грилл.** План M2P — 81 задача, около 148 агенто-дней, принцип «всё до первых клиентов» (D41). Основатель поставил приоритет ценности: рабочая система на сервере как можно скорее, с ключевыми функциями клиента и администратора. Грилл определил, что делаем до выпуска, а что накатываем волнами после.

**Состояние на начало грилла.** Сервер работает (borntobuild.ru по HTTPS, ключи Cloud.ru и Z.ai приняты, почта и алерты работают). Путь клиента есть целиком: приглашение → бриф → интервью → карточка → сборка с проверками → публикация после ревью → правки. Но живые модели ни разу не собирали систему, промпты заточены на золотые сценарии, владелец не узнаёт о заявке анонимного посетителя, на страницах нет картинок и блоков лендинга, в кабинете кредиты и жаргон, связи с командой нет.

## Решения о срезе

| # | Вопрос | Решение основателя |
|---|---|---|
| 1 | Какие классы систем к выпуску | **Три без платежей**: сайт с заявками, запись с напоминаниями, CRM и внутренние инструменты. Подписка и платный доступ — первой волной после выпуска. **Сборка остаётся универсальной**: классы — рецепты качества (эталоны, сценарии QA), а не ограничитель. Любой бриф идёт по общему конвейеру с архитектурными правилами и проверками; запрос сверх возможностей получает честный ответ и замену, а не отказ «класс не поддерживается» |
| 2 | Порог качества перед выпуском | **10 брифов на сервере** через настоящий конвейер: по 2–3 на класс и 2 вне классов. Порог 7 из 10 доходят до готовности к публикации по автоматическим проверкам, бюджет моделей до 2 000 ₽ в месячном лимите платформы. Дефекты чинятся, повторяются только провалившиеся брифы, затем проход основателя |
| 3 | Человеческий слой | **Одна кнопка «Написать команде»** на экранах кабинета с отметкой «Хочу, чтобы доделала команда». Сообщение со ссылкой на систему и почтой клиента уходит основателю в Telegram через бота платформы, копия — в /admin; ответ письмом. Чат с перепиской, очередь «под ключ» и таймер срока — после выпуска |
| 4 | Профессиональный вид | **Блоки лендинга + картинки + темы**: первый экран, преимущества, шаги, вопросы, форма заявки, подвал; картинки на странице (загружает владелец); 4 темы с фирменным цветом и шрифтами с кириллицей, тему агент подбирает под нишу. Дизайн-агент, стоки, видео и карты — после выпуска |
| 5 | Уведомления | **Владелец и сотрудники с ролью** получают письмо и Telegram о новой заявке или записи. **Посетитель без аккаунта** с его согласия получает служебные письма: подтверждение, напоминание за 24 часа, ссылку отмены. SMS — после выпуска (нужен договор с агрегатором) |
| 6 | Цена на пилоте | **«На пилоте бесплатно»**: кредиты скрыты и остаются внутренним лимитом. Клиент видит остаток словами («ещё 2 сборки»); при исчерпании — «Написать команде», основатель поднимает лимит из /admin. Рублёвый каталог — к включению оплаты |
| 7 | Внешние интеграции | **Исходящий HTTP и входящие вебхуки**: запросы функций систем по объявленным в спеке хостам через egress-прокси с журналом, список виден на ревью; вебхуки — на секретный адрес с проверкой подписи или общего секрета. Готовые коннекторы (amoCRM, Битрикс24, Tilda и др.) — после выпуска по спросу |
| 1а | Запросы сверх возможностей | **Раздел «Запросы на развитие»** (прежнее имя «Ограничения») — в срезе выпуска: агент честно говорит, чего платформа пока не умеет, предлагает замену и записывает запрос; в /admin — раздел с группировкой по категории и частоте и переходом к клиенту |
| 8 | Как исполняем | **Влить PR #49** (исправления репетиции и план M2P) и оформить **срез выпуска MVP** внутри M2P: у задач, которые идут до выпуска, урезанный объём `mvp_scope`; остальное M2P — после выпуска. Одна сессия работает пакетами PR без PR захвата, параллельно с сабагентами, независимое ревью делает сабагент; мерж при зелёном CI |

## Финальный раунд: ограничения к выпуску

| # | Ограничение | Решение |
|---|---|---|
| О1 | Модель по умолчанию | Лучшая (Z.ai) и при неизвестном регионе (D26); при недоступности — цепочка Cloud.ru. В силе |
| О2 | Месячный лимит платформы на модели | 6 000 ₽ с оповещениями на 80% и 100%; замер — до 2 000 ₽ внутри. В силе |
| О3 | Лимит на приглашённого клиента | **5 сборок и 20 правок за 30 дней** (вместо 3 черновиков и 10 правок D58); основатель поднимает из /admin |
| О4 | Ревью первой публикации системы основателем | Оставить |
| О5 | Только приглашения, без регистрации и лендинга | В силе (D32) |
| О6 | Письмо владельцу о заявке | **Данные заявки в теле письма** (имя, телефон, суть); в теме ПДн нет. Владелец — оператор этих данных, почта идёт через сервер в РФ. Ослабляет п. 64 ревизии для получателей-сотрудников системы |
| О7 | Telegram владельцу | На выпуске без ПДн: «Новая заявка — откройте по ссылке». Имя по флажку (D53) — после уведомления РКН юристом |
| О8 | Исходящие запросы систем | **Любой публичный хост, объявленный в спеке**; внутренние сети запрещены, лимиты размера, времени и числа запросов, журнал; список хостов на ревью основателя; секреты только `secret://` |
| О9 | Входящие вебхуки | Секретный адрес, подпись или общий секрет, защита от повтора. Оставить |
| О10 | Удаление полей и сущностей в работающей системе | **Разрешено к выпуску**: клиент правит систему и в сторону добавления, и в сторону удаления. Перед применением — предупреждение словами («Удаление поля „Телефон“ затронет 112 записей»), подтверждение владельца; данные уходят в архив, а не уничтожаются, поэтому правку можно откатить (D56 к выпуску) |
| О11 | Спецкатегории ПДн и документы в формах | Блокируются; запись в клинику — без медданных (D51). Шифрование полей (D52) — после выпуска |
| О12 | Чужие скрипты на страницах систем (Метрика, видео, карты, капча) | Нет на выпуске; компоненты D38/D57 — после |
| О13 | CSS строителя | Нет; вид задают токены, темы и блоки ui-kit |
| О14 | Адрес и язык систем | Только `имя.sandpile.ru`, русский. В силе |
| О15 | Юридические тексты | Пилот на черновиках закрытого тестирования (D25), только приглашённые; у систем клиентов реквизиты оператора и согласие задаёт владелец (G2-PII-06) |
