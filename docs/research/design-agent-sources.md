# Дизайн-агент: знания, атрибуция и проект (04–05.10.2026, ред. 3)

Третья редакция, по решениям основателя от 04–05.10.2026 (D45–D49 в `specs/product.yaml`):

- знания берутся из всех локальных дизайн-скиллов целиком;
- источники под MIT и Apache-2.0 можно использовать дословно, с атрибуцией в NOTICE (раздел 1);
- серые зоны решены (раздел 2), открытыми остались только пункты с пометкой [?];
- vision-модели разрешены на T1, но изображение с ПДн к T1 не уходит: сначала маскирование на нашем сервере;
- референсы снимаются свободно, от платформы требуется только инфобезопасность;
- шрифты — любые с лицензией на бесплатное коммерческое использование и веб-встраивание, лицензия записывается по каждому шрифту; коммерческие гарнитуры с сайтов «бесплатного скачивания» не используются;
- стоки — Pexels и Pixabay, только со своего хранилища; Unsplash исключён.

Подробные каталоги — шрифты, полный анти-слоп с порогами, рубрика критика, блоки по классам, ниши, шкалы и палитры, UX-правила, правила письма — лежат в [design-agent-catalog.md](design-agent-catalog.md).

## Сводка

- **Как знания попадают в продукт.** Агенты Wizard работают на моделях через OpenAI-совместимый API, Claude Code на этом пути нет. Знания из скиллов становятся тремя слоями: промпты агента (раздел 3), справочные данные (раздел 6, каталог) и детерминированные проверки. В каталоге ~90 проверок с id и порогами, большая часть взята из реестра детектора `impeccable` и pre-flight `taste-skill`.
- **Направления.** Три направления строятся на теме v2 (раздел 4): пресет, пара шрифтов, стратегия цвета, шкала, форма, плотность, глубина, движение, варианты блоков. Все значения — enum или hex, вольного CSS нет. Различие направлений обеспечивают seed-сэмплер и проверка расстояния кодом. Vision-критик отвечает за вкус.
- **Шрифты.** В Google Fonts 227 кириллических семейств без CJK и брендовых; список снят 04.10.2026. В ядро каталога отобрано 40, подобрано 22 пары по нишам. В Fontshare кириллицы нет ни у одного семейства, у Velvetyne и Collletttivo она единичная. Список основателя «не для заголовков» расширен. Текущий enum `theme.font` превращается в текстовую роль.
- **Модели.** Кандидаты по приоритету:
  - T1: Z.ai `glm-5.3-flash`, `glm-4.6v`, `glm-4.6v-flashx`;
  - T0 («Только РФ»): Cloud.ru `Kimi-K2.6` и `Qwen3.6-35B-A3B`.
  Точные id, формат картинки и учёт токенов подтверждает дымовой тест в M2-28. Текст — `glm-5.3`. Оценка — около 25–35 ₽ на систему (5–7 кредитов) на T1 и 90–130 ₽ на T0.
- **Изображения с ПДн.** Перед T1 картинка проходит OCR на нашем сервере: имена, телефоны и email маскируются, лица размываются. Это новая задача платформы.
- **Компоненты платформы.** Карты в блоке контактов — Яндекс Карты, защита форм — Yandex SmartCaptcha.
- **Текст.** И сайт клиента, и сама платформа пишут по русской адаптации `humanizer`, без выдумки. Допущения видимо помечаются, публикация с ними блокируется.

## 3. Дистиллят для промптов агента

Здесь — правила, которые идут в системный промпт (≈ 10–12 тыс. токенов, кэшируется). Таблицы с порогами — в каталоге.

### 3.1 Режимы поверхности и классы систем

Режим задаёт, чем можно жертвовать. «Убеждает» допускает смелую типографику и цвет, но оффер и действие должны быть понятны за секунды. «Работает» ничем не заслоняет задачу, состояние и привычные элементы. «Читает» бережёт понимание и навигацию.

| Класс системы | Режим | Плотность | Цвет | Движение |
|---|---|---|---|---|
| Сайт с заявками | убеждает | airy/regular | любая стратегия | calm/lively |
| Запись | убеждает, в кабинете — работает | regular | restrained/committed | calm, в кабинете still |
| Подписка, платный доступ | убеждает, затем читает | regular | по теме | calm |
| CRM, внутренний инструмент | работает | compact | restrained | still |

Класс определяет код по AppSpec: публичная форма заявки → «заявки»; сущность-слот или календарь → «запись»; рекуррентный платёж → «подписка»; нет публичных страниц → «инструмент». Классы смешиваются по страницам. Блоки и порядок секций по классам — в каталоге D.

### 3.2 Рецепт трёх разных направлений

1. **Прочтение брифа одной строкой.** «Читаю как: <тип страницы> для <аудитории>, язык <…>, опора <семейство тем>».
2. **Колея.** Назвать, что в нише делают все (из `niche-map`, каталог D3), её очевидную противоположность и три «ИИ-вида»:
   - кремовый фон + контрастная антиква + терракота;
   - почти чёрный + один кислотный или вермильоновый акцент;
   - газетные волосяные линии с нулевыми радиусами.
   Добавить рунетские штампы: Montserrat с градиентом, «три карточки с иконками» как в шаблонах конструкторов, стоковая «команда». Всё это исключается из кандидатов.
3. **Мир клиента.** Семь предметов и визуальных систем, которые аудитория знает наизусть: упаковка, вывеска, бланк, униформа, инструмент, печать ниши, навигация места, медиа ниши. Хотя бы из трёх «семейств материала»: если больше трёх из одного, копать дальше.
4. **Кандидатов выбирает код.** Seed = hash(systemId, номер попытки), сэмплер выдаёт 6–8 векторов темы из пространства, допустимого для класса. Модель выбирает три, сопоставляет каждый с предметом из мира клиента и обосновывает. «Первое пришедшее в голову» исключено по построению.
5. **Расстояние проверяет код.** Любая пара направлений различается минимум по 3 из 6 осей: класс пары шрифтов, стратегия цвета, режим (светлый, тёмный, цветной), форма (радиус и кнопки), композиция hero, плотность. Сначала фильтр пригодности по брифу, потом максимизация расстояния.
6. **Контракт направления — до 150 слов, пять блоков:**
   - **Тезис** — одна идея и какой дефолт категории она отвергает;
   - **Свой мир** — палитра и язык блоков, узнаваемые без текста;
   - **История** — что посетитель понимает, во что верит, что делает;
   - **Первый экран** — что где, в каком масштабе, где CTA;
   - **Сигнатура и риск** — один запоминающийся элемент и честный риск.
   Блок, который читается как настроение («премиально, современно»), значит, что направление не решено.
7. **Светлое или тёмное** выбирается одной фразой о сцене (кто, где, при каком свете), не по категории.
8. **Первый экран:**
   - ≤ 4 текстовых элемента; заголовок ≤ 2 строк на десктопе и ≤ 3 на 390;
   - подзаголовок ≤ 20 слов; одна основная CTA и не больше одной второстепенной; CTA видна на 390×844;
   - eyebrow по умолчанию нет;
   - визуал — фото клиента или типографский плакат, не «градиентное пятно».
9. **Самопроверка:** «можно ли угадать эстетику по названию ниши? по нише плюс избеганию?» и «сработает ли с логотипом конкурента?». Если да — переделать ту часть, а не смягчить её.
10. **Показ:**
    - три карточки равного веса, без ранжирования; тихий четвёртый выход «Классика ниши» без рекомендации — если выбран, исполняем на полном качестве;
    - «Ещё варианты» исключает показанные; после двух повторов — вопрос выбором «чего не хватает: строже, теплее, ярче, спокойнее»;
    - каждый выбор переводится в конкретные изменения токенов (каталог E).

### 3.3 Анти-слоп: главное

Полный каталог (~90 правил с id, порогами и заменами) — в каталоге B. Ядро для промпта:

- **Каркас:**
  - нет трёх одинаковых карточек «иконка + заголовок + текст»;
  - нет иконки в плашке над заголовком и карточки в карточке;
  - eyebrow-подписей ≤ ⌈секций/3⌉, нумерация только у реальных шагов;
  - на 8 секций — минимум 4 разных раскладки, ≤ 2 зигзага «фото/текст» подряд;
  - bento: N элементов = N ячеек.
- **Цвет:**
  - нет фиолетового 260–310° в заголовках и градиентах, нет циан-градиентов и неона на тёмном;
  - нет кремового фона по умолчанию, градиентного текста, свечения;
  - акцентных заливок ≤ 2 в первом экране, оттенок акцента один (кроме `duo`);
  - нет серого на цветном и `#000`.
- **Типографика:**
  - display не из списка «не для заголовков»;
  - h1/основной ≥ 2,5 на лендинге;
  - h1 ≥ 72 px только при < 40 знаках;
  - трекинг не туже −0,02 em, интерлиньяж основного текста 1,5–1,6, строка 45–75 знаков;
  - без курсивной антиквы в hero.
- **Движение:**
  - нет одинакового fade-up у всех секций, нет пружинящих кривых;
  - UI-анимации ≤ 300 мс;
  - нет бегущих строк, автокаруселей, счётчиков, пульсирующих точек, зума картинок на hover;
  - контент виден без JS и при reduced-motion.
- **Изображения:** нет фейковых скриншотов, 3D-шаров и изометрии, стоковых или сгенерированных людей, текста на фото без скрима.
  - Источники фото: загрузка клиента, затем Pexels и Pixabay (скачиваем к себе, автор в метаданных).
  - Хотлинков на зарубежные CDN нет; Unsplash и picsum (которые советует `taste-skill`) не используем.
- **Текст:** стоп-лист, превосходные степени без доказательства, выдуманные данные, «Подробнее» ×N (каталог H).

### 3.4 Русская типографика

- **Набор шрифтов.** Только кириллические, из каталога A4; живая проверка «д з к ъ я ж щ ф й ё», курсива и цифр. Не больше двух семейств плюс моноширинный для чисел. `font-synthesis: none`.
- **«Не для заголовков».** Inter (+Tight), Roboto (+Condensed, Flex), Open Sans, Montserrat, Manrope, Nunito (+Sans), Raleway, Rubik, PT Sans, Golos Text, Oswald, Comfortaa, Lobster, Russo One, Exo 2, Poiret One, Yeseva One. Шрифты без кириллицы уходят в фолбэк, поэтому тоже запрещены: Lato, Poppins, DM Sans, Space Grotesk, Plus Jakarta, Outfit, Fraunces, Instrument.
- **«С обоснованием».** Playfair, Cormorant, Lora, Merriweather, EB Garamond, Source Serif 4, IBM Plex, Geist, Unbounded.
- **Пара.** Контраст по конструкции: антиква и гротеск, широкий и обычный, узкий и обычный. Одно семейство допустимо, если вес отличается минимум на 2 ступени и шкала держит отношение ≥ 2,5.
- **Размеры:** основной 16–18 px; мелкий ≥ 13 (нигде < 12, функциональный < 11 нельзя); шкала по пресету (каталог E1). Трекинг: ≥ 40 px −0,02 em, 24–40 px −0,01, основной 0, короткий капс +0,04…0,06. Интерлиньяж: display 1,08–1,12, основной 1,5–1,6.
- **Капслок** — до 4 слов, раз на экран. Курсив кириллицы — только настоящий.
- **Типограф на сервере, до рендера:**
  - кавычки «ёлочки», внутри „лапки“;
  - тире «—» с неразрывным пробелом перед ним; диапазоны «10–12», «9:00–18:00» без пробелов; минус «−»;
  - неразрывный пробел после слов из 1–2 букв (в, к, с, о, у, и, а, но, на, по, за, от, до, из, не, ни), перед «же, ли, бы», в «5 000 ₽», «30 мин», «№ 5», «т. е.», «и т. д.», «А. С. Пушкин»;
  - «ё» единообразно.
  Грамматическое тире остаётся: запрет em-dash из `taste-skill` к русскому не применяем. Ловим только насыщение (≥ 8 тире при плотности ≥ 1 на 500 знаков).
- **Переносы.** Основной текст на мобиле — `hyphens: auto` при `lang="ru"`. Заголовки — `text-wrap: balance`, висячие предлоги снимает типограф.
- **Длины.** Русский текст в среднем на четверть длиннее английского. Заголовок в 12 слов на 360 px — это 5–6 строк, поэтому ограничение вида «≤ 3 строк» проверяет код.
- **Числа.** Через Intl ru-RU (ui-kit): «9 900 ₽», «12 марта», «+7 912 345-67-89». В ценах и таблицах `tabular-nums`.

### 3.5 Цвет и контраст

- **Пороги WCAG 2.x** (формула ui-kit): текст ≥ 4,5; крупный (≥ 24 px или ≥ 18,7 px жирный) ≥ 3; границы контролов и иконки ≥ 3. Проверяется в обеих темах, в hover и фокусе, на фото и на акцентных поверхностях.
- **Сначала стратегия:**
  - `restrained` — нейтральные и один акцент, по умолчанию для «работает»;
  - `committed` — акцент владеет 30–60 % первого экрана;
  - `drenched` — поверхность целиком цветная, только «убеждает» и только если ink на ней ≥ 4,5;
  - `duo` — второй фирменный цвет только для фона секций.
- **Палитра в OKLCH.** Нейтральные с оттенком акцента, хрома ≤ 0,02; у краёв светлоты хрома снижается. Один `neutral` на тему, тёплые и холодные серые не смешиваются.
- **Цвет логотипа** кластеризует код. Если он не тянет контраст как текст, остаётся заливкой, а текстовый вариант выводится сдвигом L (как `accentText` в ui-kit).
- **Тёмная тема** проектируется отдельно: свои поверхности по возвышению, ink не чисто белый. Посреди страницы тема не меняется; одна осознанная цветная полоса допустима.
- **Статусы** `ok/warn/bad` не используются как бренд; статус всегда дублируется текстом.

### 3.6 Композиция, плотность, ритм

- **Шкала отступов** 4–128 px. Вертикаль секций: `compact` 48/32, `regular` 96/56, `airy` 128/72 (десктоп/мобила). Текстовый контейнер 60–72ch, контент 1200 px.
- **Ритм.** Отступ над заголовком больше, чем под ним. Тесные группы и широкие разрывы; одно значение отступа на всё (> 60 %) — дефект.
- **Тест прищура.** Видно главное, второе и группы. Доминанта — одна на экран, кульминация — одна на страницу.
- **Карточки** — только когда возвышение что-то значит; иначе воздух и разделители. Тарифы и карточки выровнены по базовым линиям: цены, списки и кнопки на одной высоте.
- **Когнитивная нагрузка.** Не больше 4 вариантов в точке решения. Одно основное действие на экран. Меню ≤ 5–7 пунктов. Длинный список (> 5) — группы, колонки или вкладки, а не строки с линией под каждой.
- **Мобила.** Каждый вариант блока явно задаёт вид на < 640 px. Многоколоночное — в одну колонку, поля 16 px, `100dvh`.

### 3.7 Движение

- **Только токены** (каталог E3): `still`, `calm` (120/200/320 мс, `cubic-bezier(.23,1,.32,1)`), `lively` (+ вход hero 600 мс один раз и появление блока 400 мс со ступенькой 50 мс, ≤ 4 элемента). Нажатие — `scale(.97)`. Выход быстрее входа. Появление не из нуля (≥ 0,95).
- **Частота решает.** То, что пользователь делает десятки раз в день, не анимируется: CRM, клавиатура.
- **Hover-эффекты** только под `@media (hover:hover) and (pointer:fine)`.
- **Reduced-motion** даёт смягчение, а не ноль: остаются переходы opacity 150 мс, перемещения и пружины уходят. Текущий `base.css` (глушит всё до 0,01 с) нужно заменить на такой вариант.
- **Бюджет:** 0 КБ JS-библиотек движения в системах клиентов; только transform и opacity; LCP ≤ 2,5 с, CLS ≤ 0,1, INP ≤ 200 мс.

### 3.8 Состояния, формы, ошибки

Каталог F, главное:

- **Формы.** Подпись над полем, ошибка под полем по blur. `type`, `inputmode`, `autocomplete`. Кнопка на время отправки — в состоянии загрузки, повтор заблокирован. После отправки — что будет дальше («Перезвоним до 18:00» — только если это правда).
- **Состояния.** У каждого экрана есть загрузка (скелетон, если > 300 мс), пустое (5 видов: первое использование, очищено, не найдено, нет прав, ошибка), ошибка, успех.
- **Ошибка** отвечает на «что случилось, почему, что делать», без кодов на первом плане.
- **Необратимые действия.** Подтверждение называет объект и следствие, кнопки называют действие. Где безопасно — «Отменить» вместо диалога.

### 3.9 Текст: человеческий язык и никакой выдумки

Действует для всего, что видит человек: сайт клиента, чат агента, интерфейс платформы. Полная таблица из 25 признаков с «было → стало» — в каталоге H. Ядро для промпта:

1. Пишем как владелец, который объясняет соседу: коротко, на «вы», глаголом, одна мысль на предложение, разная длина фраз.
2. **Убрать:**
   - надувание значимости;
   - рекламный глянец («погрузитесь», «уникальная атмосфера»);
   - деепричастные хвосты, безымянных «экспертов», канцелярит («осуществляем изготовление»), «является»;
   - «не просто X, а Y», тройки прилагательных, синонимическую карусель, ложные диапазоны «от… до…»;
   - пассив без деятеля, тире как приём, жирный через слово;
   - Заглавные Буквы, эмодзи, восклицательные знаки;
   - чат-артефакты («Конечно!», «Надеюсь, это поможет»), перестраховку, бодрые концовки, анонсы «Давайте разберёмся»;
   - кальки («кастомный», «в моменте»);
   - стоп-лист (каталог H.3).
3. Кнопка — глагол и объект; у одного намерения одна формулировка на весь сайт.
4. Для заказчика в чате никаких технических слов: «деплой», «токены», «ревизия», «схема». Называем то, что он видит.
5. **Факты** берутся только из подтверждённых ответов интервью, файлов клиента и AppSpec. Всё прочее — допущение:
   - в превью — плашка «уточнить: …», её видит только владелец;
   - публикация с неснятыми плашками блокируется;
   - в чате агент прямо говорит, что предположил.
6. **Никогда не выдумываем:** отзывы, рейтинги, число клиентов, годы работы, награды, лицензии, цены, гарантии, сроки ответа, логотипы, сотрудников, фото людей, «лучший / № 1» (ст. 5 38-ФЗ).
7. Медицина, образование, финансы, дети, «гарантия результата» требуют документа или ссылки от клиента. На вопрос «откуда это?» агент называет источник.
8. **Финальный проход:** «что здесь звучит как машина?» → список → переписать. Подтверждённые клиентом формулировки и цифры не трогаем; сомнение по ним — вопрос клиенту.

## 4. Тема v2 и шрифтовые роли

**Проблема текущей схемы.** `AppSpec.theme` — `accent`, `font`, `radius`, `density`, `mode`, `logoFile`. Шрифт один, и три из пяти значений enum (Inter Tight, Manrope, PT Sans) запрещены в заголовках. Кегли 14/16/20/28 не дают лендингу ни шкалы, ни display-роли. Вариантов блоков в схеме нет.

```jsonc
"theme": {
  "preset": "masterskaya",           // enum стартовых тем; задаёт дефолты остальных полей
  "accent": "#FFC21A",               // как в v1
  "accent2": null,                   // только при colorStrategy=duo
  "neutral": "cool",                 // cool|neutral|warm|green|plum — оттенок нейтральных, C ≤ 0.02
  "colorStrategy": "committed",      // restrained|committed|drenched|duo
  "fontPair": "fira-xcond+fira",     // enum пар каталога A6: display + text (+ num)
  "font": "Onest",                   // v1: становится переопределением текстовой роли (enum текстовых)
  "typeScale": "classic",            // calm|classic|dramatic (каталог E1)
  "radius": 0, "controls": "match",  // 0|2|4|8|12|16|24; match|pill
  "density": "regular",              // compact|regular|airy
  "depth": "outline",                // flat|outline|soft
  "motion": "still",                 // still|calm|lively
  "imagery": "natural",              // natural|duotone|mono — фильтр фото из токенов
  "mode": "light", "logoFile": "…",
  "blocks": { "hero": "typographic", "proof": "photo-strip", "priceList": "rows", "cta": "band" }
}
```

**Производные переменные** (`themeToTokens`, чистая функция, как сейчас):

- шрифты: `--w-font-display/text/num`;
- шкала: `--w-step--1…6` через `clamp`, `--w-leading-*`, `--w-tracking-*`;
- отступы: `--w-space-1…10`, `--w-section-y`, `--w-container`;
- форма и глубина: `--w-radius-sm/md/lg`, `--w-radius-control`, `--w-border-w`, `--w-shadow-1/2`;
- поверхности: `--w-surface-alt`, `--w-surface-accent` + `-ink`, `--w-accent2-*`;
- движение и фото: `--w-dur-1…3`, `--w-ease`, `--w-img-filter`.

Варианты блоков берутся из темы через контекст ui-kit, проп в TSX может их переопределить. Поэтому панель «Стиль» (D13) меняет hero, тариф или календарь без кредитов и без пересборки.

**`themeLint` (код, на каждое изменение, в том числе из панели «Стиль»):**

- все пары цветов проходят пороги 3.5;
- если ink на `drenched` < 4,5, стратегия понижается до `committed`;
- `accent2` не совпадает с оттенками статусов (±15°);
- display ≠ text, кроме суперсемейств;
- на экранах «работает» `motion = still`;
- варианты блоков допустимы для класса;
- пара не из списка «не для заголовков»;
- тема не повторяет вектор другой системы той же ниши и города (мониторинг однотипности).

**Миграция v1 → v2.** Отсутствующие поля берутся из `preset`, затем из дефолтов. `font` из v1 становится текстовой ролью. Старые системы рендерятся как раньше: `preset = legacy`.

**Правки ui-kit:**

- display-роль и шкала;
- токены отступов и секций;
- наборы радиусов;
- reduced-motion «только opacity»;
- блоки и варианты (каталог D1): `Hero`, `Proof`, `PriceList`, `Steps`, `Features`, `Team`, `Gallery`, `Video` (фасад), `FAQ`, `CTA`, `LeadForm`, `Contacts`, `Pricing`/`Paywall`, `SlotCalendar`, `Charts`, `Footer`;

### 5.4 Съёмка референсов (решение основателя: свободный доступ, только инфобезопасность)

- **Доступ.** Любые открытые сайты и материалы. Содержательная фильтрация — только политиками провайдера модели: если модель отказалась, референс помечается `skipped` с причиной.
- **SSRF.** Отдельный под в песочнице (gVisor, как runtime). Наружу только http/https на 80 и 443. Адреса проверяются после резолва: блокируются 10/8, 172.16/12, 192.168/16, 127/8, 169.254/16 (метаданные облака), 100.64/10, `::1`, `fc00::/7`, `fe80::/10`, адреса кластера. Резолв повторяется на каждом редиректе — против DNS rebinding.
- **Лимиты.** ≤ 10 ссылок на систему, ≤ 5 редиректов, таймаут 20 с, страница ≤ 15 МБ, загрузки файлов выключены.
- **Чистый контекст браузера на каждую ссылку:** без cookies, логинов и данных клиента. Это защищает и клиента, и нас.
- **Хранение.** Скриншоты удаляются с окончанием прогона. Остаётся только `ReferenceDigest`: текст принципов и извлечённые числа.
- **Практика съёмки** (из `dp-scout`):
  - ждать не `load`, а стабилизации сцены (до 15 с); прокрутить ленивый контент;
  - кадр загрузчика не годится: пустой canvas, узлы прелоадера, почти нулевой разброс яркости;
  - баннер согласия пытаемся закрыть кнопкой «Отклонить» или «Закрыть», «Принять» не нажимаем;
  - антибот и капчу не обходим, а честно помечаем `skipped`;
  - страницы за логином (Instagram, VK) — просим клиента прислать скриншот;
  - библиотека в бандле — не доказательство приёма.
- **Правило вывода** (решение основателя): из референса берём принципы, а не копию. Логотипы, слоганы, иллюстрации и раскладку «один в один» не воспроизводим, критик сравнивает результат с референсом на сходство.

**Маскирование ПДн на изображениях перед T1** (D45; новая задача платформы). Применяется ко всему, что уходит в vision-модель T1: загрузки клиента, снимки референсов, рендеры D3/D8.

1. **OCR на нашем сервере.** Для русского и английского. Кандидаты — Tesseract или PaddleOCR (Apache-2.0); выбор и качество на русском — по тесту [?].
2. **Поиск ПДн в распознанном тексте** теми же детекторами, что `pii.scrub` (`specs/security/data-boundary.yaml#detectors`): ФИО, телефоны, email, адреса, номера документов. Найденное закрывается сплошной плашкой по рамке слова.
3. **Лица** находит детектор лиц и размывает их (модель и лицензия — по тесту [?]). Логотипы и товары не трогаем.
4. **Если OCR не уверен** (низкая уверенность, рукописное, плотный мелкий текст): картинка на T1 не уходит. Её разбирает модель T0 (№ 5), либо она пропускается с пометкой и сообщением клиенту простыми словами.
5. **Журнал.** В журнал вызова пишутся только счётчики («замаскировано: 2 телефона, 1 лицо»), без содержимого. Маскированная копия живёт до конца прогона, как и исходный снимок.

Для организаций «Только РФ» все vision-вызовы идут на T0. Маскирование выполняется так же: один путь проще проверять, и в рендерах не остаются чужие данные.

### 5.5 Как решает критик

1. **Сначала код.** Проверки каталога B. Падение чинится без LLM правкой токенов или варианта: сдвиг L, ступень шкалы, другой вариант блока. Затем перепроверка. Перед тем как ссылаться на «зелёный» результат, у каждой проверки есть негативная фикстура (правило аудита основателя).
2. **Затем VL-критик** по рубрике C: 7 осей 0–4 + проработка `production`/`draft`. Находка — «признак → где → замена в рамках темы», без замены не принимается. Конверсию критик не судит.
3. **`pass`** — нет P0/P1, все оси ≥ 3, `production`. Иначе пересобирается только провалившееся направление, находки идут как ограничения, не больше 2 кругов. Затем `show-with-notes`. Три круга одних измеримых правок — сигнал «подгонки» и эскалация.
4. **Число не сдаётся без кадра**: метрика контраста не заменяет взгляд на скриншот.

## 7. Риски

1. **VL-модели не прошли eval на русских макетах, формат картинок у Cloud.ru не документирован.** Нужны дымовой тест (M2-28) и сравнение `glm-5.3-flash`, `glm-4.6v` и `Kimi-K2.6` на 20 направлениях с разметкой дизайнера.
2. **Однотипность между клиентами** одной ниши и города. `themeLint` нужна проверка повторов, а дизайнеру — ежемесячный обзор.
3. **Блоков ui-kit не хватит** для уникальности. Качество упирается в работу дизайнера по вариантам D1, а не в агента.
4. **Выдуманные факты** — главный риск доверия и 38-ФЗ. Блокировка публикации с плашками «уточнить» обязательна с первого релиза.
5. **Шрифты.** Без живой проверки кириллицы и текста лицензии каждого шрифта каталог небезопасен. Коммерческие гарнитуры с сайтов «бесплатного скачивания» не используются (решение основателя).
6. **Маскирование ПДн** зависит от качества OCR на русском и детектора лиц. Пока задача платформы не готова, vision на T1 получает только рендеры с заглушками и снимки референсов без людей.
6. **Съёмка референсов** — поверхность для SSRF. Тест в CI и отдельный под обязательны до включения функции.
