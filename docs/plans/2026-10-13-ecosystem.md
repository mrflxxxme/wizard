# План: Born to Build - SaaS №1 экосистемы (веха V5)

Дата: 13.10.2026. Решения: `specs/product.yaml#decisions.D80_ecosystem`; реестр экосистемы - [mrflxxxme/ecosystem](https://github.com/mrflxxxme/ecosystem) (`DECISIONS.md`, номера Э-NN; `ROADMAP.md`; контракт `schemas/`, `docs/handoff.md`). Задачи: веха **V5** в `specs/milestones.yaml`, `V5-01…V5-10` в `specs/backlog.yaml`.

## 1. Цель и порядок

Born to Build - первый продукт экосистемы Кирилла Уклонского, который выходит в самостоятельный SaaS (Э-02). Ближайшие месяцы деньги приносит экспертиза основателя, продукт её упаковывает и доказывает (Э-01). Позиционирование не меняется: «рабочая система под задачу за день», прод для МСБ, целостный самостоятельный продукт (Э-10).

Порядок ядра:

```
V4-06 свободный TSX → V4-07 арт-директор → V4-14 «да» основателя, альфа
  ▼
V5-01 боевой магазин и оферта (основатель) ∥ V5-02 тарифы D31 в billing/plans.ts, оплата включена
  ▼
V5-03 открытая регистрация с антиабуз-лимитами + минимальный лендинг (вытянуто из M4-01)
  ▼
V5-09 критерии входа «Прототипа» выполнены, «да» основателя → V5-10 тариф «Прототип»
```

Связки с экосистемой идут параллельно лёгким режимом (§7): V5-04 лид-мост и V5-07 шлюз ключей - сразу, V5-05 вход по контексту - после V4-14, V5-06 «следующий шаг» - после V5-05. Чистка бэклога V5-08 - сразу.

## 2. Лид-мост (Э-08, Э-25) - V5-04

Born to Build шлёт в приёмник экосистемы события `LeadEvent` v1.0 (`schemas/lead-event.schema.json`):

| Событие | Когда | placement |
|---|---|---|
| `want_team` | владелец отметил «Хочу, чтобы доделала команда» | `want_team` |
| `limit_hit` | отказ `FREE_DRAFTS_LIMIT`, `BUILDS_LIMIT`, `INSUFFICIENT_CREDITS` | `limit_hit` |
| `build_failed` | провал сборки владельца | `build_failed` |
| `build_published` | первая публикация системы | `publish` |

- `source = {product: "btb", placement}`; `subject_ref` - id системы; `summary` - одна-две строки для Кирилла.
- Контакт (почта, Telegram) - только с согласием владельца и версией текста согласия; без согласия ПДн в событии нет. Текст согласия проверяет юрист (V5-01).
- Отправка не блокирует путь владельца: очередь с повторами, идемпотентный `id`, не больше одного события вида на систему в сутки.
- CTA «Запустить с экспертом» на экранах лимита, провала сборки и «Написать команде» ведёт в бот экосистемы: `t.me/<бот>?start=btb_<placement>[_<ref>]`.
- «Под ключ»: клиента ведёт Кирилл - диагностика, ТЗ, переговоры, приёмка. Стандартное собирается в Born to Build, нестандартное и интеграции делает void0 как партнёр на ревеню-шере.

## 3. Вход из экосистемы (Э-15) - V5-05

Ссылка от RADAR, Скаута или бота:

```
https://borntobuild.ru/start?ctx=<base64url(LaunchContext)>&exp=<unix>&sig=<hex>
sig = HMAC-SHA256(WIZARD_ECOSYSTEM_CTX_SECRET, ctx + "." + exp)
```

- `exp` - не больше 7 суток. Неверная подпись, срок или схема - обычный старт без сообщения пользователю.
- Длинный контекст приходит как `ctx_id`; Born to Build забирает его у приёмника по сервисному токену `WIZARD_ECOSYSTEM_SERVICE_TOKEN`.
- В контексте нет ПДн; свободный текст всё равно проходит сигнальный фильтр. Пользователь входит в Born to Build сам, контекст ждёт его входа.
- Интервью стартует с засеянным брифом и задаёт 1-2 оставшихся вопроса.

Раскладка `LaunchContext` по брифу:

| Поле контекста | Поле брифа |
|---|---|
| `goal_hint`, `need.label` | `goals` |
| `audience_hint`, `region` | `audience` |
| `solution.contract_ref` | `integrations[].contractRef` |
| `solution`, `analog` (модель, переносимость) | `assumptions` с источником `context` |
| `signals` | `assumptions` с источником `context`; цифры - только при `measured` и `url` (D49) |
| `id`, `source`, `region.okato`, `need.id` | новое поле `context` - для атрибуции и `context_id` в `LeadEvent` |

## 4. Открытая регистрация и антиабуз - V5-03

Статус чисел: **утверждено владельцем 14.10.2026** (пересмотр по факту через 2 недели после открытия регистрации).

- Подтверждённая почта до первой сборки; SmartCaptcha (D57) на регистрации.
- Не больше 3 новых организаций с одного IP в сутки; одноразовые почтовые домены - по списку.
- Бесплатные черновики - по лимитам D58 и D70.
- Бесплатные сборки забирают не больше 30 % суточного лимита платформы (900 ₽ из 3 000 ₽). При исчерпании новые бесплатные сборки ждут следующих суток, платные не страдают.
- Минимальный лендинг: обещание `positioning.promise_draft`, четыре класса систем, цены D31, «Написать команде». Полный лендинг, нагрузочный тест и мониторинг остаются в M4-01.

## 5. Будущий тариф «Прототип» (Э-10) - V5-09, V5-10

Живой прототип за минуты бесплатно или дёшево, ссылка для показа, плашка «Собрано в Born to Build». Это отдельный тариф, позиционирование продукта он не меняет. Вводится, только когда качество достойное, быстрое и дешёвое.

Критерии входа. Статус: **утверждено владельцем 14.10.2026**. Замер - на 12 эталонных брифах (по 3 на класс, как в финальном замере V3) по отчёту сборки V4-04.

| Критерий | Порог | Откуда метрика | Сейчас |
|---|---|---|---|
| Качество | медиана оценки визуального критика ≥ 70 из 100, ни один бриф ниже 60 | критик V4-09 | 30-52 |
| Без заглушек | 0 находок S01-S04 | проверка V4-18 | - |
| Гейты | G0-G2 без блокеров, сценарии брифа проходят | отчёт V4-04 | - |
| Скорость | первый экран ≤ 45 с, три экрана ≤ 90 с, живой прототип по ссылке ≤ 3 мин (медианы) | V4-17, V4-08 | - |
| Цена | себестоимость прототипа: медиана ≤ 15 ₽, максимум ≤ 30 ₽ | журнал расходов, отчёт V4-04 | полная сборка 42 ₽ |
| Бюджет | бесплатные прототипы ≤ 10 % суточного лимита (300 ₽ из 3 000 ₽), без влияния на платные сборки | лимиты D77 (18б) | - |
| Защита | открытая регистрация V5-03 работает с антиабуз-лимитами | V5-03 | - |

Прототип: плашка «Собрано в Born to Build», `noindex`, срок жизни ссылки, переход к запуску системы по D31.

## 6. Ключи моделей (Э-19) - V5-07

- На время разработки продукты экосистемы ходят к провайдерам через общий шлюз: виртуальный ключ и бюджет на каждый продукт, расход виден по продуктам.
- Лимиты Born to Build D77 (18б) остаются: 3 000 ₽ в сутки, 15 000 ₽ в месяц. Они считаются только по журналу расходов Born to Build; расход других продуктов в шлюзе в них не входит.
- Список моделей, маршруты и D18 не меняются. Runtime-вызовы с данными конечных клиентов - только контур РФ (D79 (3)).
- Переход на шлюз и обратно - переменными выката (`*_BASE_URL`, виртуальный ключ), без правки кода. Ключи разводятся, когда продукты готовы.

## 7. Процесс (Э-23)

- **Лёгкий режим** - связки с экосистемой (V5-04, V5-05, V5-06, V5-07) и чистка V5-08: быстрая полоса D79 (11), без PR захвата, один цикл ревью, короткая запись решения в описании PR и в `specs/CHANGELOG.md`.
- **Прежние ворота** - ядро с деньгами, ПДн и runtime: V5-02, V5-03, V5-10 и передача контакта в V5-04. Полный набор тестов, метка `founder-review` (`escalation.yaml#merge_policy`, E-MONEY, E-LEGAL).
- **Чистка бэклога** - разовая, задача V5-08, в этом PR не делается.
