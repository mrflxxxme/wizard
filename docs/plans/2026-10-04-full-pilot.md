## Что будет к первым клиентам

Живая платформа Born to Build (borntobuild.ru, системы на `<имя>.sandpile.ru` или своём домене):
- лучшие модели по умолчанию, только российские — по известному ограниченному региону или флагу «Только РФ»; ПДн в тексте и на картинках маскируются до отправки;
- четыре класса систем без ручной доводки: сайт с заявками, запись с напоминаниями, подписка и платный доступ, CRM; раздел «Ограничения» для запросов сверх возможностей;
- рубли вместо кредитов, «Написать команде», «Передать команде», «Под ключ», гарантия запуска;
- платежи в магазин клиента через ЮKassa, Т-Кассу, CloudPayments, Robokassa и Prodamus с подписками и чеками; почта, SMS и Telegram; исходящий HTTP по списку адресов, входящие вебхуки, amoCRM, Битрикс24, Tilda, МойСклад, СДЭК;
- свой домен, Метрика, SEO, картинки и видео, Яндекс Карты, SmartCaptcha, 8 тем и дизайн-агент с тремя направлениями и референсами;
- все тексты наружу — простым языком по правилам humanizer, без выдуманных фактов.

**Порог готовности (D42 и D59):** 20 брифов набора P, не меньше 16 доходят до готовности к публикации по автоматическим проверкам, медиана сборки ≤ 40 минут, расход на модели ≤ 300 ₽ на систему, бюджет замера до 6 000 ₽ в рамках месячного лимита (повтор только по провалившимся брифам); живые проверки каждого платёжного провайдера, коннектора и реального своего домена; затем основатель проходит по одному сценарию каждого класса.

## Объём и порядок

- **81 задача**, из них 2 уже закрыты (M2-91 ревизия ограничений, M2-92 решение основателя по ней). Оценка — около 148,5 агенто-дня.
- **Критический путь** ≈ 14,5 агенто-дня: M2-21 (контракт AppSpec v2) → M2-49 (ядро платежей) → M2-64 (подписки и платный доступ) → M2-83 (класс «подписка») → M2-88 (live-прогон) → M2-89 (доводка) → M2-90 (сценарии основателя). Задачи с запасом не больше дня помечены `critical: true` — их берут первыми.

## Как начать следующую сессию

1. Прочитать `AGENTS.md` (обновлён: правило шрифтов D64, «сначала `critical`», поля `owns` и `specs_pending`), `specs/README.md`, `specs/milestones.yaml#M2P` и этот документ.
2. Проверить, что основатель положил ключи в `.data/local/inputs.env` (`CLOUDRU_API_KEY`, `ZAI_API_KEY`), и пройти по чек-листу ниже — что уже заведено.
3. Запустить волну p-w0 параллельно, по одной задаче на агента в своём worktree. Контекст задачи — `node tools/specs/slice.mjs --task <id>`. На Windows валидатор и нарезка пока требуют обхода `path.relative` (задача M2-17 чинит это первой); до тех пор их удобнее запускать в Linux-контейнере или CI.
4. Протокол задачи: ветка `task/<id>`, сначала спека, правки только в путях `owns`, тесты и `pnpm specs:validate`, независимое ревью агентом другого семейства моделей, PR в main по правилам `milestones.yaml#M2P.plan.merge_rules` (порядок мержа общих файлов, резерв номеров миграций, дописываемые файлы).
5. Изменения решений `product.yaml` и жёстких правил `AGENTS.md` — PR с меткой `founder-review`.

## Что сознательно не вошло в исправления по аудитам

- Дробление крупных задач M2-21, M2-49, M2-64, M2-60, M2-81…M2-84: в двухзначной нумерации M2 не осталось свободных номеров, путь от этого не удлиняется. Номера M2-31 и M2-72 переиспользованы под новые решения, их прежнее содержимое слито в M2-32 и M2-71.
- Срез контекста M2-98 остаётся большим (≈ 195 КБ): нужен весь `api.yaml`; M2-17 добавит предупреждение о размере.
- Проверка `owns` в CI и запуск браузерных тестов по путям — только через валидатор.
- Послабления из ревизии ограничений, которым нужны новые функции, отложены после пилота (список в M2-93).

## Состояние репозитория и стенда

- Всё планирование, исследования и аудиты этой сессии влиты в `main` вместе с работой по локальной репетиции пилота (стенд на этой машине: `node tools/deploy/local.mjs up`, руководство — `docs/ops/local-rehearsal.md`).
- Стенд пока в режиме фикстур; после появления ключей в `inputs.env` повторный `local.mjs up` переключает его в live, а задача M2-32 снимает ограничение неизвестного региона.
- В `main` уже есть работа соседней сессии по выкату на сервер Timeweb (PR #47, #48): ретраи выпуска сертификата и API Timeweb, сертификаты в образе Postgres.

## Главные риски

- Объём: 81 задача до первых клиентов по решению «всё до клиентов».
- Внешние сроки: автоплатежи включают менеджеры провайдеров, договор SMS, DNS с API — от дней до недель.
- Модели со зрением: точные идентификаторы и формат картинок в Z.ai и Cloud.ru подтверждает смоук-тест в M2-28; доступность Z.ai из России не проверена.
- Юридические тексты: пока черновики закрытого тестирования.
