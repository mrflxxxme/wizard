# Пилот: что сделать основателю (один заход, ≈ 3–4 часа своего времени)

Состояние на 01.10.2026. Решения D23–D25 (`specs/product.yaml#decisions`): пилот бесплатный, по приглашению, без юр. обвязки, инфраструктура ≤ 10 000 ₽/мес, токены моделей ≤ 10 000 ₽/мес.
Подробности по каждому сервису: `docs/founder/access-checklist.md`; модели: `docs/founder/models-research.md`; выкат: `docs/ops/deploy.md`.

**Главное правило.** Ключи и пароли не присылайте в чат, почту или PR. Вводите их сами в GitHub → Settings → Secrets and variables → Actions → **Repository**. Окружения GitHub без Pro в приватном репозитории не работают, поэтому всё задаётся на уровне репозитория. Копию каждого ключа храните в менеджере паролей.

## 1. Timeweb Cloud

1. Панель Timeweb Cloud → «Баланс» → пополните на 3–5 тыс. ₽.
2. «API и Terraform» → «Создать токен». Срок — бессрочный или ≥ 1 год. **Выключите подтверждение удаления через Telegram**, иначе удаление staging зависнет.
3. Сохраните токен в менеджер паролей. В GitHub он станет секретом `TWC_TOKEN` (шаг 7).

## 2. Домены

Нужны **два разных домена**: платформы (клиенты входят туда) и систем клиентов (на нём живут их системы: `<система>.<домен систем>`). Домен систем не может быть поддоменом домена платформы. Имя временное, финальное выберем позже.

1. Купите оба в Timeweb («Домены» → «Зарегистрировать») — проще всего. Или, если домены уже есть у другого регистратора, поменяйте у него NS-серверы на серверы Timeweb и добавьте домены в раздел «Домены».
2. Записи DNS (сервер, сертификаты, SPF систем) выкат создаст сам. Вручную добавляются только записи почты (шаг 5).

## 3. Cloud.ru Foundation Models

1. Зарегистрируйтесь на cloud.ru (юрлицо, ИП или физлицо — как позволит форма) и пополните баланс на 1–2 тыс. ₽.
2. «Пользователи» → «Сервисные аккаунты» → «Создать», уровень «Проект».
3. Откройте аккаунт → «Учетные данные доступа» → «Создать API-ключ». Сервис — **Foundation Models**, срок — 90 дней, **без ограничения по IP**. Ключ показывается один раз.
4. Секрет GitHub: `CLOUDRU_API_KEY`.
5. Необязательно: в тикете Cloud.ru спросите, какая сборка DeepSeek-V4-Pro у них развёрнута (preview или 0813) и когда будут GLM-5.3 и DeepSeek V4.1-Flash. Это влияет на качество отката (`models-research.md`).

## 4. Z.ai (основная модель сборки)

Без ключа система работает: сборка сама уходит на модели Cloud.ru. Но по исследованию GLM-5.3 сильнее (индекс 45 против 26–27) и дешевле: 50–65 ₽ за среднюю сборку против ≈ 95 ₽.

1. Регистрация на z.ai → профиль → **API Keys** → «Create a new API key».
2. Пополнение ($20–50): российские карты не проходят. Используйте посредника или зарубежную виртуальную карту. Вариант с оплатой в ₽ — агрегатор, но его совместимость не проверена, сначала скажите мне.
3. Секрет GitHub: `ZAI_API_KEY`.

Персональные данные клиентов перед отправкой в Z.ai по-прежнему вычищаются в коде, а ИИ-действия с записями клиентов идут только в Cloud.ru.

## 5. Unisender Go (почта платформы)

1. Регистрация на go.unisender.ru, подтвердите почту, выберите тариф (по карте — от 800 ₽ за 6 000 писем).
2. Добавьте **домен отправки = домен платформы**. Письма пойдут с `noreply@<домен платформы>`.
3. Unisender покажет записи DNS. В Timeweb → «Домены» → домен платформы → DNS добавьте:
   - **DKIM** (TXT `<selector>._domainkey`) — значение из кабинета Unisender;
   - **DMARC** (TXT `_dmarc`): `v=DMARC1; p=none; adkim=s; aspf=s`.
   - **SPF не добавляйте руками**: его создаст выкат из переменной `WIZARD_PLATFORM_MAIL_SPF`. Значение — то, что Unisender просит после `v=spf1` (например `include:…`).
4. Дождитесь, пока Unisender подтвердит домен.
5. SMTP-доступ: user_id — в левом верхнем углу кабинета; API-ключ — «Настройки» → «Безопасность» → API. Хост — `smtp.go1.unisender.ru` или `smtp.go2.unisender.ru`, тот же, что в адресе вашего кабинета (go1 или go2).
6. В GitHub:
   - секреты `WIZARD_SMTP_HOST` = хост, `WIZARD_SMTP_USER` = user_id, `WIZARD_SMTP_PASSWORD` = API-ключ, `WIZARD_SMTP_FROM` = `Wizard <noreply@домен платформы>`;
   - порт по умолчанию 465, его не задавайте;
   - переменная `WIZARD_PLATFORM_MAIL_SPF` = строка SPF из пункта 3.

## 6. Telegram-бот алертов

1. В Telegram откройте @BotFather (с синей галочкой) → `/newbot` → имя и username на `bot`. Скопируйте токен вида `123456:ABC…`.
2. Напишите своему боту любое сообщение.
3. Откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id":ЧИСЛО`. Это id чата.
4. Секреты GitHub: `WIZARD_OPS_ALERT_TELEGRAM_TOKEN` = токен, `WIZARD_OPS_ALERT_CHAT_ID` = число.

Необязательно: второй бот для уведомлений систем клиентов («Заявка №123»). Секрет — `WIZARD_TELEGRAM_BOT_TOKEN`. Без него уведомления идут по почте.

## 7. GitHub

1. Settings → General → **Default branch** → `main`. Без этого еженедельный eval не запускается по расписанию.
2. Придумайте пароль из 16+ символов и сохраните его в менеджер паролей: **без него не расшифровать архив базы**. Секрет — `WIZARD_STATE_PASSPHRASE`.
3. Settings → Secrets and variables → Actions → вкладка **Repository**.

**Secrets** (кнопка «New repository secret»):

| Имя | Откуда |
|---|---|
| `TWC_TOKEN` | шаг 1 |
| `WIZARD_STATE_PASSPHRASE` | пункт 2 выше |
| `CLOUDRU_API_KEY` | шаг 3 |
| `ZAI_API_KEY` | шаг 4 |
| `WIZARD_SMTP_HOST`, `WIZARD_SMTP_USER`, `WIZARD_SMTP_PASSWORD`, `WIZARD_SMTP_FROM` | шаг 5 |
| `WIZARD_OPS_ALERT_TELEGRAM_TOKEN`, `WIZARD_OPS_ALERT_CHAT_ID` | шаг 6 |
| `WIZARD_FOUNDER_EMAIL` | ваша почта: вход, права staff, алерты. Именно секретом: репозиторий публичный, и значения переменных видны в логах Actions |

**Variables** (вкладка Variables → «New repository variable»):

| Имя | Значение |
|---|---|
| `WIZARD_PLATFORM_DOMAIN` | домен платформы, например `primer.ru` |
| `WIZARD_SYSTEMS_DOMAIN` | домен систем |
| `WIZARD_PLATFORM_MAIL_SPF` | шаг 5, только механизмы: `include:spf.unisender.ru` — без `v=spf1` и `~all` |

Ключи `CLOUDRU_API_KEY` и `ZAI_API_KEY` используют и пилот, и еженедельный eval. Отдельно для eval ничего задавать не нужно.

## 8. Выкат

1. **Сначала проверка.** GitHub → Actions → **bootstrap-pilot** → «Run workflow»: `env` = `prod`, `action` = `check` (стоит по умолчанию), подтверждение не нужно. Через 1–2 минуты откройте задание: в сводке будет таблица «Пилот prod: проверка настроек».
   - Проверка ничего не создаёт и не меняет. Она пробует токен Timeweb (и показывает баланс), находит оба домена в «Доменах» Timeweb, проверяет ключ Cloud.ru, ключ Z.ai (если задан), входит на SMTP-сервер без отправки письма, сверяет `WIZARD_SMTP_FROM` и SPF, а если пароль уже использовался — проверяет его по сохранённым ключам.
   - В ваш Telegram придёт сообщение «Wizard: проверка настроек пилота — алерты доходят». Если его нет, алерты не работают.
   - Значения секретов не печатаются, только их имена. Если в строке «ошибка», исправьте названный секрет или переменную в GitHub и запустите `check` ещё раз. «Пропущено» у необязательного (Z.ai, бот) — нормально.
2. **Когда всё ok** — снова «Run workflow»: `env` = `prod`, `action` = `apply`, подтверждение — слово `PROD`.
3. Ждите 35–50 минут. Если какой-то настройки не хватает, задание остановится на шаге «Pilot» и перечислит недостающие имена (значения не печатаются).
4. В конце в сводке задания будет ссылка на платформу. На вашу почту придёт приглашение staff.

## 9. Первый вход и клиенты

1. Откройте ссылку и войдите по коду из письма.
2. Откройте `/admin` и подключите приложение-аутентификатор (Яндекс Ключ, Google Authenticator и т. п.). Сохраните 10 кодов восстановления.
3. `/admin` → «Пилот» → «Готовность беты» → включить с заметкой **«D25 пилот без юр. обвязки»** → подтвердить.
4. Там же «Пригласить»: почта клиента, название его организации, кредиты (например 150). Клиент получит письмо со ссылкой.
5. Пока включено «ревью основателя», первую публикацию каждой системы клиента одобряете вы в `/admin`.
