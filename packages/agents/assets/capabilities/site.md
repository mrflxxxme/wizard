# Сайт с заявками
> Лендинг из блоков ui-kit и форма заявки; заявки видит владелец, о новой заявке ему приходит письмо или Telegram.

Когда: segment=site или в карточке есть публичная страница с формой заявки.

Данные и права
- Заявка (например, lead): имя, контакт (телефон или почта), комментарий, статус «новая → в работе → готово». Контактные поля pii=basic, retention — по карточке.
- Публичная роль (access=public): только create заявки, без read. Владелец и сотрудники с ролью: read и update.
- Форма с ПДн — с согласием (ConsentCheckbox или согласие внутри LeadForm); set_compliance только с consentTemplateId и policyPage.
- Уведомление владельцу: workflow on_create заявки → notify email (и telegram, если он в карточке). В Telegram без персональных данных: «Новая заявка — откройте по ссылке».

Страница для публичной роли
- Собирай лендинг из блоков ui-kit в таком порядке: Header → Hero (первый экран, одна главная кнопка к форме) → Features (преимущества) → Steps (как это работает) → Faq → Cta → LeadForm (форма заявки) → Footer. Блок без содержания в карточке не ставь.
- Перед вёрсткой вызови get_ui_kit_docs с нужными блоками. Если блока нет в оглавлении ui-kit, собери то же из AppShell, Button, Field и RecordForm.
- Картинки — компонент Image; файлы загружает владелец. Пока файла нет — пустое место с подписью «Пример: фото работы», без чужих картинок.
- Вид — set_theme под нишу (акцент, шрифт с кириллицей). Свой CSS и цвета в коде не пишем.

Тексты
- Заголовок первого экрана — что предлагают и кому, одной фразой из карточки. Преимущества, шаги и ответы — только из карточки и описания владельца.
- Отзывов, цифр, адресов и обещаний, которых нет в карточке, не пиши: ставь заглушку «Пример: …».

Экраны владельца
- Список заявок (DataTable) со статусом, карточка заявки (RecordCard) со сменой статуса; доска StatusBoard, если в карточке есть этапы.

Критерии для QA: аноним отправляет заявку → владелец её видит, аноним не читает заявки; владельцу ушло письмо (outbox email).
