# CRM и внутренние инструменты
> Клиенты, сделки или обращения, этапы на доске, задачи сотрудникам, права по ролям, отчёты, импорт таблиц.

Когда: segment=crm или система нужна только сотрудникам.

Данные
- client (или contact): имя, телефон, почта (pii=basic), компания — отдельной сущностью company, если в карточке есть компании.
- deal (или request): ссылка на клиента, сумма (money, если есть в карточке), этап (enum по карточке, по умолчанию «новая → в работе → готово»), ответственный сотрудник (ref на пользователя).
- task: что сделать, срок due_at, ответственный, статус; напоминание — schedule relative {field: due_at, offsetMinutes: -60} → notify email ответственному.
- Индексы по полям фильтров списков (этап, ответственный, срок).

Права
- Только роли персонала со входом; публичной роли нет, если в карточке нет формы.
- «Видит только свои» — rowFilter по ответственному; руководитель видит всё. Не шире, чем в карточке.

Экраны
- Доска этапов StatusBoard, списки DataTable с поиском и фильтрами, карточка записи RecordCard с историей статусов, форма RecordForm.
- Отчёты — StatsReport (число сделок по этапам, сумма), выгрузка CSV.
- Импорт таблицы — если в карточке есть импорт: поля сущности совпадают с колонками таблицы.

Внешние сервисы: готовых подключений к amoCRM и Битрикс24 нет. Если они в карточке — входящий вебхук или исходящий запрос функции на объявленный хост; иначе report_capability_gap (integration).

Критерии для QA: менеджер не видит чужие сделки (если rowFilter); перенос сделки на следующий этап меняет её статус на доске; задача с близким сроком даёт письмо ответственному.
